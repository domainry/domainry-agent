# K02 任务相关记忆验收

日期：2026-09-15。本轮在现有个人记忆、会话历史、执行上下文和 K01 反馈链路上补齐分类、作用范围、相关性召回、来源、修正、删除与不确定性语义。K02 验收完成后，完整清单进度为 **17／25**。

## 契约、范围与来源

- [SDK 记忆契约](../../domainry-agent-sdk/conversation.go)把记录分为 `user_preference`、`project_fact` 和 `task_context`，作用范围分为工作区、会话和任务。记录保留适用主题、来源消息／运行／任务／成果／反馈、采集时间、更新时间、不确定性和上次修订原因。
- `memory_search`、`memory_save` 和 `memory_forget` 使用 v2 工具契约。服务端派生当前会话和任务 ID，并逐项核对来源归属及消息、运行、任务、成果和反馈之间的关系；模型不能通过参数引用另一个用户或不相干任务的资料。已经持久化的 v1 工具回执仍按原始定义读取和验签，新调用只使用 v2。
- 用户从一条原消息保存记忆时，页面默认使用当前会话范围，并保存准确消息 ID。人工新建默认为工作区用户偏好；任务上下文不能保存成工作区范围。修改内容要求填写修正原因，普通启停不伪造一次内容修正。

## 相关性召回与隔离

- 开启个人记忆的运行只装配当前任务、当前会话及相关工作区记录。任务范围优先于会话范围；工作区项目事实必须命中标题、内容或适用主题；无主题的工作区用户偏好可以作为通用偏好使用。
- 另一会话和另一任务的记录始终排除。召回最多 8 条，模型输入中的记忆 JSON 最多 4096 字节，保留分类、范围、来源、修正、不确定性和更新时间；不会把全部个人记忆注入每个请求。
- `memory_search` 仍提供显式管理和历史查询能力，但只返回当前会话／任务适用的记录。`include_disabled` 只供明确管理请求使用，不能扩大作用范围。

## 修正、删除与能力反馈

- 每次创建、更新和删除都在 `_agent_memory_changes` 保存不可变修订。更新记录前一 revision 和用户给出的修正原因；删除先写 revision 加一的 tombstone，再从当前记忆集中移除，并阻止复用已删除 ID。
- HTTP 的同值重试忽略服务端采集时间差并返回原 revision；模型工具调用继续使用冻结回执和严格 CAS，陈旧 revision 即使内容相同也不能绕过冲突检查。
- K01 的任务反馈增加可选不确定性并保留准确任务、运行、成果和配置版本。反馈、单次改稿和普通会话内容不会自动生成工作区记忆或发布能力配置；仍需用户明确保存记忆或配置人员显式创建、评估和发布候选。

## 页面与真实流程

- 个人记忆页可创建、编辑、启停和删除三种记忆，展示范围、适用主题、来源、更新时间、不确定性和修订原因。消息操作会把准确消息／运行／任务引用传入保存表单。
- [真实 Chrome 脚本](../frontend/tests/scoped-memory.browser.mjs)操作编译后的页面和真实 Identity／HTTP／SQLite：保存原消息为会话级项目事实、明确修正、同会话相关召回、另一会话隔离、390 px 查看来源与修订信息并删除。
- 浏览器记录三次 PUT／PUT／DELETE 都为 200；除登录前预期的 session／refresh 401 外没有失败资源，JavaScript error、console error 和 warning 都为 0。窄屏页面没有横向溢出。
- v2 工具定义最初使已有 64 KiB 边界集成场景超限；在不删字段和约束的前提下压缩模型说明后，三个原边界场景及完整实际源码目录套件通过。仓库中的 `docs/evidence` 含历史 `.go` 源码快照，因此根目录裸 `go test ./...` 会把证据快照误当产品包；验收命令明确列出全部实际源码根。
