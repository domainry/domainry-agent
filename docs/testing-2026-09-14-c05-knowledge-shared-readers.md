# C05：Knowledge 原提供者与当前读者

接续[业务实际 Agent 委派](testing-2026-09-14-c05-business-write-agent.md)，补 Knowledge 的共享阅读端口、金额抽取和真实托管资料库委派。整表仍为 **4／25**，C05 未完整验收。

原资料回执的 scope、引用 ID 和抽取正文绑定实际提供者。Agent 读取已发布回执时保留该身份，实际读者继续使用自己的当前身份检查资料库成员资格、资料权限、原文件状态和上游读取权限。SDK 增加可选共享阅读与抽取端口；旧来源仅在明确不支持时沿用原执行授权路径，来源拒绝不能回退。私有会话及私有引用在调用来源前拒绝。

Knowledge 托管资料库先核对原提供者的完整原证据，再由当前读者进行真实远程读取和本地文件过滤；仅为比对重建原提供者的证据身份。最后一次提供者远程复核结束后，再检查读者的成员资格、绑定、文件状态和下载权。新增失败用例复现了这最后一次 IO 内撤回读者资格的窗口，修复后通过。未托管来源通过其共享端口校验，并在结束时重新检查双方本地成员资格。

上游 Provider 使用与普通 Connector 网关相同的工作区／ACL 策略，读取前后比较当前读者的权限 ID。真实 HTTP 用例覆盖检索、正文、抽取、双方撤权、读取期间撤权及权限 ID 改变。原回执与引用保持不变，`9007199254740993` 的 JSON 数值精度保留；普通读取仍拒绝别人的用户 scope。

Runtime 应用宿主新增当前 Identity 的资料库／文档授权与活动成员校验，支持当前资料库工具版本及抽取工具。Agent 在延迟装配时取得该授权，显式模块配置的授权优先。真实场景通过既有 Factory Options 配置 Knowledge 的私有文件存储，存储在 Runtime 重启后继续使用。

真实 Runtime 根场景使用两个实际 Identity 用户、SQLite、实际资料库／索引和上游 HTTP，以及确定性模型决策：

- 发起账号实际调用 `agent_delegate` 并批准准确委派；接收 Agent 按原配置用户及角色执行。
- 模型发现共享资料库、检索真实上传文件、读取准确引用的原正文、抽取金额，再通过 `delegation_update` 自动交付四份原回执；程序逐项验证，发起账号明确验收。
- 完整共享执行为七步，页面读取接口没有私有确认／恢复控制信息。四份原结果各为 3、4、4、7 页，按 256 字节拼接并检查准确原 SHA-256。
- 初次共享、保留原角色而撤回执行权后、重启后、撤权及正文变化恢复后，共四轮核对原页和 SHA-256。资料阅读独立于专业工具执行权。
- 当前读者下载权、原提供者资料库成员资格撤回时拒绝旧页及共享执行；正文改变时返回 `409 knowledge_source_changed`。不含正文的原目录页在目录及权限保持有效时可读。
- 恢复后原结果仍可读，实际上传次数始终为一；发起方访问原接收会话返回 404。

新任务预算为 12 步／12 次调用／8192 字节／90 秒，与前一业务读取夹具一致。当前检查包括完整 Agent application／module、完整 SDK／Knowledge、Runtime AgentHost／transport、针对性共享端口和授权 race，以及真实 Runtime 场景。实际场景 race 和最终归档状态见[接受证据](evidence/2026-09-14-c05-knowledge-shared-readers/acceptance.json)。
