日期：2026-09-14。接续[历史约定与恢复执行身份](testing-2026-09-14-c05-historical-contract-lifecycle.md)。前一阶段真实 Runtime 的新运行已完成读取与交付调用，却在最终生成阶段耗尽原 180 秒时限，完整流程未通过；原失败证据保持原样。

采样和当前代码确认 `RecordQueryPolicyDependencies.Objects` 每次调用 `services.Schema().Objects`。记录策略在查询、数据范围与字段核对中只使用对象定义，但完整 schema 会复制动作、工作流、自动化、报表、Agent 等域并计算整个快照摘要。

本次从现有 `BuildSchemaSnapshot` 提取相同的对象规范化与排序逻辑，完整 schema 继续调用这一逻辑并按全部域计算原摘要。记录策略改为在 Runtime 读锁下取得当前对象定义并规范化，不构建其余域。每次读取仍取得当前定义；没有跨请求缓存授权、schema 状态或角色。原提供者、实际发布者、当前读者、字段与成员授权继续走原路径，原执行预算保持不变。

回归场景验证记录策略不触发完整快照构建、字段／名称变更立即生效、规范化能力仍存在，撤回当前读取权限仍拒绝。修复前该场景实际构建完整快照一次而失败。Runtime 装配、schema 服务、记录策略、报表宿主与 Agent 宿主五包通过；相关三包 race 通过。

对象投影修复后，新运行实际在 22,164 毫秒内完成，交付已提交，但另一当前角色的详情仍隐藏交付。诊断 overlay 确认 `source_publisher_unverified`：同角色执行者向自身提交交付时，存储层跳过自己运行的发布记录。现在只对交付保留这一准确发布记录，原执行角色、实际发布角色、明确来源前缀和委派用途均不可替换；普通准确原角色读取仍独立于发布记录。重启／重复保存后仅一条记录，超出前缀及其他用户仍无记录。另一角色使用该记录时继续复核原提供者／实际发布者和当前读者权限，撤权后拒绝。

Agent／SDK 八包和相关两包 race 通过。真实 Runtime 原约定恢复、要求更新、重启、原执行角色恢复、新交付、原回执读取及账号验收完整场景通过，用时 **63.50 秒**；原 180 秒执行预算保持不变。测试在任务已完成却缺少新交付时立即报告真实视图，避免再等待完整时限；成功条件保持不变。失败日志、诊断 overlay、修复前源码摘要与准确结果均保留在[本阶段证据](evidence/2026-09-14-c05-record-policy-projection/acceptance.json)。
