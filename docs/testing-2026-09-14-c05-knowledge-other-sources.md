# C05：其他 Knowledge 来源与指定角色解析

接续[托管资料库共享阅读](testing-2026-09-14-c05-knowledge-shared-readers.md)，补未托管资料库及默认上游来源的实际跨账号 Agent 链路。整表仍为 **4／25**，C05 未完整验收。

Identity 指定角色的有效权限快照原先先解析全部已分配角色，再解析指定角色，覆盖第一次解析的结果和错误。失败注入证明第一次角色查询失败仍返回成功。现在指定角色直接走 `ResolvePrincipalForRole`；未指定角色继续走完整角色解析。回归同时验证读取角色不会获得另一个写入角色的授权，以及角色撤回后的快照不再 Known。没有增加授权缓存；SDK 的当前授权版本复核继续保留。

三个实际 Runtime 场景共用同一套业务夹具、实际 Identity 账号、SQLite、上游 HTTP、模型工具决策、准确委派确认、自动交付和账号验收：

| 来源 | 原结果 | 实际执行 | 上游及本地检查 |
| --- | --- | --- | --- |
| 托管资料库 | 目录、检索、正文、抽取四份 | 七步 | 真实文件上传及索引；读者下载权、提供者成员资格及原文件状态 |
| 未托管资料库 | 目录、检索、正文、抽取四份 | 七步 | 已有上游文档；通过现有启动配置绑定真实持久资料库；各账号独立上游 ACL 及当前成员资格 |
| 默认上游来源 | 检索、正文、抽取三份 | 六步 | 既有默认 Knowledge 配置；各账号独立上游 ACL；不创建本地文件或资料库记录 |

模型读取实际 `knowledge_extract` 输出，核对原正文回执、准确文档／资料库、计划摘要、decimal 有效值 `123.45` 和引用证据后才交付。交付数据使用实际抽取值；没有仅凭工具成功就提交固定答案。

任务预算继续为 12 步／12 次调用／8192 字节／90 秒，分页仍为 256 字节。首次共享、保留原角色撤回执行权、重启、恢复来源后，逐页拼接并核对原 SHA-256。三个完整正常场景合计 44 次 SHA 核对。未托管及默认来源真实请求必须使用读者或提供者各自的 ACL；意外 ACL、任何新增上传均失败。原执行会话仍拒绝另一账号访问。

读者上游正文 ACL 撤回时，正文和完整共享执行拒绝；未托管资料库的目录只包含当前仍可读的资料库元数据，因此仍可读。默认来源还直接撤回提供者 ACL，未托管来源撤回提供者资料库成员资格；旧内容不能继续阅读。上游正文变化返回冲突，恢复后原页及 SHA 保持。

上阶段已确认运行的真实托管场景 race 最终发生 Go 测试的 10 分钟超时，保留为失败记录。它不是任务执行预算耗尽，也不能计通过。当前阶段实际 race 的终态或具体运行进程另存于[本阶段证据](evidence/2026-09-14-c05-knowledge-other-sources/acceptance.json)；只有完整根场景及命令成功才计通过。完整 Identity 回归、Identity 应用／SDK 适配层 race、Runtime AgentHost／transport 和三个实际场景的命令均在归档中核对。

此前 Runtime 已发布模块集锁与本地 Agent 能力摘要不一致的失败继续保留，发布锁未改；本阶段不计完整 Runtime bootstrap 回归通过。此前归档保持原记录。
