# E07 模型能力与请求恢复策略验收

日期：2026-09-15。本轮在现有 Chat Completions、Messages 和 Responses 三种协议上补齐模型能力声明、Agent／任务级选择与冻结、持久请求尝试和有界恢复。E07 验收完成后，完整清单进度为 **13／25**。

## 模型目录、选择与冻结

- [SDK 模型契约](../../domainry-agent-sdk/conversation_execution.go)声明上下文上限、图片输入、结构化输出、协议续接和支持的推理档位；模型身份把提供者、协议、模型与能力配置纳入不可变指纹。Agent 目录只公开宿主注册的模型 key 和能力，不接收调用方提供的地址或凭据。
- [模型注册与选择](../internal/application/conversation_models.go)分别处理 Agent 默认模型和任务显式模型。接单时冻结 key、身份、能力与推理档位；执行、恢复、授权复核和已持久输入复用时重新核对注册表。能力、身份或支持档位变化会返回 `model_changed`，不在原运行中静默切换。
- Agent 模型与任务模型保持独立。任务显式选择可覆盖 Agent 默认模型；普通转交会采用接手 Agent 的模型，显式任务选择则通过 `model_explicit` 保留。接收方校验会清除发送方执行上下文，跨主体消息和转交不会把调用方任务模型带给接收方。
- 上下文上限接入 E06 压力管理。通用 SDK 当前没有模型 tokenizer，`ContextTokenLimit` 作为保守上界与字节上限取较小值，因此可能提前压缩，但不会用估算放宽宿主字节限制。图片能力在本轮只进入声明和兼容性核对，图片内容块仍归 K05。

## 协议、失败分类与有界恢复

- [Provider 协议适配](../internal/infrastructure/provider/conversation_execution.go)在三种请求格式中传递推理档位，并按声明决定是否复用协议续接状态。协议不支持或模型档位不兼容时在发送前拒绝；结构化输出和图片支持作为冻结能力供后续内容类型使用。
- 408、429、5xx、网络错误、超时和意外 EOF 被分成稳定错误码及可恢复属性；`Retry-After` 同时支持秒数和 HTTP 日期。提供者正文、凭据和原始网络错误不进入公开结果。
- [请求恢复器](../internal/application/conversation_model_retry.go)使用宿主配置的最大尝试次数、基础等待与最大等待做指数退避，并受运行截止时间约束。每次尝试开始、失败、等待、完成、局部用量和安全错误码都写入 SQLite；worker 重启后先完成已保存的等待，再继续同一步骤。
- 每次重试前重新核对运行、Agent、任务模型、上下文来源、工具目录和当前授权。相同用户 `client_message_id` 继续指向原运行；失败尝试的文本和工具调用片段从投影及下一次输入清除。工具只在完整模型步骤持久化后执行，已完成工具回执在后续模型失败、人工恢复和服务重启后继续复用，不会随模型请求重放。

## 诊断与页面

- 运行详情公开每个模型尝试的步骤、运行轮次、尝试号、状态、安全错误码、等待时间、局部用量和时间；运行指标单独累计模型重试。终态模型失败把当前步骤标成可恢复的 `interrupted`，同时保留失败尝试与已经完成的工具效果。
- [Agent 配置页面](../frontend/src/AgentDiscovery.tsx)从服务端模型目录选择模型及推理档位；[任务页面](../frontend/src/TaskDialog.tsx)可设置任务模型；[执行详情](../frontend/src/ExecutionActivity.tsx)展示尝试、等待和错误。浏览器状态归并与服务端投影采用相同规则，刷新不会重新显示失败流片段。

## 回归结果

- SDK 全量通过；除历史证据目录外的 36 个实际产品包全部通过，其中完整 Web 为 533.856 秒，Integration 为 99.131 秒。
- E07 针对性 race 覆盖应用选择与接收方上下文、三协议能力和失败分类、SQLite 尝试投影、自动重试及人工恢复，全部通过。
- Integration 真实验证一次网络失败按 `Retry-After` 等待后成功：同一用户消息只入队一次，失败流片段消失，已完成工具只执行一次，尝试与用量完整；另一场景在 3 次后按配置停止。
- 跨主体 HTTP／Identity／SQLite 场景验证接手 Agent 使用自己的冻结模型；模型失败后已保存的个人工具效果保持可见并可在宿主重启后恢复。前端 91 项测试和 TypeScript／Vite 生产构建通过。
