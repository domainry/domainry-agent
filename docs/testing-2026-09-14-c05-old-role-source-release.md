# C05：同所有者旧角色来源首次共享与混合角色根

日期：2026-09-14。接续[同用户不同角色明确发布](testing-2026-09-14-c05-same-user-role-source-release.md)。本阶段补齐同一所有者的未发布旧角色来源首次提交、混合角色根与受权根内部的旧角色遍历。C05 仍未完整验收，整表仍为 4／25。

## 实现

- SDK persistence 新增可选、仅服务端使用的 ConversationSourceAuthorityRepository。存储按准确会话／运行及用户／工作区／Runtime 范围读取原运行身份，不返回输入、输出或执行许可。运行原角色来自账本。
- 发布上下文分别记录当前提交者、实际读者和每个根的原执行身份。提交者等于读者时仍解析旧角色；不同根不会统一继承当前提交角色。每个原角色与提交者的当前 share 授权分别核对，读取仍使用实际读者的当前资料权限。
- 未发生身份切换的同角色来源只记录内部遍历边界，保留普通来源校验。只有从服务端原快照的内部引用实际进入旧角色时才建立受权的准确前缀，并核对当前提交者及原角色的 share；任意直接引用、跨所有者或跨工作区身份不能使用这一内部遍历许可。
- 新交付在保存前建立上述来源上下文，逐份检查原回执与实际读者权限。主体完全相同、没有独立委派主体映射行时，来源发布也会按每个原运行角色持久化，覆盖已有同身份委派。否则首次提交虽核对了旧角色，后续读取仍会误用当前角色。
- 约定来源发布限定在新建或来源变更时；暂停、取消、转交等元数据更新不会重新发布不变的历史来源。旧转交夹具用 ORM 直接恢复历史字节，继续覆盖原来源可恢复与已缺失两种情况，避免使用当前来源发布写入器伪造历史数据。
- Report 独立共享分析阅读先保留实际读者的当前检查。授权目录隐藏字段／数据集造成的规格错误，在原提供者证明核对成功后归为 403；真实无效原规格仍为 400，原证明变更为 409，目录服务故障仍为 503，不重新执行分析。

复用现有 ORM、事务及宿主 _schema_migrations，未增加迁移或公开 authority DTO。私有会话、原执行入口及附件边界继续保留。

## 真实 HTTP 验证

新增 TestUnpublishedMixedOldRoleReportAndAnalysisFirstDeliveryThroughRealHTTP 使用真实 Identity、Runtime、Report、Tools、Agent 后台任务及 SQLite，仅模型 wire 为确定性夹具。两个独立旧角色各产生一份报表／分析原回执；实际完整报表逐行求和与分析总额均为 70。

切换到没有专业执行权的成果阅读角色，明确绑定接收 Agent。两份原来源在发布前不可从交付入口读取，普通执行／结果入口也不能通过该角色重放。账号通过 HTTP 首次提交两个旧角色的混合交付；旧报表角色失效时首次提交拒绝，恢复后原证明逐份核对成功。

发布后两份完整结果与原值逐字节对应，重启后保持。字段撤权保留原角色及原发起角色，两个回执均拒绝；独立 owner 端口也验证分析的当前字段拒绝。恢复资料权限后可读；最终只移除原报表角色，报表拒绝而独立分析原回执仍可读。普通执行资料始终隐藏。

时钟协作的旧基础场景也按当前独立阅读要求更新：撤回时钟执行权隐藏原执行、原消息及分歧来源，保留有当前 delivery_read 的已提交原值及其历史版本，并核对当前交付和完整历史原值一致；再撤回 delivery_read 时当前交付和核对信息隐藏，历史成果入口拒绝读取。不能把执行权撤回当成成果读取权撤回。

本阶段的新混合旧角色提交由账号 HTTP 完成。既有跨用户／同用户不同角色专业 Agent 的工具委派、自动四回执交付与账号验收另作回归，不能把本阶段账号提交宣称为混合旧角色端到端模型自动交付。
