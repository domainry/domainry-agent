# K05 图片输入与模型能力匹配验收

日期：2026-09-16。本轮把图片输入接入现有会话、Knowledge 私有附件、模型能力目录、恢复和 Agent 委派链。K05 验收完成后，完整清单进度为 **20／25**。

## 契约与 owner 边界

- Agent SDK 增加兼容旧文本字段的有序文本／图片内容块。浏览器输入图片时只提交附件 ID 和清晰度；会话、文件名、媒体类型、字节数、SHA-256 与修订均由 Agent 从当前附件记录冻结。
- Knowledge 继续拥有会话私有附件、存储端口和上传／下载授权，本轮增加 PNG、JPEG、GIF、WebP 白名单与扩展名／实际媒体签名匹配。Agent 不复制附件表或二进制存储。
- 模型请求、执行步骤、任务、轨迹和分叉只保存不可变引用，`Data` 字段不参与 JSON。持久化边界再次拒绝二进制、非法摘要、伪造来源、非用户图片、超过四张以及未声明图片能力的模型快照。
- 浏览器沿用附件上传接口，使用逻辑消息 ID 和图片序号形成稳定上传幂等键。相同发送重试复用身份，换图会生成新的发送身份。

## 模型装配与恢复

配置模型必须明确声明 `image_input=true`。前台消息在入队前检查，后台任务、委派和分叉在接收时再次检查，模型输入与执行步骤在落库时还有独立门禁。旧文本消息不生成内容块，原请求线格式保持不变。

每次普通回复、工具步骤、摘要或提供者重试前，Agent 都重新调用当前附件下载授权并读取原件，核对会话、附件 ID、文件名、类型、字节数、SHA-256 和修订后才在内存副本中写入数据。Chat Completions 编码为 `image_url`，Messages 编码为 base64 `image/source`，Responses 编码为 `input_image`；三种线格式都不发送内部附件和来源元数据。

服务重启后，冻结引用可从历史模型输入恢复，原件仍按当前权限重新读取。摘要保留被压缩区间的图片引用；会话分叉把引用绑定到准确完成运行，并在每次子会话装配时复核来源轨迹和附件。附件删除、内容变化或授权撤回会阻止后续模型请求，并从当前消息读取投影中隐藏图片块。

## 委派共享

创建普通后台任务或跨 Agent 委派时，只从准确来源运行的用户消息继承图片，并写入来源会话、运行及步骤边界。接收 Agent 使用图片前必须同时通过委派来源发布／执行读取链和发布者当前附件授权；附件 ID 本身不授予接收方下载权限。

真实三账号 HTTP／Identity／SQLite 链路验证：发布者上传并发送真实 PNG，执行者接单后模型收到相同字节及准确来源引用；第三账号只能按已发布执行查看允许的过程，撤回通信／执行发布或附件权限后已保存内容不会继续暴露，服务重启也不会恢复失效授权。

## 页面

输入框支持选择、预览和移除最多四张受支持图片，文字可为空。发送时先完成私有上传，再提交引用；发送失败保留图片选择以便使用同一逻辑身份重试。自己的历史图片通过当前会话私有下载路由显示；委派来源图片显示文件名、大小和来源授权说明，不向接收账号生成发布者私有下载链接。轨迹页面显示引用元数据，不包含图片字节。
