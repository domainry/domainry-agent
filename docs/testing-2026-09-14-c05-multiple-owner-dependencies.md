# C05：多个所有者的原专业来源依赖

本阶段接续[依赖主体与传播](testing-2026-09-14-c05-dependency-subjects.md)和[模型请求上下文计量](testing-2026-09-14-c05-context-meter.md)，补齐接收 Agent 对多个上游所有者原专业回执的实际阅读与交付。C05 其余范围继续待办，整表仍为 **4／25**。

`delegation_source_read` 版本 2 增加可选 `dependency_id`。模型仍传当前委派 ID；来源必须属于本次运行冻结的准确上游依赖，并位于该上游原约定的 `requirements.sources` 前缀内。每页分别检查所采用的约定版本、依赖投影、原始发布、原提供者与发布者角色，以及实际读者的当前受众和资料权限。返回页保留上游 ID、准确原结果引用、SHA-256 和原字节。新调用只发现版本 2；已保存版本 1 的原页继续按准确旧定义核对，未知版本及篡改定义拒绝。

各上游保留自己的发布范围。接收方交付引用自己读取原页时由服务器记录的阅读回执，嵌套原来源继续重新核对；下游重新共享自己的约定不会改写上游发布者或扩大上游受众。运行回执具有准确调用前缀，后面的回执可能包含前面已读取的来源，不能将其当作只有最后一项来源的无关数据。

本阶段还修复两个实际失败：

- 跨归属委派的匹配追溯原来沿来源会话始终使用当前执行人，读取另一个账号的私有祖先会话时返回 404。存储层复用已有按原主体追溯来源链的逻辑，经可选 SDK 端口只返回 Agent ID；当前起点仍必须归当前主体所有，原循环排除与八层深度限制保持。没有增加私有会话或原运行的读取入口。
- 原约定保存直接依赖，执行任务冻结完整依赖链，不能直接比较两个数组。应用层按已采用的准确原约定版本重建链路后比较，不能跟随今天的上游替换来源。空 `fields` 在存盘后省略，原遍历把 `[]` 与 `nil` 算作不同键，造成同项重复；现已统一遍历键。历史重复项仅在完整证据一致时合并，版本、根或数值证据冲突拒绝。空依赖链也保持等价。明确来源／依赖拒绝保留对应执行错误码。

真实 Runtime 场景使用三个真实 Identity 账号：第一个账号在旧报表角色下执行原 `report_query`，第二个账号在另一个旧分析角色下执行原 `analysis_run`；随后各自在阅读角色下首次发布自己的要求来源。第一个发布者明确授予第三个账号上游查看范围，第二个发布者向第三个账号的 Agent 接单。第三个账号另一个独立 Agent 采用两个原上游版本，从模型实际收到的 `Content` 发起阅读，计算报表与分析实际总额各为 70，引用服务器记录的自己阅读回执，提交交付并通过程序规则，最后由账号明确验收。

验证覆盖：

- 实际账号登录、角色配置、Agent 绑定、匹配、接单、工具调用、SQLite 原账本、专业查询和 HTTP 为真实链路。模型为确定性夹具，没有调用外部模型服务。
- 接收方仅调用 `delegation_source_read`、`delegation_get`、`delegation_update`；未重复执行报表或分析。原结果引用、原 SHA-256 及完整结果内容保持，直接访问两个提供者的私有结果入口返回 404；上游仅查看范围不授予执行查看或取消权。
- 重启后阅读和验收保持。分别撤回两个原专业角色、两个发布角色、读者字段权限及第一个上游受众后，相关旧回执拒绝；恢复后可读。第二个所有者撤权不隐藏其前面第一份阅读回执。所有恢复后，原验收内容、已完成任务和原执行运行 ID 保持。
- 存储验证当前起点归属、跨工作区拒绝、只有 Agent ID 的追溯、空字段依赖去重、跨归属变更停止，以及下游重新共享不改写上游发布和受众。
- 应用验证准确已采用版本、历史重复项、篡改依赖／依赖 ID／原根拒绝、两个所有者各自角色范围及原结果独立阅读；原版本 1 保存页继续可读。
- 八个完整核心 Go 包、SDK 所有包、四个真实 HTTP 根场景、六个应用／存储根场景的 race，以及既有旧角色混合专业阅读／自动交付 Runtime 根场景通过。

Runtime 验证使用 `/tmp/runtime-work/go.work` 装配当前本地模块，没有改发布依赖或创建分支。编译时发现 Runtime 当前上传调用把公开身份投影传入要求完整身份的内部端口，已改用该执行原本持有的 `invocation.Principal`，Action／Upload 完整包通过。上下文仍为默认 65536 字节，新增任务仍为 12 步、12 次调用、8192 字节输出和 180 秒，没有提高预算。

诊断失败独立归档，不计通过：早期发布依赖编译、夹具类型／观察账号／请求频率、跨归属匹配 404、直接／完整链比较与空字段重复、模型误传服务器 `client_id` 和空数组、私有入口及验收状态名的夹具预期，以及误把各回执撤权结果要求一致。没有把上一阶段完整 web 或 Chrome 记录记为本阶段新增验收。
