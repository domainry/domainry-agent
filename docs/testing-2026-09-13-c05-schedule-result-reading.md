# C05：计划工具独立回执读取

日期：2026-09-13。接续[历史与执行记录读取](testing-2026-09-13-c05-history-result-reading.md)，补齐 `schedule_create/list/get/update/pause/resume/delete` 的来源策略。C05 仍保留跨用户／角色主体协作；整张清单仍为 **4／25**。

## 实现

Tools 的计划适配器声明 `AuthorizeResultRead`。读取使用实际当前用户的计划归属和 `schedule_get` 数据权限；列表额外检查 `schedule_list`。这些检查直接调用当前授权端口，不通过阅读者 Agent 的工具配置取得原创建／更新／暂停／恢复／删除权限，不携带确认、租约或写入幂等键，不运行计划操作或查询重放。

Agent 对计划回执额外核对原持久执行记录的调用、定义、完整结果和幂等键。Tools 校验原请求摘要、输出形状、操作类型、资源 ID 和预期版本。列表逐项读取原来保存的计划，不重新执行列表查询；新计划不会替换旧页。状态变化允许保留原状态和版本；计划内容、种类、来源和创建身份仍须与当前计划一致，内容修订或源计划删除后隐藏旧正文。

删除回执使用新增的 Scheduler 可选端口 `ScheduledPlanDeletionReader`，查询实际 owner tombstone，仅返回计划 ID、删除版本和 deleted 标记。不存在或仍存活的计划都返回 not-found。端口不调用 Delete／Reconcile，不恢复投影或触发工作，复用原持久表，没有数据库迁移。SDK、Module 实现、远端 Binding、私有 SaaS 路由和 HTTP SDK 已接通；远端按独立 descriptor capability 协商。SaaS 读取只使用由宿主启动或绑定握手初始化的应用，不调用可能启动 worker 的延迟初始化路径。没有端口的旧部署明确返回 unsupported，继续采用原执行授权；实际来源拒绝不降级放行。

计划正文可以带原会话／运行引用。Agent 在交付读取、普通来源复用和原结果读取／恢复时继续检查这些引用：实际用户拥有源会话、当前私有执行读取权限、原运行资料来源；同一运行只遍历本次调用之前的来源。计划里的通信正文不使用同委派的交付来源例外，读取缓存也保持分离。通过产品 API 创建且没有会话引用的计划依然使用计划 owner 权限。

## 验证范围

- Tools 七种操作覆盖写权限撤回、读取权限撤回、不同用户、原内容保持、状态变化、内容修订、来源删除、删除端口缺失和取消；读取前后计划状态相同。
- Agent 原始账本和嵌套计划来源检查覆盖私有通信缓存、缺失源会话和伪造操作身份；计划读取不请求生产者执行授权。
- 真实 Agent、Identity、SQLite、HTTP 和 worker 实际执行七次工具调用并提交七份交付回执。五次写调用沿用当前宿主策略，该策略没有请求确认，本阶段未变更确认机制。当前／历史交付分页结果在撤回写权限后保留原值，计划读取权限／私有执行权限撤回及工具停用时隐藏；普通写调用的原结果入口继续拒绝；恢复权限并重启后值不变，计划状态未被阅读修改。此 Agent 测试的 Scheduler 端口使用 owner fixture。
- Scheduler 独立真实 SQLite 与 SaaS HTTP 场景实际创建、删除、关闭并重启宿主，再读取原 tombstone，复核用户／工作区／产品／Runtime 归属；普通 get 仍隐藏删除记录。本地 owner 测试不安装 clock、投影仓库或 dispatcher，验证该接口只读；远端测试检查 capability 缺失和实际错误传播。
- 既有计划自然语言／产品管理和历史／任务回执 HTTP 场景回归通过。
