# C05：Identity 主体事实复用与末次授权检查

接续[报表对象投影与实际生命周期采样](testing-2026-09-14-c05-report-object-projection.md)。当前代码确认一次 SDK 主体解析除了两次主体构建，还重复读取用户、有效角色、分配及快照角色。两次构建中的后一次承担当前授权版本检查，不能用首次结果替代。

新增 Identity 内部 `ResolvePrincipalContext`，由一次实际主体构建收集用户、有效分配和角色投影；应用层 `ResolvePrincipalAccess` 用这些事实构建快照，然后重新读取当前主体并比较授权版本。SDK 只消费该 owner 用例，不接受调用者提交的主体或事实。明确角色、角色 ID 别名及 SessionRoleKey 的有效权限合并语义保留；普通有效访问端点仍走原授权入口，工作负载分支继续使用原专用路径。主体构建查用户改用仓库现有按 ID 查询；汇报范围仍读取当前用户列表，没有增加跨请求权限缓存。

真实 SQLite／ORM／SDK 对照夹具记录如下，均包括保留的最终授权复核：

| 仓库读取 | 原生产路径 | 当前路径 |
| --- | ---: | ---: |
| 按 ID 用户 | 1 | 2 |
| 工作区用户列表 | 4 | 2 |
| 角色列表 | 4 | 2 |
| 用户角色分配 | 4 | 2 |

同一最终夹具用 Go overlay 恢复本轮修改前的四个生产文件，并将两个新增生产文件中性化，复现四种选择方式的重复读取和十种末次复核缺失；取消仍正确拒绝。七种实际变化包括分配撤回、用户停用、角色停用、权限停用、发布策略变化、分配过期及绑定资格失效；最后三种为投影 IO 之后注入的按 ID 用户／角色／分配查询异常，当前新增末次读取会传播异常。初次计数误按 ID 查询与用户列表同一入口，以及过期字段夹具类型错误，分别作为测试诊断保存，不计生产权限缺陷。

另一个真实反例确认角色列表已排除停用角色，但原 `BuildPrincipal` 仍把该角色的权限合入有效主体。当前合并同时检查角色状态，移除该角色的授权；原生产路径及本轮状态补丁前分别保存失败证据。四个新根包含四种选择、十一种投影期间变更／失败、停用角色合并和跨请求撤权；当前全量 Identity 59 个有测试包通过，核心 Domain／Application／SDK 的实际 race 共 189 根通过。按 ID 查询的最终失败、角色／分配最终失败都保留原错误链；撤回后同上下文再次请求不能复用先前事实。
