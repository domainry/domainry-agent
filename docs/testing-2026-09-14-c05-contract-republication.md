# C05：原约定恢复与明确重新共享

日期：2026-09-14。接续[原交付重新共享](testing-2026-09-14-c05-delivery-republication.md)，本阶段补原约定的准确版本恢复、预览、共享和审计。完整条目仍为 **4／25**，C05 保持部分实现。

## 当前实现

- 新约定版本保存当时完整的 Requirements。旧记录的空快照标记保持不变，恢复结果单独返回；不能从今天的委派、任务或配置补造原要求。
- 原约定记录必须实际存在。旧 Requirements 可从准确首次接单的不可变重试回执、准确已完成的 `agent_delegate` 调用，或持有要求根和原执行身份的同任务／约定版本运行恢复。多个原声明必须一致；缺失、冲突、其他委派／任务／角色证据拒绝恢复。没有资料根的旧运行不能证明当时声明为空。
- SDK／HTTP／Module／SaaS 接通版本索引、准确原约定预览及共享审计。索引只返回版本；预览按当前查看／管理／共享权限、发起人归属和逐根当前来源权限检查，不产生发布授权。原提供者、当前发布者与接收主体分别核对。
- `republish_contract` 绑定准确原约定版本、服务端规范记录摘要和委派 CAS。提交重新检查当前权限，事务内重新取原记录／比较摘要，保存本次实际发布用户／角色和准确资料发布范围。只更新委派修订号及时间，并新增审计；不执行原任务、不改原约定／交付／核对／验收／决定。
- 资料授权失败时，仍有当前查看权限的人可以取得安全的恢复入口：委派 ID、双方、状态、修订号及访问标志。原文、要求、依据、任务、消息、交付与核对资料均不返回；查看权被撤回仍拒绝，临时不可用仍报错。
- 页面可选择原版本、预览、填写说明并明确共享，查看本次实际发布人与接收人。关闭／失焦／版本变化／撤权清除预览；提交成功但响应丢失时，刷新后仍能按准确原请求 ID、摘要及 CAS 重试。已验收记录也可共享，重试不重复审计。
- 原始结果恰好属于读者当前完整身份时，普通阅读先检查原身份及当前数据权限，不依赖其他发布角色。相同用户的其他角色、其他用户和超出原引用前缀的资料仍需准确发布证明与当前权限。
- 通过 ORM 新增宿主迁移 29 的发布审计表，纳入主体清理；不引入模块私有迁移账本。

## 验证范围

应用用例覆盖索引不泄露资料、缺少私有来源端口、预览不发布、来源／原角色撤权、错误发布主体、伪造摘要、模型不能发起人工重新共享、窄范围回执与恢复入口。存储用例覆盖原要求冻结、旧排队接单从首次不可变回执恢复、只从捕获原根与原身份的运行恢复、原任务／验收／历史不变、混合写入回滚、准确重试单条审计及跨执行归属的原 assignment 恢复。

真实 Runtime 场景先通过工具生成不同旧角色的完整报表与分析原结果，两者原值均为 70，再由读取角色的 Agent 委派、分页阅读、自动交付及账号验收。停机后仅去掉原约定 Requirements 快照和既有发布者旧格式标记，保留真实原账本／接单调用／运行。重新打开后恢复准确两个原要求根，切换当前阅读角色、预览但不授权，当前字段撤权拒绝提交，明确共享后原约定可读，重试只有一条审计，原任务／验收／历史保持。原专业角色与发布角色撤权、原页重读及再次重启继续核对。

真实 Identity／Agent HTTP 浏览器使用实际自动时钟委派和账号验收，覆盖原约定选择、预览无授权、明确共享、服务端提交成功但响应丢失、刷新后准确重试、单条审计和实际发布身份、当前 Share 撤回／恢复、预览清理及桌面／窄屏。浏览器数据库使用当前格式，旧格式恢复由存储与真实 Runtime 验证。

通过 8 个核心／SDK／传输包、2 个包的针对性 race 用例、1 项真实 Runtime 场景、1 项真实 HTTP 浏览器流程、75 项前端测试和前端构建。118 份相关源码／测试及工作区文件摘要、571 份构建文件摘要与日志一并保留；race 原始用例日志保留，原 shell 调用未留存。

本阶段使用 SQLite 和确定性模型 wire。完整旧历史接单流程、多所有者旧角色首次共享与混合依赖根、其他专业来源、完整执行详情共享、跨主体转交／退出和参与人更多权限范围继续待完成；缺少整个原约定记录的情况仍拒绝，不从当前资料合成旧历史。恢复页面的普通暂停／取消等管理操作仍需补齐。
