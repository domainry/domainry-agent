# C05：明确资料共享

日期：2026-09-13。接续[完整成果阅读](testing-2026-09-13-c05-delivery-artifacts.md)，将现有 `share` 权限接入可使用的资料共享流程。C05 仍未整项验收，跨用户／角色主体和 Knowledge 检索／抽取、业务等其余 owner 的独立结果阅读策略继续在原清单推进。整体 **4／25**。

## 实现

- 沿用委派消息 HTTP／Module／SaaS 和 `agent_message` 工具，增加可选 `documents`。每条消息最多 4 个准确资料库文件引用，包含 `library_id`、`document_id`、`revision` 和 `sha256`；不保存副本正文，不允许私有附件 ID、重复文件或不完整的版本引用。旧消息不含该字段时保持原行为。
- 发送必须有当前 `communicate` 和 `share` 权限。Knowledge 通过自己的 `documents_get`、`documents_download` 和资料库成员／来源绑定检查，确认文件仍处于 ready 状态且版本和 hash 一致。引用不会增加资料库成员、专业工具或执行授权。
- 使用已有消息事务保存引用、真实发送者、接收方、任务约定版本及幂等回执；与收件箱一起投递和消费，重启不重复发送。Agent 发消息继续保留原运行来源和私有附件来源限制。
- 接收前、历史运行及工具结果再使用时重新核对当前 Knowledge 权限和准确版本。引用作为有明确来源的任务数据进入模型，注明不能将其当作指令或授权；模型需调用原有受权 Knowledge 工具读取正文。收件箱字节预算现在计入实际序列化引用及前缀，首条消息超限明确报错。
- 沟通记录对当前不可访问或已变更的资料隐藏引用及关联消息正文，保留失效提示。原执行历史继续要求完整来源检查。
- 页面增加资料库／文件选择、随消息共享、读取文件信息和下载原文件；支持分页、移除待发引用及当前版本核对。下载沿用原有身份、取消、大小和 SHA256 验证；权限变化、切换页面和关闭窗口时清除已读内容。
- 私有附件继续通过既有“另存到资料库”创建独立副本，再明确发送副本引用；不自动改变附件可见范围。本文新增的共享入口适用于本部署、同一当前用户下的 Agent；没有把跨用户主体建模算作完成。

## 验证

- 应用：发送缺少 share 时在读取来源前拒绝；接收和已存工具结果来源检查覆盖撤权、跨 owner、版本或 hash 改变、删除和索引状态；超出上下文字节上限不会静默丢失消息。
- 持久化／SDK：准确引用及真实发送者、重建 Store 后收件箱、相同 mutation 重放、不同版本冲突；拒绝私有附件、无效 ID／hash、重复引用及超限。
- 真实 HTTP／Identity／Knowledge／SQLite：上传会话私有附件，明确另存到共享资料库并验证幂等，删除原附件后副本仍可下载；发送检查共享权、下载权和版本；接收 Agent 经 Knowledge 工具读到原件，再通过实际 `agent_message` 工具把准确引用发回委派方，保留 Agent 身份和原运行来源；撤权隐藏引用，恢复和重启后可核实原消费记录。整个流程只有一次副本索引写入。
- SaaS：实际 HTTP 签名转发保留任务约定版本、准确文件引用和用户主体；当前拒绝原样返回，跨工作区请求不抵达 owner。
- 真实 Chrome：选择文件版本、发送引用、下载原件、撤回共享权、撤回阅读权、恢复、刷新、390px 窄屏及 blur 内容清理。

证据与最终检查结果见[命令记录](evidence/2026-09-13-c05-shared-documents/commands.md)。无新增数据库迁移；资料正文和权限仍归 Knowledge，现有附件另存流程没有改动。
