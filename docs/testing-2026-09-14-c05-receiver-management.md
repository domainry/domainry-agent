# C05：接收方管理交付与 Agent 窄回执

日期：2026-09-14。接续[参与人管理范围与原任务归属](testing-2026-09-14-c05-participant-management.md)。C05 继续实现，整表仍为 **4／25**。

接收方原有交付阅读责任与明确新增的管理范围可以组合。应用仍核对当前 Identity 的查看、管理、交付阅读权及实际授权人的当前共享权；保存事务复核准确接单映射和管理名单，接收方的原有交付阅读不会因新增管理范围被误拒绝，也不会提供给其他管理参与人。撤回管理范围后，即使原接单责任仍在，旧管理请求也不能重放。

获授权的接收方 Agent 可以从自己另开的会话核对交付。保存前仍验证实际调用身份、准确运行租约、工具定义、参数、幂等键和执行栅栏；保存的核对记录使用实际用户、Agent 和核对运行。发起会话、原执行会话、原任务及原执行用户不变。普通参与人当前不能授予 `delivery_read`，本次没有扩大其支持范围。

真实 Agent 流程还暴露了窄回执的来源审核缺口：写入返回的 `management_only` 回执没有完整名单和执行身份，不能用它本身推断权限。现在审核先严格验证其允许字段，再通过服务端当前委派记录复核查看／管理范围及当前角色；旧回执可以保留原版本，但每次阅读都重新复核授权。给回执附加私有约定、输入、会话、任务或名单均被拒绝，同一次审核对象中撤回当前管理权或缩小名单也会拒绝再次读取。

新增存储场景覆盖接收方核对／验收、重启后准确回执、撤权后旧请求拒绝、普通管理人不能借用接收方阅读权，以及实际 Agent 从独立租约会话核对、伪造发起会话租约与取消租约后重放拒绝。新增应用场景覆盖窄回执当前授权和额外字段边界。

真实双账号 HTTP／Identity 场景从实际待办执行开始，覆盖没有明确管理范围时拒绝、明确授予后当前交付阅读权撤回时拒绝、拒绝不修改版本，以及真实模型工具 `delegation_get`／`delegation_update` 核对。模型收到的结果是只含必要状态与版本的管理回执；核对没有自动验收，原发起人随后验收，重启保留原记录，原执行绑定撤回测试继续通过。

模型为测试夹具；Identity、HTTP、工具执行和数据库持久化使用真实链路，没有调用外部模型服务。

本次验证：

- 应用及存储两个完整包回归通过。
- 两个包相关 race 场景通过。
- 三个真实双账号 HTTP 场景通过：原接收角色执行／管理核对／重启撤回、独立参与人管理／通信、跨主体真实来源工具委派与自动交付。
- 保留修复前的两项接收方权限失败、仅修阅读门槛后的 Agent 会话限制失败，以及窄回执审核失败；准确生产快照在 `source-before/testdata`。首次 HTTP 夹具缺少必填原因及后续窄回执审核失败分别保留诊断，不计为通过。
