# C05：参与人依赖管理与跨归属传播

依赖读取现在按准确上游委派和当前查看范围解析，物理存储归属不再替代实际读者。管理下游委派不会取得上游查看权限；转交时分别核对管理人和接手人的上游范围。存储在冻结依赖、检查循环、创建原执行任务和转交事务中使用实际主体。发起归属、管理操作人和执行角色分别保持。

模型读取冻结依赖时使用准确原约定版本和原字段投影，核对来源引用及摘要；当前约定不能替换历史值。资料沿用上游约定发布范围，并复核实际发布角色、原提供者角色和当前读者。其他委派或交付／执行用途的发布不能释放该依赖。重新共享下游约定只发布自身直接来源，保留上游发布者及受众，应用和存储均检查接手人的上游查看范围。

参与人详情返回已核对的依赖、当前依赖状态、变更通知及工作目标关联；不取得私有源会话、任务或执行会话控制。页面转交保留准确上游 ID、版本及字段，并显示本次采用的上游要求。来源撤权后，详情回到不含依赖值的恢复元数据。

要求变更沿同一工作目标的持久依赖图传播到其他归属。每个节点先以真实物理归属核对工作区；系统停止原角色的下游任务、记录准确变更来源并通知原双方，变更人不会取得这些私有委派。同一个目标 ID 在其他工作区不进入传播。旧归属记录从准确主体映射或原任务证明恢复，无法证明的记录不推断归属。

验证包括以下实际范围：

- 存储中的 A→B、B→C、C→D 委派和原角色 worker；A 修改上游后，两个下游停止，旧 worker 无法提交，原通知和归属保持；其他工作区碰撞目标保持运行。
- 管理人缺上游查看范围时无法设置依赖；授权后冻结准确字段。不同接手人缺上游范围时转交事务不创建任务；明确授权后接手，管理人与执行角色分别保存。
- 原接单工具的持久确认、实际调用回执和来源前缀；跨归属下游约定重新共享保持上游发布记录、不新增下游来源发布；接手人上游范围撤回后重新共享事务不修改委派。
- 应用来源夹具覆盖历史版本、字段／原值／摘要／引用篡改、三方角色撤权、准确委派和用途范围、参与人详情及撤权隐藏。
- 真实 Identity 三账号与 HTTP：含依赖转交、原发布保持、准确重试、手动交付验收和重启；新执行第一轮请求等待时撤回上游查看范围，下一次调用前停止。检查新运行的实际工具账本为零条，且没有第二轮模型请求。
- 真实 Chrome 参与人转交的请求保留上游版本及目标字段；接手历史、原共享执行、旧执行人撤回入口和 390px 页面。六张截图逐张查看，无 page error。

六个完整 Agent Go 包、相关来源／依赖／转交／逐次身份／退出的 race、跨归属约定重新共享的独立 race、三条真实 HTTP 转交根场景、Chrome、前端 79 项测试及构建通过。核心包为 application、database/agent、remote、transport/http/module、capability 和 server；HTTP 根测试另行执行。来源夹具和存储场景覆盖上述各自范围，不把它们记作新增 Runtime 验收。

模型使用确定性夹具，实际调用内置 `time_now`，没有调用外部模型服务。本阶段未新增 Runtime 专业工具验收；多所有者混合专业依赖来源、完整旧接单和历史共享、更广的 Identity 退出联动及其余 C05 范围继续待办。完整清单仍为 **4／25**。
