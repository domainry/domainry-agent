# C05：个人工具原回执独立阅读

日期：2026-09-13。接续[业务写入回执](testing-2026-09-13-c05-business-write-receipt-reading.md)，本阶段覆盖 `calculate`、`time_now`、`ask_user`、`memory_search`、`memory_save`、`memory_forget` 及五种 `todo_*` 工具。整体仍为 **4／25**；C05 的任务／历史／执行记录来源策略和跨用户执行主体尚待完成。

## 实现与权限

个人结果只在服务端已授权的交付来源审计中使用独立阅读策略。读取要求当前 `delivery_read`、工具启用、实际读取者拥有原会话，以及原执行账本中的完整调用、定义、幂等键和完成结果一致。原参数按当前已知定义校验；缺少原执行读取端口时保留既有授权路径。不能通过模型提供的结果值或资源 ID 构造回执。

- 计算结果用原参数重新核对确定性算法；时间结果按原时刻和原时区来源核对，不替换为当前日期或用户后来更改的时区。
- 用户答复读取原完成调用的答复和交互 ID，不取得 worker 租约、不再次提问，也不以读取权限代替确认权限。
- 记忆沿用当前用户的 Memory 读取接口。交付中的每条记忆必须与当前保存版本完全一致；更正、停用或删除使旧内容不可读。明确保存的停用记忆仍按该原版本核对。
- 待办通过 Todo owner 的存储接口核对实际用户与原资源身份，使用现有 `todo_get` 数据读取权限，独立于读取方 Agent 的工具配置。原待办状态和版本保持历史值；后来完成待办不会修改已交付回执。删除来源待办或撤回读取权限会隐藏结果。
- 记忆／待办删除只允许原账本证明的 `{id, deleted}` 确认，不恢复已删除内容；待办删除回执仍要求当前 `todo_get` 读取权限。

入口只读，不重复保存／修改／删除，不产生新确认；普通运行详情、普通结果读取和个人资料的用户隔离沿用现有策略。本阶段未修改公开 SDK、数据库迁移或生产前端。

## 验证

逐项应用测试覆盖十一种工具、实际读取者／工作区、缺失会话、原参数／结果／定义／幂等键篡改、停用工具、记忆更正／删除、待办删除／撤权及历史状态保持。

真实 Agent、Identity、Todo、SQLite、worker 和 HTTP 场景执行计算、时间、用户提问、记忆保存／查询、待办创建／查询／更新，以及记忆／待办删除。四次实际用户响应或两次实际删除确认完成后，撤回生产工具权限、只保留协作阅读与 `todo_get` 数据读取权，验证当前／历史交付内容逐字保持原值，原运行和普通结果入口拒绝，资料撤权或遗忘隐藏内容，恢复与完整宿主重启后行为一致。读取没有新增记忆版本、待办更新或恢复删除项。

命令与原始结果见[测试证据](evidence/2026-09-13-c05-personal-result-reading/commands.md)。工具设置停用检查在撤回执行权前进行，因为设置目录本身只列出当前获准执行的工具；不为测试修改产品授权。

## 剩余范围

任务、历史消息和执行记录可包含未交付的上下文与运行细节，需分别核对当前来源及执行阅读范围，不能直接扩入以上个人结果白名单。跨用户／角色主体仍需要显式参与者与执行主体模型；本阶段没有替换读取者 UserID。未提供独立阅读端口的自定义来源继续要求原执行授权。前阶段记录的 Runtime 发布模块锁与工作区契约差异仍待联合发布核对。
