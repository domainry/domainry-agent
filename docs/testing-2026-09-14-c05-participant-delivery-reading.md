# C05：参与人的独立交付阅读

日期：2026-09-14。接续[接收方管理交付与 Agent 窄回执](testing-2026-09-14-c05-receiver-management.md)。整表仍为 **4／25**，C05 继续实现。

参与名单现支持 `view`、`communicate`、`manage`、`delivery_read` 四项独立范围。授予交付阅读需要实际授权人当前的查看、管理、共享和交付阅读权限；阅读再取当前 Identity 权限与这项委派名单的交集。交付阅读提供当前交付、已提交历史和准确原回执，不提供私有会话、任务、实时调用或执行过程。

授权人只能转发已明确发布给自己的同委派交付来源。保存事务保留原提供者、实际发布用户与角色、准确用途和原运行前缀。新增阅读者没有变成原执行人或原发布人。新交付及原发布人的明确重新发布也覆盖当前交付阅读名单；撤回名单不依赖阅读旧资料。重启保留实际提供者与发布者证明。

三账号流程暴露了嵌套来源的归属问题：接收方回执引用发起人的原始输入，第三人阅读时不能把未知嵌套来源当成第三人的私有运行。现在先核对第三人持有的准确发布记录，按原提供者查账本，实际读者仍是第三人。外国用户阅读历史协作快照时，名单权限取服务端当前委派，历史内容和证据仍取原版本。

页面独立提供“阅读交付”选项，沟通或管理选项变化保留它。撤回后关闭旧交付和原回执；重新授权须重新读取。桌面截图及 390 像素窄屏截图已检查。窄屏测试增加弹窗实际边界检查并等待布局，避免仅检查页面滚动宽度就误接受裁切截图。

验证：应用、存储及 SDK 三个完整包通过；前端 77 项测试、类型检查与构建通过；两个 Go 包相关 race 通过；三个真实 HTTP 场景通过，其中来源场景包含真实第三账号的 Identity 建立、角色分配和登录、当前与历史交付、准确回执、私有入口隔离、原发布角色共享撤回、授权人共享撤回、名单撤回与重新授权。Chrome 七项场景通过，无页面异常；真实 Runtime 旧约定更新、重启恢复与原历史 HTTP 场景通过。

模型使用夹具，Identity、HTTP、数据库、真实时钟工具及 Runtime 端口使用真实链路，没有调用外部模型服务。时钟结果为 159 字节，首个 256 字节请求已经完整；本次验证了准确最终偏移及撤权后再次请求拒绝，**没有把它计为大型专业结果的多页阅读证明**。
