# C05：工作区账号的跨主体原来源与回执

日期：2026-09-14。接续 [Identity 停用与生命周期删除](testing-2026-09-14-c05-identity-lifecycle.md)。本阶段补邮件、日历、网页的实际跨账号委派与执行阅读，并修复原写入回执的执行人定位。C05 仍保留剩余范围，整表仍为 **4／25**。

## 实际行为

两个真实 Identity 账号分别作为发起／读者和 Agent 配置所有者／执行者。发起 Agent 从模型可见消息调用 `agent_delegate`，账号确认该调用后，接收方以自身绑定角色和独立会话执行。Integration、Connectors、Tools、Agent worker、OAuth 流程及独立 SQLite 数据库使用实际实现；上游服务和模型为确定性协议夹具，不代表厂商真实账号或真实模型的成功率。

- 邮件覆盖账号发现、列表、搜索和正文四项原回执；日历覆盖账号发现、列表、事件列表、正文和忙闲五项；网页覆盖搜索与正文两项。每项完成条件只采用对应工具的原回执，实际自动交付后由账号明确验收。
- 工作区账号沿用 Integration 的工作区归属与当前资料权限。双方撤回专业执行权后，读者仍可读取当前／原交付回执、明确发布的完整执行及 256 字节分页的原结果；完整原 JSON 与 SHA-256 保持。阅读不请求原操作确认、不调用外部服务、不开放私有会话或取消入口。
- 原执行在真实工具已持久标为运行中、Connector 的业务 HTTP 尚未返回时明确发布。其他账号可查看公开步骤和时间，未完成调用的参数、结果、确认和授权保持隐藏。
- 邮件和日历分别创建实际个人账号并执行正文读取；即使再明确授予另一账号委派的执行／交付阅读范围、发布准确原运行，个人正文及原回执仍拒绝，原所有者可读。委派发布不改变 Integration 个人账号归属。
- 读者撤回账号资料阅读、原工作区账号撤销后，相关交付及执行正文关闭；完整重启和重新登录不恢复执行权限，也不重新获取原外部数据。
- 真实网页 HTTP 503 单独验证失败调用：原私有运行保存实际失败参数、错误和之后的模型答复；共享运行保留状态与时间，隐藏失败载荷、结果引用、错误正文、答复和控制信息。执行权撤回及重启后保持，不重发外部调用。

## 写入回执修复

原 Tools `WriteAdapter.AuthorizeResultRead` 按读者的用户 ID 查询 Integration 原账本。Integration 的原 invocation ID 与账本元数据绑定实际执行人；另一获授权工作区读者因此找不到原回执，交付及执行阅读被错误隐藏。

现在先用实际读者的当前账号阅读范围核对准确账号／操作／来源，再使用 Agent 受权发布记录提供的原 `ResultProducer` 核对原执行人的当前资料权限并查询原账本。原执行人只用于原证据定位；结果返回前再次解析实际读者权限与账号来源。未知或错误部署／工作区／执行人、个人账号越权、查询过程中撤回读者范围均拒绝。原请求 ID、载荷指纹、invocation ID、记录时间和回执正文仍逐项核对；没有新增执行或重试入口，也没有更改公开 SDK、Integration 账本或确认规则。

真实工作区邮件写入场景要求发起方明确授予接收方管理范围，再由实际接收账号确认准确发送操作；外部服务只受理一次。交付完成条件明确要求 `accepted` 原回执，保留实际送达状态未知。另一账号在双方撤回专业执行及账号写入权后读取原服务回执、执行参数及原页，明确验收和重启后保持。Calendar 创建／更新、Mail 发送／回复四类公用端口夹具同时核对严格原执行人账本、错误原身份、个人账号、资料范围及读取中撤权。

## 心跳并发修复

实际跨账号 HTTP race 检查发现：worker 为委派来源装配新的执行 context 时，心跳闭包同时读取该变量，造成 `conversation_service.go` 的数据竞争。心跳现在通过协程参数持有启动时的 context，继续使用原截止时间、取消和租约；执行正文仍使用装配后的受权来源 context。没有改变任务预算、当前权限核对或存储围栏。修复前 race 日志单独归档，不计为通过。

## 验证与剩余范围

命令、终态日志、修复前源码和失败诊断分别归档于 [接受记录](evidence/2026-09-14-c05-shared-account-sources/acceptance.json)。此前阶段的清单与日志保持原字节，本阶段另捕获实际账号读取／写入实现与对应测试源码。

读取场景沿用既有通用上下文与宿主设置。写入场景沿用产品已有的 1 MiB 参数、2 MiB 上下文配置；没有为测试提高设置。新委派预算为 12 步、12 次调用、8192 字节输出、60 秒，原同账号写入回归保留原设置。跨账号 MailSend 使用完整普通正文并逐项核对收件人和实际效果次数；原同账号大正文回归继续使用重复 4000 次的原正文。大正文跨账号场景的普通 HTTP 检查通过，但 race 版本在真实 HTTP 等待点之前超时，失败日志保留；不计为 race 通过，也没有通过增加预算处理。测试遇到资源版本竞争时，只在准确约定、接收方、名单及原交付摘要均未变化时刷新版本并重试；其他冲突直接失败。

普通正文的跨账号写入 race 检查同样在真实 HTTP 等待点前超时，不能把原因归为正文大小。两份日志均记失败；仍需定位该链路的实际等待和预算行为。Tools 四类严格原账本读取的针对性 race 与 Agent 的独立检查分别记录，不能替代这条实际跨账号写入 race 的通过。

专业写入的其他实际跨主体组合、其余原来源及完整历史／多所有者／依赖／退出范围的证据核对仍需按 C05 完整要求继续；未接入独立结果阅读端口的自定义来源仍执行原授权检查。C06 及全部后续条目继续保留原顺序。
