# C05：单项委派参与人与通信

日期：2026-09-14。接续[共享 Agent 配置与执行主体](testing-2026-09-13-c05-agent-sharing.md)。本阶段实现单项委派的查看、沟通参与范围；**C05 仍未整项完成，整表仍为 4／25**。

## 当前行为

- 委派记录归属用户，以及带版本的参与名单。所有者具备当前 `view`、`manage`、`share` 权限后，可以通过既有 `delegation_update`／HTTP decisions 接口执行 `set_participants`。最多 64 人，必须属于当前 Runtime／工作空间，范围只支持 `view` 和可选的 `communicate`。参与者不能管理名单。
- Identity 使用实际操作者和委派真实归属人计算权限，随后与该用户的单项参与范围取交集。显式邀请不会绕过角色数据范围；只允许读取本人记录的角色仍不能读取别人的委派。部署需要为参与者配置适当的数据范围，代码不会自动扩大角色权限。
- 参与者可以查看允许共享的当前约定；有沟通范围时可读通信、向委派双方发送补充、问题和回复。原始会话／运行／任务、执行细节、交付与验收资料、其他参与人名单和所有者控制入口不随参与范围开放。消息中不可读取的来源内容会隐藏，执行记录 ID 不对参与者返回。
- 参与者消息保存真实用户、发送时选择的角色和参与版本。消息是任务输入；接收 Agent 继续使用原任务持久保存的执行身份和能力快照。客户端不能用消息参数指定接收方账号或专业工具身份。
- 进入执行上下文前重新核对发送者当前成员状态、原选择角色的当前权限和该项参与版本。撤回或更改参与范围时，在同一事务内使不再有效的待接收消息失效；重新加入不会恢复旧消息。原文和已消费历史保留。
- 授权行锁与冻结输入的事务一起持有；沿用存储方言提供的行锁接口和 SQLite 串行化事务，不依赖 MySQL 对无变化 UPDATE 的影响行数。重复发送使用实际发送者与原请求计算幂等凭证，接收方快照不会改变请求摘要。
- 调整名单返回 `participants_only=true` 的明确保存回执，包括委派 ID、归属、修订号和参与范围。它不读取私有执行来源；完整详情由后续读取单独核对，避免已经撤权成功却因详情来源失败而报保存失败。
- 新增宿主迁移 **26 `delegation_participant_grants`**，使用 ORM 和宿主 `_schema_migrations`；准备状态同时检查 Agent 配置共享表和委派参与表。名单、消息、消费和撤回状态可重启恢复。
- 页面支持添加、查看、调整和移除单项参与人；参与者只看到自己的范围。通信显示实际发送者、消费与失效状态。长 Agent ID 和状态文字在 390px 视口中换行，撤权后已打开详情关闭，刷新后不会恢复。

## 验证

- 实际 Identity 双用户、HTTP、SQLite、后台 worker：未邀请不可见；角色仅本人范围仍拒绝；角色允许跨归属后与参与范围取交集；私有会话／运行和管理操作拒绝；真实消息进入原执行用户的模型上下文，执行身份保持。
- 在原任务模型调用暂停期间排入参与者下一轮消息，再撤回发送者的沟通权限：旧消息被标记失效，记录的模型输入不包含该消息。撤回范围与重启后均不可继续读写。
- 存储：发送和名单调整幂等、真实发送角色、跨 Runtime／工作空间隔离、撤权后冻结输入失败、撤回再加入不恢复旧输入、只读参与者不能读写通信。
- 应用：来源不可读时仍能获得撤权保存回执；待接收消息按发送者原角色复核，未换成执行角色或默认角色。
- SaaS HTTP：实际操作者、参与名单、省略与空数组、授权版本、保存回执标志和当前拒绝结果保持；跨工作空间请求不能到达写入服务。业务 RPC 沿用既有类型化操作。
- 实际 Chrome 双会话：邀请只读参与人、隐藏私有入口、升级为沟通、发送与消费、真实署名、390px 换行、实时撤回及刷新保持。截图已人工查看。
- 应用、存储、HTTP Module、能力描述、remote、server、SDK 相关回归和参与链路 race 检查通过；前端类型检查与生产构建通过。具体命令、日志、截图和源文件摘要见[阶段证据](evidence/2026-09-14-c05-delegation-participants/commands.md)。

## 仍在 C05 的工作

当前参与范围仅覆盖查看约定与沟通。**不同执行主体用各自专业权限接单、执行和交付，以及参与者管理、执行阅读和交付阅读范围，仍需实现。** 当前参与者人工消息已验证；携带其他用户私有运行来源的 Agent 消息尚不构成完整的跨主体 Agent 通信交付链路。

通过 Agent 执行生成的约定和输入仍带原来源：参与者必须通过当前来源检查，否则拒绝详情读取。后续需要明确共享这类约定和输入的来源阅读契约，不能把添加参与者解释为开放原会话和私有附件。

本阶段没有发布。真实数据库验证使用 SQLite；Postgres／MySQL 只验证迁移渲染。Runtime 已发布模块锁与本地 SDK 增量的联合发布检查继续保留。
