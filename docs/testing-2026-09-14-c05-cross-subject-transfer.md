# C05：跨主体转交与原执行共享

委派现在可转交给配置所有者明确绑定角色的另一主体。接手人的当前接收权限、配置共享、角色、工具范围和容量分别核对；模型或 HTTP 参数不能指定执行身份。委派 ID 与发起归属保持，新任务和运行属于新执行人。逐次接手记录保存原任务的私有身份证明，公开历史新增执行用户／工作区元数据，不公开内部角色证明，不授予旧私有会话读取权。

交接采用准确原执行：发起人及新接手人阅读其他用户的运行时，需要原执行人明确发布该项委派的准确运行，并具有当前执行阅读范围。转交事务再次核对原接手、发布与参与人记录及委派版本，更新执行绑定，关闭旧收件箱中的待消费消息，保留原账本、已完成效果和累计预算。原执行人保留明确的查看参与范围时，可撤回本人旧发布；该操作不依赖继续拥有接手身份或正文读取权。

页面同时读取可读发布与本人发布元数据。新接手人能看到旧执行人已共享的运行；旧执行人能找到本人撤回入口。接单历史中的其他用户运行通过委派限定的执行阅读入口打开，没有旧私有会话链接。长 ID 在 390px 页面内换行。正文失效后的元数据页面仍提供本人发布的撤回入口。

验证使用实际 Identity 三账号、真实 HTTP／SQLite、两个独立绑定角色和实际 `time_now` 工具执行；模型为确定性夹具。覆盖发布前拒绝转交、接收授权撤回、转交和原请求重试、原／新私有运行隔离、逐次角色与累计预算、新执行人完成并手动交付、发起人验收与重启，以及旧共享撤回后的继承内容隐藏。另一个场景在新接手人的模型请求中撤回原发布，证明下一次工具调用和后续模型请求被阻止。存储测试覆盖原写入效果复用、原身份保持、错误用户／角色／工作区及未绑定身份拒绝。

六个完整 Agent Go 包、完整 SDK、相关 race、前端 78 项测试及构建通过。实际 Chrome 完成页面转交、发起人／接手人阅读旧共享执行、旧执行人撤回入口和 390px 边界检查；原三账号发布／撤回控件浏览器回归通过。六张转交截图逐张核对，浏览器无 page error。

本阶段转交仍由发起人管理；参与人的完整转交与依赖管理、多所有者依赖，以及更广的 Identity 停用／退出联动仍需继续完成。旧执行人的查看参与范围与新执行人的执行阅读范围在测试中由发起人明确授予，没有自动赋予旧私有历史访问。C05 保持待办，完整清单仍为 4／25。
