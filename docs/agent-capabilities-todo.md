**实施边界**

- 文档检索沿用已接入的 Verdent 知识服务，现有实现通过通用知识库 Connector 调用；继续使用该接入，不安排 WeKnora 部署或迁移。
- Conversation 负责持续会话，Interactive 保持单次业务路由，Task 保持后台业务任务语义。提取共同的执行机制，分别保留入口和状态边界。
- 用户待办保存业务事项；Agent Run 保存一次处理过程；计划任务保存何时触发处理。三类记录分别建模，通过引用关联。
- Agent SDK 管公共契约；Agent 管上下文、执行与状态；Connectors 管外部服务协议；Identity 管授权；宿主管凭证、数据库和网络访问。
- Web Agent 的前端负责输入、上传、预览、确认和下载；工具由服务端或已授权的外部服务执行。网页入口不要求工具在浏览器进程执行。
- 用户本地资料以用户选择上传或已授权的数据源为入口；文档解析和索引继续归知识服务。成果编辑针对本产品保存的产物版本；用户电脑上的原文件和本地应用需要额外访问机制。
- 独立网页宿主目前只装配 Identity 和 Agent，业务数据、Workflow、报表等工具须在对应宿主能力接好后才公布；未挂载能力时不能接受执行或伪造结果。

**默认开放规则**

**文件类能力在 Web Agent 中的实际场景**

- “帮我找合同中的付款条件”：用户选择上传合同或选择已授权资料 → 知识服务解析并提供索引状态 → `knowledge_search` / `knowledge_read` 获取有来源的内容 → 回复并展示引用。网页无需取得用户电脑的任意文件路径。
