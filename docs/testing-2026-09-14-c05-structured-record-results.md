# C05：产品结构化记录原结果阅读

接续[查询排除范围与原游标交付](testing-2026-09-14-c05-query-exclusions-cursor.md)。本阶段接入产品装配使用的 Tools RecordAdapter 独立结果阅读策略，并补同用户原角色共享执行的读取范围。完整 C05 尚未验收，整表保持 **4／25**。

原适配器只注册执行／恢复回调，读取保存的 save 回执仍要求写入授权。反例先复现 `tool.result_read_unsupported`。现在 list／read／save 注册 `AuthorizeResultRead`：读取准确不可变版本，save 另核对原幂等请求的只读保存账本。读取仅要求当前 read／list 权限，不调用 Invoke、Reconcile、Save 或产品写入校验，也不重新列出当前列表来替代历史页。保持原查询、顺序、游标、完成标记、版本、时间和 JSON 大整数。

记录继续按部署／工作区／用户隔离。同用户的原执行角色与当前阅读角色分别复核；不同用户的发布引用不能改写个人记录归属。每次源读取和保存账本 IO 后再次核对当前阅读权，缺失或变化的原记录／账本、不同归属、变更定义、未知字段和错误页边界拒绝。单元检查覆盖账本 IO 期间撤回读者，以及历史完整／未完整／空页，确认没有额外写入或重新列举。

实际产品场景使用 ConfigureRecords／OpenProduct、真实 Identity Cookie 网关、Tools 注册及组合宿主、Knowledge Record Repository 和 SQLite。先通过注册的 SDK 工具建立原版本并更新当前版本；旧 read 和 list 仍核对原版本，错误保存账本键拒绝。这两次保存是来源夹具，不计作 Agent 用户确认。

随后由实际独立 Agent 发起工具委派；接收 Agent 真正执行一次保存、读取该版本、查询原列表、获取约定并自动交付三份原回执。用户经实际 HTTP 交互批准操作并验收准确交付。接收运行保持六步，实际保存效果一次；连同前面的两次来源夹具保存，产品校验总数始终为三。任务预算保持 12 步／12 次调用／8192 字节／60 秒。

实际执行用户通过 HTTP 明确发布这次原运行；交付本身不会隐式发布完整执行。本场景不计作新增四个 Agent 共享工具的模型调用验收。当前交付、准确原 deliver 历史版本和显式共享执行三个入口，分别在首次读取、撤回写入权后和重启后逐页核对原引用、字节位置及 SHA，共 27 次核对。撤回资料读取权时三个入口均拒绝；恢复 read／list 后原版本可读，重启不会恢复 save 权限。共享执行也保持六步，不携带操作确认或写入范围。

共享执行反例发现：再次核对同用户／同角色原根时，`sourceReleaseContext` 清掉了之前已经验证的准确执行读取范围，回退到旧执行授权。修复只保留已存在且与同一委派匹配的 execution 阅读范围；原始协作回执、其他委派、约定／消息及尚未发布的执行不能借此生成读取范围。对应正例和五项权限边界反例保留。

重启后实际登录第二个 Identity 账号，使用真实管理员角色编写端口给它 read／list 权限并撤回 save。它能查询自己的空列表，但不能读取第一账号的个人记录，四类保存原结果（含空列表）按原提供者归属拒绝。产品还通过 ORM 核对唯一宿主 `_schema_migrations` 账本，没有另建模块迁移账本。

最终源码的正常实际产品根通过，9.50 秒；完整实际产品 race 根通过，158.63 秒，另完成相同 27 次原 SHA 核对。Tools 全量及相关 race、Agent Application 完整 race 通过。原 race 的夹具把发起委派和接收执行放进同一个 60 秒观察窗口，交付调用完成时提前结束观察；失败保留。拆开观察窗口后完整通过，实际任务预算未变。发布夹具最初未从真实 Identity 解析选定角色，以及账号验收采用旧委派版本的失败也保留。

宽范围回归还发现一条成果来源测试模型缺少已有大小计量端口，将内部授权快照算作模型协议正文而触发上下文上限。该 chat_completions 夹具现复用生产协议编码器计量；完整工具、消息及内部证明保留，生产上下文上限和执行预算未改。准确成果生成步骤／后续私有来源边界场景已通过。

Agent 的递归 `go test ./...` 同时将七个历史证据快照目录当作 Go 包，其中独立源码片段出现编译／混包错误；该命令不计通过。归档时按实际进程记录运行或终态，保留所有历史证据。已列出全部 36 个可执行代码包及后续全量回归脚本，后续状态以[本阶段证据](evidence/2026-09-14-c05-structured-record-results/acceptance.json)为准；没有把一个场景通过记作完整 Agent 包验收。
