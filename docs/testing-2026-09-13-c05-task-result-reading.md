# C05：任务原回执与私有来源读取

日期：2026-09-13。接续[个人工具原回执](testing-2026-09-13-c05-personal-result-reading.md)，本阶段覆盖 `task_start`、`task_get`、`task_list`、`task_cancel`、`task_resume`。C05 仍有历史／执行记录的独立来源策略以及跨用户／角色执行主体待完成，整体仍为 **4／25**。

## 行为与边界

任务工具的原结果进入交付时，先按当前 `delivery_read`、工具启用状态和实际用户拥有的原执行账本核对完整调用、定义、结果与幂等键。这个核对与十一类个人工具共用内部实现，不增加公开端口或执行能力。缺少原账本读取端口时保留普通授权路径。

`task_start` 只读取原受理回执，检查原任务 ID、来源会话／运行、创建时间、工具范围和预算。原来的 `accepted` 不改为完成；查询、取消和恢复回执保留当时的任务状态、进度、控制项和预览，读取不会触发状态转换。

任务详情可能包含原输入、等待问题、执行预览和成果信息，不能只凭交付权公开。所有五种结果都重新读取真实用户范围内的当前任务，核对原资源身份，并按任务及来源会话的当前 `execution_read` 权限验证。即使来自同一委派，原始任务详情也不使用较窄的“交付来源核对”权限例外。非委派任务沿用现有用户拥有范围，不额外发明控制授权。

原来源运行按保存的调用位置核对，避免读取任务回执时递归进入自身；执行运行必须真实归属该任务。结果预览核对原 assistant 消息、后台任务 ID、字节数和截断内容。成果引用通过 Knowledge 的当前 `artifact_read` 授权、工具启用状态、准确版本和完整来源核对，原版本元数据变化或来源不可验证时隐藏。私有附件不因嵌入任务预览或成果而共享。全部读取有超时和取消边界。

上述嵌套来源检查也接入普通结果读取及恢复时的已完成调用重放：有任务控制权并不自动证明内嵌资料仍可读。没有修改后台任务创建、取消、恢复的执行逻辑、工作队列、公开 SDK、数据库迁移或生产前端。

## 验证

- 五种任务工具的应用测试：独立读取与控制权分离、同委派私有执行读取、缺失／其他用户任务、错误执行归属、原调用篡改、原答复变化、私有附件、成果读取撤权／停用／元数据变更／遗漏来源、取消和恢复阅读。
- 真实 Agent／Identity／SQLite／HTTP／worker 场景：创建并实际运行后台任务，查询列表和详情，取消后恢复一次并完成；另外创建一个独立委派，读取它的真实私有任务详情。六份原回执作为明确交付依据保存。撤回所有个人工具执行权限、保留协作阅读权限后，当前与历史交付仍逐字等于原结果；撤回 `execution_read` 后，交付及准确结果入口拒绝包含私有委派任务内容的回执。恢复权限并重启宿主后原任务运行及完成事件不变。
- 已有后台任务启动／恢复／SQLite 场景、计划任务当前身份及真实确认场景、十一类个人工具交付 HTTP 场景回归通过。

应用包全量与对应任务 HTTP／应用竞态检查通过。具体命令、结果和源码摘要见[证据](evidence/2026-09-13-c05-task-result-reading/commands.md)。本阶段没有新增浏览器视觉验收或发布声明。历史／执行记录工具还需独立来源策略；跨用户参与者模型和前阶段的 Runtime 发布模块锁差异仍保留。
