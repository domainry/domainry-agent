# E05 跨 Agent 预算与进度诊断验收

日期：2026-09-15。本轮把 C07 已有的同一工作根预算扩展为可核对的整体账本和稳定委派分配，并把模型执行活动与有证据的业务进度分开。E05 验收完成后，完整清单进度为 **11／25**。

## 预算、分配与实际计量

- [Agent SDK 任务契约](../../domainry-agent-sdk/conversation_task.go)公开整体预算、总用量、当前委派分配、模型／工具调用数、token、模型耗时、费用及费用是否可确定。旧 `ConversationWorkBudgetRepository` 保持兼容；新的计量端口作为可选扩展，旧宿主不会因接口扩展失效。
- [共享预算账本](../internal/infrastructure/persistence/database/agent/conversation_work_budget_store.go)以根会话聚合，以稳定委派 ID 分配。每次模型请求先在工作区序列化边界内预留输入、输出、耗时和可选费用上限；提供者实际开始后才计一次模型调用，完成后按实际 token、耗时、工具调用和冻结价格结算。并发 Agent 不能超额预留。
- 提供者已开始后发生取消、失败或租约失效时，账本保留有上限的实际模型耗时，并将无法证明的费用标记为未知。缺失／非法 token、未配置价格或混合币种不会伪造精确成本；存在费用上限而历史费用未知时，后续调用保持阻止状态。
- 工具重复诊断使用工具名与规范化参数的摘要，不保存参数明文。转委派沿用原稳定委派分配及根账本，累计调用、token、耗时、费用和重复指纹不会清零。

## 业务进度与恢复动作

- [任务投影](../internal/application/conversation_tasks.go)从当前约定、程序核对结果、持久运行尝试、计划证据／成果、依赖 revision、共享预算和工具调用指纹生成诊断。已完成步骤只有带证据或成果引用才计入阶段成果；模型自行写出的步骤结果不直接变成业务进度。
- 正在等待输入或确认时建议等待；依赖变化、计划阻塞或明确 Goal 阻塞时报告具体阻塞；出现重复调用、三次以上约定修订，或三次以上尝试仍没有核实事项和阶段成果时建议调整策略。诊断依据、计数和原因通过任务查询返回，不把执行步数换算为完成百分比。
- 委派运行结束、提交交付和验收通过继续是不同状态。接收方任务在 `awaiting_delivery`、`delivered` 或 `needs_changes` 时保持业务阻塞；只有当前交付被接受后，任务才显示业务完成。

## Agent 选择历史

- [Agent 目录历史](../internal/application/conversation_agent_discovery.go)只采用 Agent ID、配置摘要、配置 revision、模型身份和任务类型完全匹配的样本。终态模型运行与已接受交付分别计量；协调耗时从委派创建到最近一次明确接受或要求修改。
- 接受率和协调耗时只有在至少三份已复核交付后才参与候选排序。样本不足时页面明确显示不确定性；成本估计继续声明依据，并排除工具收费、重试、未来修订和其他 Agent 工作。

## 页面与验收场景

- [任务诊断组件](../frontend/src/TaskDiagnostics.tsx)在任务和委派详情中把“执行活动”与“业务进度”分区，另行显示本项委派累计、整个工作累计和整个工作上限。桌面和 390 px 页面均显示实际模型／工具调用、token、模型耗时、费用、核实项、阶段成果、剩余依赖和建议动作。
