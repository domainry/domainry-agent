# C05：执行发布者撤回入口与运行中读取

接续[执行共享工具](testing-2026-09-14-c05-execution-tools.md)。执行人撤回已有共享不再依赖重新读取执行内容。C05 尚未完整验收，完整清单保持 4／25。

新增 `GET /agent/delegations/{delegationID}/execution-publications`，返回当前用户本人发布的准确运行引用与原发布身份。接口只需要当前委派 `view`，不读取旧运行正文、不要求 `execution_read` 或 `share`。其他参与人使用既有 `/executions` 读取获授权共享；即使持有共享执行范围，也不能从发布者入口取得其他人的撤回引用。SDK 使用独立可选服务／存储端口，Module 与 SaaS 保留实际请求身份。

页面分别处理查看内容与撤回发布。执行人仍有委派查看权时，保留本人发布列表、说明与撤回按钮；失去执行阅读权时隐藏查看与重新发布入口。失去共享权仍可撤回已有发布。失去委派查看权后入口关闭，恢复权限不会制造新发布。撤回沿用原明确说明、委派版本和持久幂等机制。

验证已完成：

- Agent 应用、存储、远端、Module、能力绑定及 SaaS 六个完整 Go 包通过；SDK 完整包通过；前端构建及 77 个现有测试通过。
- 新增应用检查证明只需 `view`；错误委派、用途、原提供者、发布者、工作区、Runtime、前缀和空引用均拒绝，错误证明混入正常证明时不返回部分元数据。
- 存储检查覆盖其他参与人隔离、后续角色读取、存储重新打开、原提供／发布角色保持和跨工作区拒绝；应用与存储两个相关 race 根场景通过。
- 真实三账号来源 HTTP 根场景与 Chrome 验证通过：撤回执行阅读权保留本人撤回入口，仍可撤回并关闭第三账号打开的运行详情；撤回共享权后仍可撤回已有发布；撤回委派查看权关闭入口；明确恢复与重新发布；桌面和 390 像素窄屏布局。两张截图已逐张查看，显示实际撤回区域。
- 真实跨用户执行 HTTP 根场景通过：实际 worker 停在第一轮模型请求时，执行人明确发布准确运行；发起人读到 `running` 状态、原运行 ID 和第零步骤，不能使用私有运行入口或取得确认／写入控制；在 worker 继续前撤回后，原共享读取立即拒绝。后续原接收角色执行、沟通、交付及撤权场景继续通过。

浏览器权限变更入口仅装配在测试服务器；生产没有增加该入口。模型为确定性夹具，Identity、HTTP、数据库与工具调用为真实链路；未调用外部模型服务。本阶段未改变未完成／失败工具载荷的保守隐藏策略，也未修改 Tools Registry。其余 C05 来源、管理与主体退出范围继续按 TODO 推进。
