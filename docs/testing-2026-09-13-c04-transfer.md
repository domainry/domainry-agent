# C04 增量：平权 Agent 转交与原效果复用

日期：2026-09-13。本批实现委派转交，C04 仍有完成条件核对和结构化分歧处理待办，整张清单保持 3／25。

用户或发起方 Agent 可对已经停止的工作选择另一位接收方，填写剩余工作及原因。委派 ID 保持不变，新接收方得到独立的 Task、会话及冻结配置；约定版本递增，旧交付移入接手历史。数据库第 22 次迁移增加接手记录表，每条记录含责任 Agent、配置版本、任务／会话、约定版本、来源、原因及时间；更新相同历史键但内容不同会被拒绝。升级前没有接手记录的委派从最初约定恢复来源，缺失来源保留为空，不把后续要求的出处冒充初次接单出处。

服务从实际账本构建交接内容，调用方只能提交目标 Agent 和剩余工作，不能伪造原效果。原任务及历史运行必须已经终止，所有已发起的写入必须得到确定回执；未知结果继续使用独立只读核查入口。当前权限、接收方能力／配置、数据来源和依赖版本检查通过后，在同一事务中保存新接单、历史及幂等回执。转交过程中要求发生变化会拒绝过时请求；同一请求重投不会产生另一份任务。旧 worker、旧恢复入口及历史任务控制不能重新成为当前执行方。

累计步骤和工具调用预算覆盖所有历史接单会话，新任务只获得剩余额度。接收方再次提出与原成功调用同名、同参数的写操作时，服务核对原冻结工具定义与原结果摘要，并返回原回执，不再次调用 Invoke、Reconcile 或发起业务操作确认。参数比较忽略 JSON 空白和对象键顺序；不会把不同参数的操作合并。工具定义变更会明确阻止复用，不以新定义重新提交相同效果。再次转交时保留最初实际效果，复用副本不会重复计入实际效果清单。

复用事件单独保存在审计中，逻辑调用占用本次调用预算，实际工具尝试数为零。页面可查看当前接收方、每次接单与转交、剩余工作、旧交付、原执行和原回执。刷新与重启仍能恢复相同记录。转交原因的来源与原 Brief 的来源分别保存；交接、模型下一步、历史和工具结果读取都会重新核对来源权限，私有附件不能因转交自动进入新会话。

截图复核还发现并修复一处原回执保存问题：JSON 再次解码到已有结构体会保留被新快照省略的旧错误码。工具记录读取现按完整快照替换；核查与转交测试比对整份确定回执，浏览器断言成功复用时不再出现旧“结果未知”提示。页面也区分“新操作需确认”的策略与本次只复用回执的实际行为。

本次仍有明确边界：当前接收方还有未关闭的对外委派时，转交返回具体阻塞，防止后续通知失去负责人；在 C07 完成后续责任迁移策略。累计时间、输出／token／费用预算仍归 C07／E05，本批累计的是步骤和调用数。单项委派最多 16 次接单、交接最多 128 个历史运行，并受输入上下文大小约束，超限明确拒绝。缺少只读核查端口的工具保持未知结果阻塞。本记录不声称自然模型效果或真实第三方生产服务已验收。
