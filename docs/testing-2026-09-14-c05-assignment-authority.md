# C05：逐次接手的原执行身份

接手记录现在在存储内部保留准确原执行身份，包括原角色。公开 SDK／HTTP 接手历史仍使用原 DTO，不输出内部身份字段，也不授予原私有任务或运行读取权。新记录从实际任务取得身份；旧记录在首次转交事务中补充已核实的身份，原接手双方、会话、任务、时间和交付等公开事实保持。

累计步骤／调用预算、交接运行与已完成效果、原效果复用，以及旧约定要求恢复，改为逐次接手查询原执行主体。每条身份记录与准确任务、委派、接手会话、Agent 及冻结版本核对；错误角色、工作区和任务拒绝。后续阅读角色不能替换原角色。

验证覆盖两个实际主体的工具写入与完成、原效果和预算保持、私有运行读取仍拒绝、存储重新装配、旧记录补全后在另一角色下真实转交、公开历史保持、错误身份拒绝及原三次接手／效果复用回归。六个完整 Agent Go 包及相关 race 通过，真实 Identity／HTTP 主体执行、删除和重启回归通过。

这是跨主体转交所需的持久化基础。本阶段尚未移除跨主体转交拒绝，也未完成接手人的独立授权、原执行明确发布与转交事务绑定更新。C05 保持待办，完整清单仍为 4／25。
