# C05：前缀与非空阅读范围

接续[查询排除范围与原游标交付](testing-2026-09-14-c05-query-exclusions-cursor.md)。完整 C05 继续待办，整表保持 **4／25**。

当前 Identity SDK 的授权谓词支持 prefix／exists；大小比较属于 Runtime 的业务查询过滤，不属于该 SDK 授权谓词。新增证明只处理 SDK 已校验和翻译的谓词，不增加授权算子或单独解释业务数值范围。

原范围覆盖判断只识别相同绑定 SQL、有限集合及 AND／OR／否定的结构关系，无法证明 `name prefix Scope` 覆盖 `name prefix Scope:`，也无法证明 `name exists true` 覆盖原前缀／不等／排除查询策略。新增六组真实 ORM 反例在补丁前全部被拒绝，失败日志保留。

现在前缀按 SDK 绑定后的实际字符串比较，只有字面前缀扩展可以获得覆盖关系。百分号、下划线和反斜杠保持 SDK 的字面转义；不做大小写／排序规则归一化。NUL 和非法 UTF-8 不能通过新的前缀推导获得授权。不同实际 Subject、缺少当前业务 claim、不同 fact 和未支持算子不扩大范围。

exists 的证明遵循实际 SQL 条件：等值、不等、IN、NOT IN、LIKE 均不能匹配 NULL fact，所以非空读取策略可覆盖同一 fact 上的这些原策略。NOT IS NULL 与 IS NOT NULL 同义；NULL 和非空范围仍分开。该证明不把保存 JSON 中“字段存在但值为 null”当作 SQL 非空。读者 deny 的方向继续反向证明，新增测试检查更小／更大的前缀 deny。

六组 SDK 身份夹具使用不同原提供者与读者，调用真实 Runtime RecordApplicationService／RecordStore／SQLite：普通前缀、字面通配符、字面反斜杠、非空覆盖前缀／NOT IN／不等。每组加入 NULL 名称记录，原策略实际只选中两条非空记录；核对第一页面的 total=2 和原游标第二页。更宽读者可读取两份原回执；读者收窄后仍可读取首行，但两份旧分页回执都拒绝；恢复范围后重新允许。读取不改写原证据，读者不能拿原提供者游标执行新查询。

完整授权宿主正常／race 已通过。实际跨账号 Agent 根复用复杂筛选与原游标场景，核对当前源码下的真实 Cookie／Identity／RPC、工具委派、自动交付、账号验收、原工具执行权限撤回、重启及资料权限恢复；根场景 133.59 秒、包检查 134.474 秒，四轮共 20 次原 SHA。它是完整原链路回归；新增 prefix／exists 具体覆盖分支的证据来自上述实际 ORM 用例，不将该根的原身份策略声称为真实配置的前缀授权角色。最终状态与具体编译源码见[阶段归档](evidence/2026-09-14-c05-prefix-existence-scope/acceptance.json)。实际 Agent 根编译后，单元夹具把缺少业务 claim 的引用修正为 SDK 实际识别的 `$context.unknown`；最终完整 owner 正常／race 编译该修正，生产源码相同，两个具体版本分别记录。
