# C05：参与人管理范围与原任务归属

日期：2026-09-14。接续[参与人授权身份与准确约定来源](testing-2026-09-14-c05-participant-publication.md)。本阶段继续实现 C05，新增参与人 `manage` 范围，完整 C05 仍待完成，整表仍为 **4／25**。

参与人管理仍需实际授权人的当前共享权、操作人的当前 Identity 查看／管理权和这条委派的明确范围。存储保存前也核对当前名单和版本，当前名单已撤回管理范围时拒绝修改及原修改请求的重放。只有原执行方可以提交交付或拒绝接单；管理范围不变成接单／交付权。交付核对另需交付阅读范围。

新增内部记录读取用于已授权管理：操作人始终是当前登录用户或调用 Agent 的真实身份，原发起／执行身份只用于准确记录和任务的内部存储路由。暂停、取消和恢复沿用原任务、原执行会话和原角色。应用向参与管理者返回 `management_only` 写入回执，只含保存的委派 ID、状态、版本、决定及时间；实时内容另按当前权限读取，回执不包含私有会话、任务、约定正文、交付或参与人名单。

原接收方也可以被明确授予管理范围。额外范围与原接单责任取并集后再与当前 Identity 权限取交集；实际授权人撤权时移除额外范围，保留独立的原接单责任。管理用户不会成为原任务执行用户，管理角色不会替换已冻结执行角色。

需求变更现在从原工作目标的记录归属查依赖任务，按原执行身份停止受影响工作，并通过事务内已读取的准确记录发送通知；通知路由不借用操作人的私人记录。应用／存储场景覆盖参与人修改声明目标后原所有者的依赖任务进入待更新、原任务停止，以及参与人仍不能打开该依赖委派。

Agent／SDK 八个包及两个包的相关 race 场景通过。真实 Runtime 的旧约定恢复／更新／重启／恢复执行／再次交付／验收完整流程通过，用时 **67.41 秒**，原执行预算保持。真实双账号 HTTP 覆盖当前角色管理权撤回、明确范围、暂停／恢复、准确版本冲突、窄回执及缩小范围后旧修改请求拒绝。准确修复前生产文件保存在 `source-before/testdata`，当前完整夹具配合 Go overlay 重现管理读取／回执和接收方额外范围缺口，以及依赖更新和通知归属缺口；初期语法错误、夹具遗漏发起会话、旧生产流程兼容性失败分别保留为诊断。
