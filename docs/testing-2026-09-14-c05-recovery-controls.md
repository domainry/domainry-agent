# C05：资料失权时的委派管理入口

日期：2026-09-14。接续[对象投影与原角色交付发布](testing-2026-09-14-c05-record-policy-projection.md)。本阶段补页面行为，原接单／执行身份、发布证据、当前 Identity 授权及服务端 CAS 继续使用现有实现。

原页面在 `contract_omitted` 时提前返回，只留下原约定恢复入口。现在获准查看且具有当前管理权的发起方，可以按实际状态暂停或取消该委派。资料不可读时只保留允许停止的操作；继续执行、更新要求／输入、依赖调整、转交及交付评估仍不显示。暂停、取消提交使用列表中的准确委派版本和用户填写的原因，服务端继续核对当前权限及真实归属。

资料隐藏后不显示空约定中的“需求 v0”。可读与不可读状态切换时重新初始化详情组件，清掉旧输入／要求／管理表单。实际浏览器测试还发现停止按钮会调用交付核对初始化，隐藏约定的空完成条件导致三次 `null.map` 错误；现在不可读约定直接返回空评估，不从缺失约定初始化评估内容。

两个回归场景在准确修复前的状态模块上失败，复现不合适的操作范围及空约定评估异常；当前前端 77 项及构建通过。真实 SQLite、Identity 当前角色编辑、HTTP 和 Chrome 完整场景通过，用时 **25.02 秒**，浏览器错误为零。验证资料隐藏、可读表单清理、准确版本暂停、旧版本拒绝、资料恢复、管理撤权关闭表单、撤权后提交拒绝且版本不变、恢复权限清空表单、资料不可读时取消及桌面／窄屏无横向溢出；截图已检查。准确结果见[证据](evidence/2026-09-14-c05-recovery-controls/acceptance.json)。测试的约定明确引用原工具委派接单回执；它包含原任务详情，撤回当前执行阅读权会使该资料不可读，同时保留当前委派查看／管理权。随后单独撤回管理权，验证修改被拒绝；修改角色权限不要求重新登录。
