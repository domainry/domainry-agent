# C05：Agent 原生执行共享工具

本阶段接续[明确执行共享](testing-2026-09-14-c05-execution-sharing.md)，补齐 Agent 调用入口。C05 仍未完成，完整清单继续为 4／25。

新增 `delegation_execution_publish`、`delegation_executions`、`delegation_execution_read`、`delegation_execution_result_read` 四项版本化工具。发布使用当前委派版本、具体说明和准确原运行引用，幂等键由服务端根据原工具调用分配；模型参数不包含内部 ToolRequest、执行用户、角色或 client_id。发布／撤回复用现有确认机制，事务在重放与保存前核对原调用、批准／写入范围及当前 worker 租约，已停止的调用不能改变共享。只读工具不请求额外写入确认。

工具调用现有委派服务和来源发布表，具体实现由 Agent 拥有。`ConversationToolDefinition`、`ConversationToolCall` 等沿用 Tools SDK 类型和 Schema 契约；四项工具通过现有 collaborationToolHost 接入，不是 Tools Registry 中新增的通用业务适配器。Tools README 已明确历史、记忆和执行查看属于 Agent 原生能力。通用邮件、日历、网页、报表等工具仍由 Tools 消费各自中立业务契约；本阶段没有修改 Tools 实现。默认会话可发现获当前工具权限允许的四项工具，显式 Agent 的工具白名单仍需包含实际所用项。

共享运行回执保留准确委派 ID、原步骤、已验证调用参数／结果、回复与用量，去除交互确认与写入控制。结果分页保留原结果引用和准确字节。已保存工具输出在再次进入模型、历史或交付时走专门的来源遍历，重新检查准确发布、当前授权人、原发布／提供角色及所有资料范围；包装回执不能把通信等原始来源变成较窄的约定或交付授权。

嵌套读取共用当前遍历的循环检查。运行向前推进时，允许保留旧的准确已完成调用与文本前缀，不把旧观测替换为新运行；未验证调用保留公开状态，载荷采用白名单。结果回执核对原页的边界与原字节，当前模型上下文预算缩小时不会重切历史页。正在执行的运行不能读取自身完整过程；原结果读取只核对到准确调用前缀。

验证已完成：

- Agent 应用、存储、远端、Module、能力绑定、SaaS 六个完整 Go 包及 SDK 完整包通过。
- 三个真实 HTTP 根场景通过；来源根通过模型调用验证真实三账号发布确认、执行索引、五步完整过程、准确结果页、当前通信撤权后旧回执隐藏、未发布运行拒绝，以及实际执行人确认撤回和重新发布。
- 应用夹具证明旧运行向前推进时可保留准确观测，伪造参数／结果／回复／运行与控制信息拒绝；较小上下文实际改变新分页，但原页仍可核对；无环包装先可读，加入两运行循环后由引用检查拒绝。
- 存储夹具证明已停止 Agent 调用不能发布或撤回，当前委派版本与发布证明保持；相关 race 共十个根场景通过。
- 真实 Runtime 跨用户和同用户不同角色专业场景通过，保留七步原运行、四份报表／分析结果的 4–7 页完整字节及原 SHA-256、重启和当前字段／行／原提供角色撤权核对。

模型采用确定性夹具；Identity、HTTP、工具、数据库及 Runtime 为真实链路，未调用外部模型服务。本阶段没有前端改动，没有将上一阶段浏览器结果记为本阶段新增验证。首次失败是夹具包含服务端 client_id、分页请求超过既有 8192 字节上限，以及存储夹具函数名错误；失败日志保留，不计通过。

证据：[接受记录](evidence/2026-09-14-c05-execution-tools/acceptance.json)。运行中真实 HTTP、未完成／失败调用参数的独立策略、其余跨主体来源、多所有者混合来源、完整参与人依赖／转交管理、退出生命周期及失去执行阅读权后的发布者撤回页面继续待办。
