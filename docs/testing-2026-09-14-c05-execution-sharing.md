# C05：明确共享执行与参与人阅读

日期：2026-09-14。接续[参与人的独立交付阅读](testing-2026-09-14-c05-participant-delivery-reading.md)。参与名单现支持查看、沟通、管理、交付阅读和执行查看五项范围。整表仍为 **4／25**，C05 未完成。

实际执行用户可以明确共享一项委派的准确运行，也可以撤回。保存事务从原运行和任务／接单记录复核归属，不能由发起人、参与人或客户端选择另一用户的私有运行。原提供角色与实际发布角色分别保留；晚加入的参与人只能转发发起人已经持有的准确执行发布，不能把授予名单解释为另一角色重新发布。共享过程沿用 ORM 来源发布表、原委派版本和幂等审计，没有新增迁移账本。

SDK、Module／HTTP 和 SaaS 增加四项端口：发布／撤回、已共享运行索引、准确运行读取和原结果分页。每次阅读重新核对当前执行查看范围、实际名单授权人和原发布／提供角色的当前共享权。普通会话和任务控制入口仍按原归属核对；运行读取不附带交互确认或写入范围。撤回可在执行阅读权失效后进行，不依赖重新读取旧业务资料；旧发布请求只重放原回执，不能恢复已经撤回的来源。

页面独立提供“查看执行”，执行人填写说明后共享或撤回运行。参与人复用处理记录查看已经验证的工具参数／结果、回复、错误和用量；共享窗口通过按委派读取定期更新，不订阅别人的私有会话流。名单、来源共享或当前角色失效时清除旧窗口；并发变更用旧版本保存名单会拒绝，刷新后才能按当前版本修改。

来源权限依然独立。真实时钟运行引用了原始消息与历史交付：只有执行查看时拒绝，补沟通后仍因历史交付范围不足而拒绝，全部所需来源权限满足后才提供过程。执行查看不会自动提供专业工具执行或管理权。尚无可验证成功回执的调用只显示状态与耗时，隐藏参数、失败载荷和相关模型回复；失败原回执的独立分页同样拒绝。这一分支有完整出站 JSON 的敏感值／伪造结果引用回归； pending／failed 参数的独立阅读策略继续待办。

验证范围：

- 应用、存储、远端、Module、能力绑定和 SaaS 六个完整 Go 包通过；SDK 完整包通过；相关 race 通过。
- 前端 77 项、类型检查与构建通过。Chrome 八项实际三账号流程覆盖运行参数／结果、只读检查、执行人撤回与重新共享、名单撤回与恢复、保留独立沟通／交付范围及 390 像素弹窗边界，无页面异常；桌面和窄屏截图均检查。
- 三个真实 HTTP 根场景通过，来源根新增第三账号执行阅读、准确结果、私有控制拒绝、缺少原通信／历史交付授权、发布者共享撤回、读者当前角色撤回、名单撤回，以及执行人失去当前执行阅读权后仍能撤回发布。
- 存储覆盖运行中共享后账本继续推进，准确运行及实际发布者保持；重启准确证明、晚加入／已有读者、原运行归属、撤回仅删除执行发布及旧发布请求不能重新授予。
- 真实 Runtime 两项专业场景通过：跨用户和同用户不同角色，在读者没有专业查询执行权时查看七步原运行；四份报表／分析原结果分别为 847、1109、933、1550 字节，以 256 字节请求实际经过 4、5、4、7 页并核对原始 SHA-256；重启后重复完整阅读，字段／行范围撤回以及原提供角色失效后拒绝。

模型使用夹具；Identity、Runtime、HTTP、工具、数据库和 Chrome 使用真实链路，没有调用外部模型服务。普通私有运行投影会受当前角色和读取时点影响，专业场景的完整过程依据固定模型七步序列及四份原结果 SHA-256，不把私有投影的步骤数量当成完整过程证明。

同一最终存储夹具配合修复前名单保存源码，明确失败于晚加入读者缺少执行发布。首次 HTTP 能力分类失败、来源范围不足、SaaS／SDK 路由统计未更新、浏览器旧版本保存拒绝及专业夹具错误使用私有投影长度的失败日志均保留，不计为接受结果。诊断追踪通过临时 Go overlay 运行，生产源码不含追踪输出。
