# K07 附件网页索引与同一次任务核对

2026-09-11。附件页面已提供显式索引、当前处理状态和丢失响应后的核对入口。文件上传仍只保存私有原件；用户确认后才将原件交给 Connector。Agent 不恢复源文件解析。

本批功能和分段网页验收完成，**K07 整项继续不勾选**：尚缺附件专用 KB 的真实 Verdent 验收及无法确认的上传结果核查。当前本地服务配置没有 `AGENT_ATTACHMENT_KNOWLEDGE_BINDINGS`，已询问专用 KB ID 或配置文件路径，未借用个人／共享资料库。后续已核实上游删除支持幂等，并完成[删除恢复与真实回执验收](testing-2026-09-11-knowledge-delete-recovery.md)；下面的网页报告保留本批当时的证据范围。

## 实现与边界

- 公共 SDK 增加可选 `ConversationAttachmentIndexCheckService` 和持久层 `ConversationAttachmentIndexCheckRepository`。Module、SaaS、remote 客户端通过同一操作分发，应用层只调用公开端口，不直接导入数据库、HTTP Provider 或其他服务实现。
- `POST /agent/conversations/{conversationID}/attachments/{attachmentID}/index/check?expected_revision=N` 核对已有任务。请求只接受一个正整数版本参数，拒绝正文及用户、ACL、远端来源等额外字段。它要求当前 Identity 的 `agent.conversations.attachments_check_index` 权限，同时复核原索引／原件读取权限；清理任务复核删除权限。
- 核对在 ORM 事务内保存 `last_check_revision`，唤醒已有任务，保留不可变来源、远端文档编号、写入标记与单调租约。活动租约保持当前身份和到期时间；租约空闲时可更新当前认证角色。不会新建远端文档、清空不确定结果或抢占正在发送的写入。最近一次核对可按原版本恢复响应；更旧回执可通过当前元数据核实，再按当前版本发起核对。
- 元数据详情和变更响应带 `indexing`：是否已申请、是否可启动／核对、当前来源大小上限、不可操作原因和最近一次核对版本。这些信息每次由宿主重新计算，不作为持久 ACL 授权。列表只保留摘要；网页不会自行按角色名推算权限或选择远端 KB。
- 前端区分“用于当前会话检索”的确认、“核对索引状态”及“核对上次请求”。本地只保存带账号范围、会话、附件、哈希、版本的重试信息，不存原文件或密钥。一次索引／核对／恢复分别只有一个对应 API 请求，用返回的附件更新列表与详情，不在成功回调额外刷新接口；后续状态轮询独立进行。
- 原件仍可独立预览和下载。列表更新遵守当前游标窗口，删除边界记录时不丢失下一页游标。索引与另存资料库面板使用各自的 React key，避免重绘使重试状态丢失。
- 已就绪文件的核对仍按 `INDEXED` 完成并停放任务，不退回索引中。已发出的不确定上传只观察同一远端文档；正向索引状态可证明文件存在。单独的“查不到”不证明删除成功，核对也不会盲目重发删除。

没有新增数据库迁移：核对版本保存在既有附件 JSON，沿用第 14 个迁移的任务和来源登记。
