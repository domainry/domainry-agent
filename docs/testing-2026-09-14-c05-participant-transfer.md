# C05：受权参与人转交

具有明确管理范围的参与人现在可以转交已结束的委派。应用继续核对当前管理角色和名单发布者，存储在准备交接、读取原请求回执及转交事务中重新检查该项范围。实际操作人和新执行人分别保留；不能借委派管理范围控制发起人的私有会话。新 Agent 的配置可见性、实际绑定角色、接收权和工具范围仍按真实主体核对。

原约定资料通过既有准确发布阅读。参与人转交不能代替发起人重新发布私有来源；新接手人必须能读原发布，事务再次核对其准确发布记录。原发布者、原始身份、字节和记录保持；管理人的本次模型来源单独按本人来源检查与发布。接单历史及约定变更记录保存实际管理人，独立接手会话按接收身份创建，原账本、已完成效果和累计预算保持。管理响应与重试均只返回窄管理回执。

页面从委派已结束状态展示转交入口，受权管理人无需取得私有任务详情。运行中的任务不因此增加入口，来源失效或管理范围撤回时关闭入口；后台仍核实旧任务、未核查效果及对外委派状态。

验证包括真实 Identity 三账号、发起人准确会话来源、原执行与新执行实际 `time_now` 调用、参与人 HTTP 转交及准确重试、原来源发布记录完整保持、额外管理范围撤回后禁止重放、独立执行责任继续、手动交付验收与重启，以及转交后撤回原共享会阻止下一次工具／模型调用。另一个存储场景使用不同的管理人和接手人，验证实际管理记录与准确接收角色分别保持。实际 Chrome 以参与人登录完成转交、查看旧共享运行、接单历史、旧执行人撤回入口及 390px 边界；重放使用页面实际提交的请求，六张截图逐张核对且无 page error。

六个完整 Agent Go 包、转交／逐次身份／主体退出／参与人管理的 race、两条真实 HTTP 根测试、Chrome 与前端 79 项测试及构建通过。模型为确定性夹具，没有调用外部模型服务。

本阶段验证准确原约定根及无依赖的转交。参与人的完整依赖管理、多所有者依赖及混合依赖来源、其他专业来源共享与 C05 其余范围继续待办。未将这些范围算入完成，完整清单仍为 4／25。
