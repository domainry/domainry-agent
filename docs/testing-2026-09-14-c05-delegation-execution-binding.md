# C05：接收方执行身份绑定与应用接单

日期：2026-09-14。接续[委派与执行归属分离](testing-2026-09-14-c05-delegation-execution-storage.md)。本轮将接收方明确认可的执行角色接到配置、匹配、接单、后台复核和页面，验证用户直接发起的跨主体委派。**Agent 自主发起委派时的跨主体来源共享、自动交付与完整执行详情共享仍未完成；C05 保持未完成，整表仍为 4／25。**

## 当前实现

- Agent 配置新增 `delegation_execution`。省略表示保留原设置；`caller` 使用发起人的权限；`owner` 由配置所有者明确绑定自己当前选定的角色。启用需要当前配置权、查看／接收／共享权限，执行角色由服务端从实际操作者取值。浏览器只提交模式，不提交执行用户或角色。普通对话继续使用对话发起人的身份。
- `delegation_role_key` 仅作为已保存绑定的返回字段。普通改名、工具修改等不会意外重新绑定当前角色；页面提供明确的重新绑定操作。绑定角色参与保存幂等摘要，相同请求标识不能通过重试更换角色。
- 接单首先检查发起人的权限和对配置的当前共享授权，再检查接收角色的当前权限。接收方通过实际执行关系获得该委派的查看、接收、沟通、执行阅读和交付阅读范围，仍与 Identity 角色的数据范围取交集；委派所有者仍作为真实 `owner_user_id` 交给 Identity。执行关系不授予发起方的管理／参与名单修改权限。
- 匹配使用实际接收角色的工具授权和用户队列名额；配置负载仍是工作空间内该 Agent 的实际聚合，历史样本仍限发起人自己的记录。接单时再次核对这些条件。权限服务失败不会被当作一个正常的匹配结果。
- 接单快照固定配置版本、执行用户和接收角色。后台运行复核原发起人的当前发起权限、共享配置、接收角色和快照；角色、配置或共享撤回不会把旧任务自动换成另一个身份继续执行。
- 具体委派的协调记录仍归发起方，任务与工具运行归接收方。应用可以为已获准的委派读取具体接收任务的状态，普通会话／运行／任务入口仍拒绝跨用户直接访问。来源不能读取时，委派页明确显示执行详情不可读，不把未知步骤展示成已完成的零步骤，也不提供另一用户的私有会话入口。
- 通信沿已持久化的两侧身份路由，保留发送用户和发送角色；接收时复核原发送角色。其他用户的输入在模型上下文中明确标识为独立用户提供的任务信息，不作为执行用户的授权。服务器状态通知保持独立路径。
- 页面新增执行身份选择、当前绑定角色、重新绑定和撤回；共享配置卡片说明委派实际使用的身份。修复了保存后立即再次编辑取得旧版本的问题，页面先采用实际保存回执，再刷新目录。

## 已验证的实际行为

使用真实 Identity、HTTP、SQLite 和可控制时序的模型夹具：发起账号没有接单和待办工具权限，接收账号绑定自己的角色并共享配置；发起方仍可以匹配、创建委派，实际模型调用读取接收方的真实 Todo 数据。运行快照中的执行用户和角色与接收方一致。

发起方的人类补充消息确实进入接收方模型输入，保存真实发送身份和消费回执。发起方无法通过普通会话／任务接口或委派详情取得接收方私有待办内容。接收方手动提交无私有来源引用的结论，发起方按准确交付摘要验收；交付与验收记录保留各自实际操作者，重启后状态保持。模型返回前撤回执行绑定，旧任务停止且未完成后续待办工具调用。

应用与存储用例另外验证同一用户不同角色、普通对话不取得绑定角色、角色变更和当前权限撤回、绑定幂等冲突、普通配置编辑保留角色，以及执行关系不能获得发起方管理权限。原共享配置、委派参与人 HTTP 场景继续通过。

真实 Chrome 双账号验证绑定、共享目录的身份提示、普通编辑保留角色、立即再次编辑、撤回与刷新后保持；同时检查桌面和 390px 布局，以及发起方页面对私有执行的处理。前端类型检查、构建、状态测试、相关 Go 回归和指定边界的 race 检查通过。证据与命令见[验证记录](evidence/2026-09-14-c05-delegation-execution-binding/commands.md)。

## 未完成范围

本轮的跨主体交付验证是**接收方手动提交结论**，不是 Agent 自动交付的来源验证。Agent 发起的约定、输入、消息以及模型生成的交付包含私有运行来源；目前缺少跨主体明确发布这些来源的完整契约。接单入口提前拒绝接收方不能读取的模型来源与依赖，防止已经接单后才发现输入不可读。后续要保留实际读者与原执行主体各自独立的权限检查，接通已提交成果及其原始回执，不能把协调记录的归属当作读取私有数据的授权。

同样待完成：参与者管理及执行／交付阅读范围、跨主体转交与各次接手的身份记录、主体退出／数据清理、跨所有者依赖传播，以及整个目标的累计预算。当前双主体转交仍按原保护逻辑拒绝。新增执行绑定的 SaaS 专项跨主体端到端场景仍需补充；本轮不声明发布或真实 Postgres／MySQL 数据库验收。
