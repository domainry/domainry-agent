# C05：业务原回执阅读

日期：2026-09-13。接续 Knowledge 原回执阅读，补齐内置业务目录、记录查询、单条记录、关联记录及流程状态的独立交付阅读。C05 仍保留跨用户／角色主体、业务动作／流程启动回执和其他未接入来源的独立策略，整体 **4／25**。

## 实现

- SDK 增加可选 `ConversationBusinessResultReadSource`。Agent 仅在服务端交付来源检查中调用，验证原完成状态、工具定义、原参数、来源身份／用户范围及完整结果结构，并检查当前工具设置和 `delivery_read`。调用结束再次核对来源身份；超时取消不会继续回退。
- 来源 owner 明确决定读取权限。只有精确的 unsupported 错误回退到原执行授权；业务权限拒绝或连接失败不会借原执行权放行。未实现该端口的自定义业务宿主保持原行为。
- Runtime 的目录、记录、关联查询复用当前 Identity、对象、记录范围、字段可见性／脱敏及原签名或完整结果检查。流程状态复用当前流程参与者和关联记录检查。实际读取者一直传给 owner，不替换为原执行者或系统主体。
- 已有签名绑定当时的完整有效权限摘要。权限摘要改变后，业务读取需要当前完整结果与原结果一致；流程状态的独立读取也支持这一核对，且先验证原签名。权限改变又同时发生数据／状态变化时，旧回执会被隐藏；不会把当前值替换成原值，也不会忽略损坏签名。这是当前保守边界，未声称所有历史快照可在任意授权变化后继续阅读。
- 同一委派的交付依据可能包含之前读取的协作约定。该内部来源核对不再要求执行沟通／委派工具，但仍逐项遍历资料、消息和运行来源。直接读取含消息／执行细节的原始协作回执继续要求相应权限，不继承只供内部来源核对的例外；不同委派及私有附件也不继承。
- 沿用当前与历史交付的准确回执引用、分页、Module／SaaS 入口和页面，没有新增 Agent 路由、Action 或数据库迁移，也未修改生产前端。

## 服务契约

受信任 `businessrpc` 新增 `business_result_read`，仍验证固定部署范围、当前主体和真实 owner；不调用生产工具授权接口，不发起工具或写入。只传已有完整证据 DTO 与实际读取者。新增方法及错误语义经过契约检查，当前 SHA256：

旧客户端／服务端 pin 不匹配时拒绝握手，部署双方需共同更新；本阶段没有修改部署配置或发布服务。SDK Backend 未增加必选方法。`invoke_action` 和 `workflow_start` 暂返回明确 unsupported，仍保留原完整执行／回执授权，继续在 C05 实现 owner 策略。

## 场景验证

- Agent 应用：五种业务结果在无专业执行 Profile 下可读；普通历史拒绝；改变原值、额外未验证字段、来源身份、执行中绑定变化、停用、撤权及 unsupported 均按预期处理。协作来源例外覆盖同委派、跨委派、私有附件和直接读取原始协作结果。
- SDK 实际 HTTP：保留原请求、证明与 `9007199254740993` 整数精度；撤回工具权后独立阅读可达 owner，普通 revalidate 仍拒绝；owner 拒绝、失效主体和跨工作区请求拒绝；unsupported 精确错误传输，不触发写入或重试。
- Runtime 真实 Record／Identity／SQLite：原签名、普通更新、记录归属、字段撤回、关联起点／关联字段及流程参与者检查；当前权限变化时仍按完整原投影复核，损坏签名拒绝。
- Runtime 真实业务 RPC：执行原目录、两页查询、记录、关联查询和一次实际流程启动／状态读取；切换到移除全部 Agent 工具权及流程启动权的角色后，五类原回执可读。字段和记录权限撤回隐藏相关结果，恢复与重启后原回执仍可核对。
- Agent 真实 HTTP／Identity／SQLite／worker：接收 Agent 完成五类调用，经实际交付工具提交准确回执；撤回全部 Agent 工具权、只保留协作 view／delivery_read 后，当前与历史的五类业务原回执仍可读，原始执行详情拒绝。工具停用或 owner 撤权隐藏交付，恢复和重启保持原引用。夹具确认全程只有原来的五次业务工具调用。
