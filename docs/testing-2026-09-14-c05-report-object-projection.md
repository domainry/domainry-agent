接续[旧生命周期 race 终态](testing-2026-09-14-c05-historical-lifecycle-race-terminal.md)。先前正常运行的 CPU 调用图显示，整份 Schema 构建的 15.50 秒累计 CPU 中，11.90 秒来自报表／分析对象索引：它只需要对象定义，却调用整份 Schema 构建与摘要。

本次将 `reportRecordSchemaMap` 改为复用当前对象投影，保留有效能力归一化。针对性用例先复现旧路径构建一次整份 Schema；修复后核对对象字段、能力、实际元数据更新及删除立即生效，重复读取没有整体 Schema 构建。没有增加跨请求权限或元数据缓存。

完整装配宿主正常／race 各 61 根通过，包耗时 0.814／1.829 秒。实际旧约定完整生命周期正常通过：要求更新、重启、原角色撤回与恢复、准确新约定运行、再次交付／验收和原历史保持，根 64.74 秒、包 65.871 秒。新正常采样中整份 Schema 构建累计 CPU 为 3.37 秒，报表对象索引不再出现在整体构建调用链。旧正常采样与新采样是独立运行，分别保存源码版本；这些累计 CPU 不是墙钟时间，也不构成受控性能基准。

同一场景的实际 race 已终结退出 1：根 563.66 秒、包 565.509 秒。修订运行使用原角色和约定版本 2，剩余预算 7 步、8 次调用、8192 字节、180 秒；在 180006 毫秒中断，错误 `execution_interrupted`。两份原回执与约定调用成功，交付调用已生成但状态 `not_started`，没有再次交付。观察窗口 30 分钟，失败属于实际执行预算，不是观察超时。

这次实际 race CPU profile 已取得完整终态样本：采样时长 563.87 秒、总 CPU 1049.33 秒；主体解析链累计 237.97 秒，其中 SDK resolver 237.91 秒、角色 Snapshot 116.60 秒，Domain `BuildPrincipalForRole` 在整个采样中 111.54 秒。累计项重叠，不能相加；当前代码也确认 SDK Resolve 之后 SnapshotForRole 会再次解析同一角色主体。后续继续减少重复事实读取与构建，保留真实当前角色和授权版本检查，不能简单跳过快照的重新解析。
