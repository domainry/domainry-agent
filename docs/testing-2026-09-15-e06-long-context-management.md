# E06 长上下文管理验收

日期：2026-09-15。本轮把原有会话摘要和结果按需读取扩展为可注册、可刷新、逐步冻结且可撤权的上下文装配，并增加模型输入压力、执行区间压缩、来源版本变化和提供者缓存用量诊断。E06 验收完成后，完整清单进度为 **12／25**。

## 来源注册、版本与装配

- [Agent SDK 上下文契约](../../domainry-agent-sdk/conversation_context.go)公开只读 `ConversationContextSource`。宿主在启动时声明来源种类、工作区／会话／任务范围、运行内／逐步刷新、信任类型、顺序、单源字节上限和稳定前缀；重复 key、模糊信任、越界预算和把动态数据标成稳定指令都会拒绝启动。
- [来源装配](../internal/application/conversation_context_sources.go)只调用适用于当前任务身份的来源，以当前租约主体和当前用户输入读取并立即授权。项目指令明确限制在当前用户、任务和工具授权内；业务记录按不可信数据处理；文件来源只提供引用，必须再用获准工具读取正文。
- 每个模型步骤冻结来源定义摘要、版本、内容／消息完整性摘要、顺序和更新时间。逐步来源更新会保留完整变化链；执行循环以上一步持久输入为下一步基线，恢复执行也采用已保存步骤，因此 `record-v1 → record-v2 → record-v3` 不会重新从运行初始版本跳转。
- 当前任务约定、计划、已接收的要求变更和未解决分歧沿用现有版本化装配。转交记录、旧完成结论和压缩执行区间明确标为历史事实，不授予权限，也不作为当前完成或业务状态证明。

## 压力、压缩与恢复

- [执行上下文管理](../internal/application/conversation_execution_context.go)优先调用 SDK 的纯 `ConversationStepInputSizer`，用提供者实际序列化器计算请求字节；不支持该端口时保守计算完整冻结请求。普通无注册来源的运行也记录压力，非法测量不会关闭上限检查。
- 超限时先把已存工具结果缩成带原状态、资源 ID、错误码、完整字节数和不可变读取引用的有界预览；仍超限时把较早且完整的模型／工具区间改成服务端检查点。检查点保留助手文本、精确调用参数、调用／结果配对和读取引用，移除旧提供者续接块及内联结果正文；最新区间、用户修正和当前来源继续保留。
- 压缩前会重新读取并授权原结果；每次模型请求前再次核对冻结工具目录、已消费结果、注册来源及其根来源。无法安全压缩时返回可恢复的 `execution_context_exceeded`，不会截断当前用户请求、伪造结果摘要或绕过授权。
- 稳定系统提示、工具定义和运行内冻结的项目指令形成稳定摘要；动态消息与刷新来源单独形成摘要。提供者报告的缓存命中／创建 token 按步骤和运行累计展示，缓存记录不会替代当前来源授权。

## 持久化、公开诊断与撤权

- SQLite 对冻结来源、压力和压缩字段做结构及完整性校验；运行来源快照包含各步骤的上下文 manifest。历史回复进入新模型输入、摘要或共享读取前，会对初始输入和每个历史步骤重新授权。
- 运行事件和公开 API 只投影来源 key、种类、范围、刷新方式、版本、顺序、更新时间、压力、压缩计数和缓存 token。来源正文、模型输入、工具 Schema、定义／内容／消息摘要及授权材料不进入公开诊断。
- [处理记录页面](../frontend/src/ExecutionActivity.tsx)展示实际输入字节和上限、是否按提供者协议计量、来源版本和更新链、压缩结果／区间及提供者缓存用量；桌面和 390 px 均可阅读。

## 真实场景与回归结果

- 真实 Identity／HTTP／SQLite／编译前端／Chrome 场景注册项目指令、当前业务记录和文件引用，执行三次模型请求及两次工具读取。业务来源依次为 `record-v1`、`record-v2`、`record-v3`；峰值输入 16,169／20,480 字节，压缩 2 个结果和 1 个旧执行区间，缓存命中 180 token、新建 100 token。
- 撤回旧业务来源后，新运行只装配 `record-v4`。原回复在会话历史中替换为来源不可验证提示，旧正文、Q1–Q3 记录内容和内部摘要未出现在新模型输入或公开运行 JSON。
- SDK 全量、Agent 核心包、完整 Web／Integration、上下文针对性 race、90 项前端测试、生产构建和真实 Chrome 流程通过。完整 Web 为 558.744 秒，Integration 为 99.274 秒；浏览器登录后的 JavaScript 错误、控制台错误和警告均为 0。
