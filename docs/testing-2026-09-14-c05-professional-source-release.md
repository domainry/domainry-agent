# C05：报表与分析的跨主体来源阅读和自动交付

日期：2026-09-14。接续[内置时钟来源发布](testing-2026-09-14-c05-source-release.md)。本阶段接通 Report／Analysis 原证明与实际读者权限的分离，并验证真实 Runtime 的双用户 Agent 自动交付。**C05 仍未完整验收，整表仍为 4／25。**

## 实现边界

- Agent 的独立工具结果阅读请求继续使用实际读者的 Authority；服务端从已发布来源账本解析 ResultProducer，仅用于原证明身份核对。该字段不进入公开工具 JSON，不能提供执行权、租约或操作确认。
- Tools 的 Report／Analysis 适配器通过可选共享阅读端口分别处理报表目录、查询结果、分析目录及计算结果。普通执行与原授权重放保留实际调用者权限；缺少独立来源端口保持拒绝，明确资料拒绝不会回退为原执行者权限。
- Report 保留原 HMAC 格式和签名主体，使用原提供者的当前来源版本、范围和定义复核不可变原结果，再独立检查读者的 results-read、受众、源资料和字段权限。原提供者不需要继续拥有原查询操作授权。
- Runtime 通过原有资料与字段策略分别解析两方查询范围，证明读者的行与组织范围覆盖原提供者的范围；保留 JSON 未公开的查询约束。允许无限制范围覆盖受限范围及已证明的集合／布尔范围覆盖，不重新执行历史报表或分析。不支持或不能证明的范围仍拒绝。
- Runtime 嵌入式 Agent 现在提供当前协作授权和共享用户校验，并识别协作工具。协作资源归属仍由 Agent 加载，Runtime 不保存第二份委派状态。失效用户／角色作为授权拒绝处理，真实 Identity 服务故障保留不可用错误。
- 四个新增业务 RPC 共享阅读操作保留实际读者为请求 Authority，严格校验原提供者选择器与部署范围，再由 Runtime 重新解析双方当前 Identity。共享端口不发布私有数据；明确回执发布、准确前缀和当前委派权限继续由 Agent 校验。

## 实际验证

真实 Identity、Runtime、Report、Tools、SQLite 和业务 RPC 中，通过 HTTP 创建并登录第二个用户。原提供者查询两页报表、计算四条客户记录的精确总额 70，并读取报表／数据集目录；另一账号读取这些原回执。

读者移除报表与分析执行权限后，五项原来源阅读及四项 Tools 回执阅读仍通过；普通查询、计算、原执行授权重放和普通跨用户原证明阅读拒绝。读者 results-read、资料或字段撤权、行范围缩小，原提供者资料撤权、篡改结果或错误提供者均拒绝对应数据阅读。重新打开实际数据库后仍可读；真实业务动作只修改名称、保持余额总额不变，也使旧报表／分析回执因资料版本变化失效。

完整 Agent 场景中，发起账号没有报表／分析执行权，接收账号明确以自己的 headquarters_admin 角色接单并共享配置。发起 Agent 通过 agent_delegate 创建委派，测试账号完成该调用要求的操作确认；接收 Agent 自动执行目录发现、报表查询、数据集发现和分析计算，从原结果逐行求和并与原计算比较，自动交付四份准确原回执。

四项完成条件分别核对各自工具、operation 和结果结构。目录回执不能替代查询回执；测试中混用时程序正确阻止验收，最终交付按四项条件分别提交。发起账号独立读取四份回执并通过 HTTP 验收，**不声明发起 Agent 已自主验收**。重启后继续可读；字段撤权、数据范围缩小和原接收角色失效后拒绝。双方普通私有会话入口返回 404，未发布调用引用返回 403。模型使用确定性流式夹具，业务工具与权限 owner 均为实际实现，不代表真实模型的任务成功率评估。

应用、SDK、Tools 和 Report 相关完整包回归通过；Runtime 当前授权与资料范围完整包回归、三个实际 owner RPC 场景、新增自动交付场景，以及新增应用／SDK／Report／Runtime 边界的 race 检查通过。新增签名用例拒绝未配置签名密钥，分析目录覆盖带空白的原请求；缺少 owner 范围证明端口的查询与分析共享阅读返回 503，不误报为历史结果失效。命令、原始结果、代码摘要和范围见[本轮证据](evidence/2026-09-14-c05-professional-source-release/commands.md)。

## 兼容性与剩余范围

业务 RPC 严格契约摘要更新为 `0975df00be8381ea7a3ec45a9b2aa68dedcd999c8c6901bd1ad8f82466374a53`，需要协调客户端和服务端的部署 pin。原有请求／结果 DTO 与必需 Backend 接口保持不变；旧摘要在握手阶段拒绝。Report 的原 HMAC 不重签成读者身份。

Runtime 验证从其目录执行，并使用 `/tmp/runtime-work/go.work` 绑定当前本地模块；补齐本地 Data Exchange SDK 后修正其已有 Lifecycle 类型引用，使当前装配可编译，没有修改该 owner 的业务逻辑。实际数据库覆盖 SQLite。

其余专业来源的跨主体独立阅读、同用户不同角色与多所有者依赖、参与者管理及执行／交付范围、完整执行详情共享、跨主体转交与主体退出仍在 C05。未提供独立读取端口的自定义来源保留原授权检查。C06 及后续条目继续按原顺序推进。
