# C05：实际模型请求的上下文计量

完整 HTTP 回归发现两个失败：跨用户委派交付验收、撤回计划写权限后读取七项原回执，均在模型调用前返回 `execution_context_exceeded`。当前个人工具与计划工具按 Key 去重后共 38 项，完整内部定义为 66,265 字节，超过默认 65,536 字节；这些定义包含不发送给模型的输出 Schema、授权和回执策略。原检查错误地把整个内部执行快照当成模型输入。诊断失败日志保留，不作为通过证据。

同次完整检查还发现 Module 测试仍断言 28 个迁移；当前 source-owned schema 已有第 29 项 `agent_contract_publications`。同步测试断言后 Module 完整包通过，本阶段没有新增迁移。

SDK 新增可选 `ConversationStepInputSizer`，不增加既有模型接口的必需方法。实际 Provider 使用与 `StreamConversationStep` 相同的协议编码器和配置，纯计算发送请求体的 JSON 字节数，不调用网络。上下文装配的工具预留、结果压缩后的检查、正式模型调用及恢复检查统一使用该端口。配置或冻结模型身份不匹配、协议未知、输入非法、计量失败或返回非正值均停止；未实现该端口的宿主继续按完整 SDK 请求保守计量。

默认上下文限制、任务步骤／调用预算和执行时限保持不变。工具定义、输出 Schema、授权、原来源证明和回执策略仍完整冻结，来源权限复核继续执行；不会为通过容量检查删去这些字段。压缩记录的 BeforeBytes／AfterBytes 仍记录完整执行快照的实际序列化大小，不混用 Provider 请求体计量。HTTP 模型夹具采用实际 Provider 编码器计量。

验证范围：

- 应用测试证明超过内部快照容量的未发送元数据保持逐字节不变；实际请求超限、无效计量、模型变更错误及没有计量端口的保守检查仍阻止执行。
- Chat Completions、Messages、Responses 的真实 HTTP 请求体长度均与配置模型的计量结果完全一致；首轮和携带原生续接状态／配对工具结果的后续请求分别核对。首轮完整内部快照超过 64KB，而发送体正常计量。计量前后请求计数不增加。
- 独立 Provider 测试覆盖冻结身份变更、未知协议和非法输入，均不发送请求。
- 原跨用户委派与七项计划回执 HTTP 根场景均通过，沿用实际 Identity、工具执行和交付链路。
- 完整 assembly/web 包以 `-count=1` 通过，耗时 419.421 秒，包括原协作、来源、执行共享和三账号依赖转交 HTTP 场景；浏览器测试保持默认条件跳过，本阶段不声明新增 Chrome 验收。
- 八个完整 Agent 包、SDK 根包及上下文／协议针对性 race 通过；依赖原接单存储夹具移除服务端注入的 conversation_id，跨归属约定重新共享和协议根场景通过。
- 补充应用来源夹具覆盖两个不同上游所有者，各自原执行角色与实际发布角色分开。任何一方角色撤权阻止合并发布，但另一条独立依赖仍可读取；发起人可查看上游不能替代接手人的受众范围；跨所有者原根替换被拒绝。下游重新共享仍只列自身直接来源，不接管上游发布。此项验证来源与授权逻辑，不记作真实 Runtime 专业查询验收。

八个包为 application、database/agent、provider、remote、transport/http/module、capability、server 和 module。模型仍为确定性夹具，没有调用外部模型服务；本阶段没有新增前端或 Runtime 专业来源验收。C05 的多所有者混合专业依赖来源、其余专业共享及历史流程、更广 Identity 退出联动等原待办继续保留，完整清单仍为 **4／25**。
