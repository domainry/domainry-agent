# C05：报表原结果的排除与 NULL 范围

当前 Report／Analysis 共享阅读通过 Runtime 的真实对象和字段授权、查询归一化分别取得原提供者与当前读者的范围。此前范围证明只处理正向集合和部分旧操作符，而 Identity SDK 的不等／排除实际编译为 `not`，存在／不存在实际编译为 `exists`／`not_exists`。因此同一排除条件或更宽读者也被拒绝。

本次补充完整编译树的操作符、参数形状、深度与节点预算验证，再证明包含关系。有限正向集合包含保持 SQL 的 FALSE ≤ UNKNOWN ≤ TRUE 顺序；两边否定时反转包含方向，处理双重否定及直接字段的 NULL 互补。未知操作符、无效分支和上下文相关关系不能通过其他匹配分支绕过验证。字符串字面值不同不能证明 SQL 不相等，不据此允许正向范围进入否定范围。

八组实际 SQLite ORM 场景覆盖不等、较弱排除、组合排除、双重否定、提供者与读者 guardrail、非空、空及否定空；核对实际行 ID／总数、NULL 和另一工作空间。每项都验证 SDK 授权配置有效；收窄读者后真实查询成功返回空页，而原范围阅读拒绝，原记录字节保持。旧证明代码以 Go overlay 对照，八项全部复现范围拒绝；同一有效夹具在当前代码全部通过。早期 guardrail 夹具把 `all` 和 owner 谓词混用，在比较前即被 SDK 拒绝，诊断保留；它没有被记作生产 guardrail 权限缺陷。

十项边界核对 nullable 字段否定的 UNKNOWN、排除方向、空 IN 常量、SQL 字面值不可作排除证明、未知兄弟分支、无效 NOT 及关系存在扩展。完整报表宿主正常和 race 各 12 根通过，包耗时分别 0.397／1.916 秒；5480 份依赖源码／测试／嵌入／模块输入在封存时核对未变。该保守清单包含依赖包测试的上集，不声称每项均为该命令实际编译文件。源码、有效夹具的旧失败／新通过、完整宿主日志及摘要见[阶段证据](evidence/2026-09-14-c05-report-negation-scope/acceptance.json)。后续[业务 NULL 否定证明](testing-2026-09-14-c05-business-null-negation.md)补业务总数的实际反例，[对象投影与实际采样](testing-2026-09-14-c05-report-object-projection.md)继续处理真实生命周期耗时。

本阶段的新策略分支由实际 ORM 与 SDK 授权夹具验证，未宣称原生 Identity 角色页面已经能配置这些谓词，也未新增在线模型或浏览器验收。未知关系表达式、更完整来源与生命周期等范围继续待办，完整 C05 与整表仍为 **4／25**。
