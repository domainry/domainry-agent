# C05：原查询筛选参与共享阅读范围证明

接续[前缀与非空阅读范围](testing-2026-09-14-c05-prefix-existence-scope.md)。本阶段处理原查询筛选比原提供者完整读取策略更窄的情况；完整 C05 继续待办，整表保持 **4／25**。

实际反例：原提供者可读取 Alpha／Beta／Gamma 三条记录，但原查询只选择 Alpha／Beta；读者也只能读 Alpha／Beta。旧实现仍要求读者覆盖原提供者整份策略，拒绝两份已被原筛选限制的分页回执。十组记录分页和一组关联分页在补丁前均实际失败，原日志保留。

真实查询与来源范围证明现在复用同一字段／算子／JSON 解码与 RecordNormalizeFilterExpression 边界。JSON 解码保留 Number，整数归一化不经过浮点数，文本空格保持字面值。参数错误、字段权限不足、未知字段和不支持算子不会通过放宽筛选获得阅读。

来源证明在原提供者策略与原筛选条件的交集中判断读者范围。原策略和查询字面值各有独立绑定上下文；查询上下文没有 Subject、AccessBundle 或执行权限，不进入任何业务 IO／授权端口。查询值放入仅供 SDK 绑定的局部常量 claim，SDK 解引用一次后保持原字面值。不会修改实际原提供者／读者的 claims，也不会将 `$subject.id`／`$context.query_literal_0` 文本自动变成身份条件。

等值、不等、IN／NOT IN 和 NULL／非空筛选按归一化后的值映射到现有 SDK 算子。大小比较与字面 substring 只保留它们隐含的非空约束；currency／percent 有实际数据库专用编码，避免将原始小数文本当作 SDK 等值比较，只使用不受编码影响的 nullness。未知或不能证明的组合继续拒绝，未扩展 Identity 的授权算子。

读者的 AND 条件可分别由原策略和原筛选证明。新读者 deny 仍按原方向检查；原 NOT IN 明确排除该 deny 时，还可证明完整查询满足 NOT(deny)。没有通过首行可见、重新计数或当前结果替换原总数。原游标始终不授予读者实际查询权，也未使用游标位置缩小阅读范围证明。

关联分页使用实际目标对象的字段与策略来证明显式原筛选，来源父记录、关系字段与当前读者的关联读取仍经过原 Runtime 边界；未把父对象筛选误套到目标对象。当前只利用显式筛选，不把未单独证明的关系约束当作额外授权。

新增实际 ORM 场景覆盖有限查询、混合策略／筛选、原提供者 unrestricted、2^53 以上原整数、整数字符串归一化、排除、NULL、大小比较／字面 substring 的非空约束、新读者 deny 被原筛选排除，以及目标对象关联分页。每组原第一页 total=2 与原游标第二页核对；读者收窄后即使首行仍可读，也拒绝两份旧页。原回执字节不改写。字面 claim／空格、相邻浮点数、不可翻译策略和数据库小数编码另有证明边界测试；小数用例是元数据投影证明，未冒充实际小数存储验收。

完整授权宿主正常／race 已通过；七类业务原回执真实 RPC／重启通过。实际跨账号复杂筛选 Agent 链路仍使用公开角色模型回归，状态见最终归档。公开 RolePermission 只提供既有五种 DataScope，guardrail 的数据限制为整项限制；当前不能把新增条件行分支记成真实发布角色配置。该具体分支由真实 Runtime RecordApplication／RecordStore／SQLite 与 SDK 身份夹具证明，实际 Cookie／Identity／RPC 的完整链路分别计证据。
