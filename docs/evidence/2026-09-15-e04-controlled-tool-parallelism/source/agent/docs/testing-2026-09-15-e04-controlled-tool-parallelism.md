# E04 受控工具并行验收

日期：2026-09-15。本轮只开放工具 owner 明确声明、无顺序依赖且无外部可见写入的读取调用并行。Agent 仍拥有执行决策、实时授权、并行上限、持久回执、取消和审计；工具声明本身不会启动 goroutine，也不会取得 Agent 运行控制权。E04 验收完成后，完整清单进度为 **10／25**；基于资源冲突键的写入并行继续留在后续扩展范围。

## Agent 与 Tools 的边界

- [Tools SDK 定义](../../domainry-tools-sdk/tools.go)增加可选 `parallelism`。空值保持串行兼容；当前唯一允许值 `independent_read` 是工具 owner 对无顺序依赖、无外部可见写入的明确承诺。`domainry-tools` 注册表拒绝未知值和把写工具声明为独立读取。
- `domainry-tools` 的网页、邮件、日历和结构化记录读取，以及报表、分析和计划读取由各自 owner 显式声明。Agent 自有工具只先开放纯时间读取和确定性计算；历史、Knowledge、任务、协作、回执读取及所有写入保持串行，不能仅凭 `effect=read` 自动并行。
- [Agent SDK 并行判定](../../domainry-agent-sdk/conversation_execution.go)要求同一模型步骤内每个调用都存在、均为读取、均显式声明且服务端上限至少为 2。混合批次、旧定义、缺失定义、任何写入和旧冻结步骤的零上限全部返回串行宽度 1。

## 调度、授权与持久顺序

- Agent 在模型步骤写入后先完成全部调用的参数解码和运行预算预留，再按冻结的 `max_parallel_tools` 分成有界批次。默认宽度为 4，部署可用 `AGENT_CONVERSATION_MAX_PARALLEL_TOOLS` 配置，合法范围为 1–16；配置值进入每个冻结模型步骤，恢复不能悄悄改宽度。
- 每个 goroutine 仍独立执行运行主体复核、来源复核、当前目录比对、具体工具授权、参数 Schema 校验、可用性检查、开始账本和最终回执。模型只提供工具名和参数，不能提供并行声明、权限或批次大小。
- SQLite 开始事务只放宽当前批次内部的调用顺序；下一批调用必须等前面完整批次的每个回执进入 `completed`。旧步骤继续要求所有前序调用依次完成。三调用、宽度 2 的持久化场景证明第二个调用可先开始，第三个调用在首批完成前被拒绝。
- 并行执行结果写入按调用 ID 独立保存，内存结果按原索引收集，全部完成后再按模型原始调用顺序装配工具消息。并发完成顺序不会改变模型上下文，也不会合并回执。
- 同批执行基础设施错误会取消其他成员；用户取消运行会取消当前批次的全部调用。外部调用结束后，Agent 使用受限的无取消上下文保存实际回执，因此取消不会把已发生效果伪装成未发生；本轮开放的并行项均为读取。

## 实际计量与页面

- 运行指标新增实际并行读取批次数、实际启动调用数和峰值同时执行数。指标从 `tool.started` 与终态工具事件投影，按尝试和调用去重；仅在步骤中符合并行条件但未实际启动的调用不会计入。
- 多个 Agent worker 的排队／运行容量继续由现有用户和工作区容量账本计量；单次运行内工具并行只进入该运行的新指标。两类并发没有共用一个数字，也不会用工具宽度增加 worker 名额。
- 步骤页面显示该模型步骤采用的独立读取并行调度和原顺序回执；运行详情显示实际读取调用数、批次数和峰值。零并行的历史运行显示“未使用”。

## 验收场景

- 真实 Identity／HTTP／SQLite 场景覆盖两调用完整并行、三调用按 2+1 限宽、未声明工具串行回退和运行取消。每项执行前都已有独立授权，完成投影保持 `read-one`、`read-two`、`read-three` 原顺序。
- 针对性 race 覆盖实际并行执行及持久化批次顺序。Agent SDK 覆盖混合、写入、旧定义、重复／缺失定义和限制为 1 的拒绝分支；Tools 注册表覆盖合法读取、未知声明和非法写入声明。
- 前端状态测试核对步骤事件投影；生产构建后的真实 Chrome 核对两个实际读取、1 批、峰值 2、两个独立回执以及 390 px 页面。浏览器登录后的 JavaScript 错误、控制台错误和警告均为 0。
- Agent SDK、Tools SDK、Tools、Agent 核心包、完整 Web、Integration、前端测试和生产构建通过；各仓库 `git diff --check` 通过。
