# C05：共享执行工具的历史阅读用途

接续[产品结构化记录原结果阅读](testing-2026-09-14-c05-structured-record-results.md)。本阶段修复共享执行工具输出再次进入历史／模型时丢失阅读用途的问题，完整 C05 仍未验收，整表保持 **4／25**。

真实反例先实际执行 `delegation_get` 和四个共享执行工具，发布经过用户确认。撤回原记录 save 权限、保留 read／list 权限后，直接共享执行仍可读，检查 Agent 的保存历史却隐藏。诊断记录明确指出 `requirements_save` 与 `delegation_get` 在空阅读范围中被拒绝；这是来源遍历退回执行授权，不是根据统一 AccessError 推测的超时。

现在执行过程／结果分页保留自己的准确工具回执前缀作为来源，后续读取重新执行该回执的类型化证明：准确委派和原运行、当前明确发布、实际读者、原提供者和原页字节分别复核。既不把旧页换成当前结果，也不把裸原运行当作获得私有历史的授权。发布回执仍只提供元数据，撤回后重读它不会恢复共享。

委派详情里的任务结果与交付结果分别处理。原任务投影先通过 execution_read，随后只对它的准确原运行保留 execution 阅读用途；只有具备原身份查询端口的来源才能采用此策略。不同原角色仍需该委派的明确 execution 发布，不能仅凭同用户存储归属引入旧角色。交付的来源核对继续使用 delivery 阅读用途；该用途没有授予原始任务和通信内容的权限。

旧步骤输入曾把这些工具输出展开成裸原运行。兼容读取只接受同一不可变快照中、该输入之前实际完成的成功工具回执，且必须准确解释所引用的原运行／结果前缀，然后重新检查其当前授权与原字节。历史账本和输入不改写。同一步／未来调用、其他运行、越过原结果前缀及非法步骤边界均不能恢复用途。嵌套遍历继续共用当前请求内的引用／记录循环检查。

实际产品夹具新增只配置五个协作工具的检查 Agent，不配置记录写入／读取工具。它真正获取约定、确认发布、列出准确原执行、读取六步原过程，并用准确原 result_reference 读取两页结果。检查运行保持七步／六次工具调用。六份包装原回执分别经普通历史结果入口完整读取并核对 SHA，原三份记录回执继续从当前交付、准确历史交付和共享执行三个入口核对。首次、写入撤权后和重启后共 **45 次原 SHA**；资料读取撤权时历史载荷隐藏。

原实际接收任务仍为六步，一次保存，连同两个 SDK 来源夹具保存，产品校验总数保持三。任务预算保持 12 步／12 次调用／8192 字节／60 秒，未增加执行或上下文预算。正常／race 根采用确定性模型，实际 Identity Cookie、HTTP、Tools 注册、Knowledge 原版本和 SQLite 链路保持。

串行实际 race 中，原六步任务在原 60 秒预算内完成；随后检查 Agent 的 90 秒观察窗口先结束，普通检查运行仍为 running、第四步已产生，未证明其终态。该检查不是另一个后台任务，仍采用 ConversationService 的默认 5 分钟运行预算。夹具改为按已有 5 分钟观察它的终态，服务端默认超时、委派实际预算和全部完成／原字节断言保持；首次失败及 CPU profile 保留。该 profile 的累计 CPU 包含主体解析约 65.63 秒、来源遍历约 46.46 秒，节点有包含关系，不能相加或据此省略权限检查。

并发检查另复现真实 60 秒任务超时：原交付已保存，最后一步被中断，失败保留。原观察器在接单后仍反复读取发起运行、委派列表、完整委派及接收运行。现在接单前仍核对原创建，接单后只跟踪准确接收运行和实际确认，终态后重新获取完整委派并逐项核对交付。观察器不延长服务端预算，不忽略终态失败，也不重复保存。

当前检查状态以[阶段接受记录](evidence/2026-09-14-c05-execution-wrapper-history/acceptance.json)为准。新增来源／权限反例、Application 完整 race及八个核心包已通过；最后的实际产品正常／race 与可执行代码回归均按具体编译版本归档。可执行包回归只排除七个不可变诊断快照目录，原递归命令的编译／旧夹具失败继续保留。边界补丁与观察器修正的编译版本分别记录，不把之前的回归结果冒充当前版本。

其余完整历史接单与执行来源组合、更完整查询表达式、其他多所有者旧角色／混合根、其他依赖管理及 Identity 主体退出、先前专业写入实际 race 超时和 Runtime 已发布模块集锁同步继续待办。四个工具的业务实现仍归 Agent、沿用 Tools SDK 协议；本阶段没有改成 Tools Registry 注册，没有发布模块或改 Runtime 发布锁。
