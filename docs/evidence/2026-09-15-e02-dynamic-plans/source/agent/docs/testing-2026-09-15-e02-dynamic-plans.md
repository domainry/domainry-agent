# E02 计划与动态调整验收

日期：2026-09-15。本轮为普通后台任务和委派执行补齐持久、版本化计划，覆盖步骤依赖、执行依据、要求变化后的影响传播和恢复。E02 验收完成，完整清单进度为 **8／25**；完成条件的独立程序、Agent 或用户验收继续归 E03。

## 计划契约与执行

- [Agent SDK 计划契约](../../domainry-agent-sdk/conversation_plan.go)定义任务计划、版本、步骤、依赖、输入、预期输出、执行者、要求字段、证据与成果引用。计划写入使用 `client_id`、`expected_version` 和当前约定修订，读取可指定不可变历史版本。
- `plan_update` 只进入后台任务的模型工具目录；普通交互会话看不到该写工具。规划写入不要求用户逐次确认，但仍核对当前 Identity 动作权限、冻结的任务工具范围、任务归属和执行 Run。
- 服务端验证无环依赖、依赖状态、完成步骤不可改写，以及工具定义、原调用／结果、历史计划、任务、Knowledge 成果和证据引用的真实来源。执行者由服务端从当前 Agent 与 Run 派生，模型不能冒充其他执行者。
- 简单请求可以不创建计划。建立计划后，每次更新保存完整新版本；乐观并发与幂等重放在 SQLite 事务内处理，旧版本继续可读。

## 动态调整与恢复

- 任务要求变化时，按步骤声明的 `requirement_fields` 计算受影响步骤和传递依赖。已经完成的步骤及其证据保持不变；其他受影响步骤进入 `needs_review`，未受影响工作继续复用。
- 委派要求更新沿用现有依赖通知和唤醒链路。恢复执行采用当前约定与当前计划版本，保留仍有效的原工具回执；计划历史可对照恢复前后的执行依据。
- 运行完成、取消或失败时，不遗留伪装成执行中的计划：未完成步骤分别转为 `needs_review` 或 `blocked`。要求变化造成的终态依赖失效会新增系统计划版本，同时保留原运行结果和已发生效果。
- 计划随会话导出、删除和主体清理进入既有生命周期；恢复通知携带当前计划版本，避免用旧快照继续。

## 页面与共享边界

- [任务计划页面](../frontend/src/TaskPlan.tsx)展示当前版本和历史版本、步骤依赖、状态、执行者、要求字段、输入输出、证据和成果链接。点击证据会打开准确持久运行与工具调用。
- 委派详情仅在拥有 `execution_read` 时展示执行计划。跨主体共享使用明确发布的不可变执行／计划回执；发布回执的读取权不授予计划修改权，也不允许读者进入对方私有会话。
- 要求变化后的真实浏览器流程显示旧时间回执只执行一次、恢复计划采用约定 v2、受影响步骤重新核对并产生第二次交付引用；桌面和 390 px 页面均可查看。
