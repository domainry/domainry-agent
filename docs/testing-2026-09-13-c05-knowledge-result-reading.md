# C05：Knowledge 原回执阅读

日期：2026-09-13。内置 Knowledge 来源已支持在撤回 `knowledge_libraries`、`knowledge_search`、`knowledge_read` 和 `knowledge_extract` 执行权后，阅读明确提交到当前或历史交付的原回执。当前资料阅读权、来源及原值仍须核对。C05 保留跨用户／角色主体和业务等其余 owner 的独立阅读策略，整体 **4／25**。

## 实现与边界

- SDK 增加可选 `ConversationKnowledgeResultReadSource`；来源 owner 明确实现独立阅读策略。私有会话附件及其引用拒绝进入该端口。仅明确的 unsupported 错误回退到原执行授权检查，权限拒绝不回退。
- Agent 仅在服务端构造的交付来源检查中使用独立端口；先检查真实委派的 `delivery_read`、已完成原回执、准确工具定义和当前工具启用设置。普通执行详情／原始结果入口继续使用原授权。
- 目录检查当前 `libraries_list` 及每项资料库访问；托管资料检查当前资料库成员、`libraries_get`、`documents_download`、文件状态、原 SHA256、绑定和资料来源。来源调用前后均核对，撤权、归档、删除和变更不能复用旧决定。
- 远端 provider 核对当前工作区／用户／来源身份、来源 PermissionIDs、文档访问和完整响应。上游没有签名版本／ACL 凭证时，读取会重新查询来源以验证原回执；不新增 Agent 工具执行或资料写入，也不把当前新值替换进旧回执。
- 检索／正文／目录使用严格结果结构及原参数核对。抽取复用原 Schema、计划、值和证据的确定性重建，重建前后检查来源，避免只允许阅读来源却放行被改变的抽取值。
- 非托管来源需显式实现阅读策略；持久托管来源保护仍在调用前后检查。不支持该接口的自定义来源、旧式非结构化上下文维持原完整执行权限要求。
- 沿用已提交原回执的分页、当前／历史交付页面和 Module／SaaS 契约；没有新增路由、Action 或数据库迁移。本阶段未修改生产前端。

## 验证

- Agent 应用验证四种工具结果在空专业执行 Profile 下可读；普通历史不能借用该路径。覆盖独立 owner 拒绝、停用、原值改变、额外未验证字段、私有附件及 unsupported 回退。
- Knowledge owner／provider 验证当前权限、成员、文件状态／hash、来源绑定、执行中撤权、远端文档 ACL、工作区及用户隔离、来源改变与连接不可用。持久托管来源标志在调用期间变化仍拒绝。
- 真实 HTTP／Identity／Knowledge／SQLite／worker 先完成四种工具调用，再通过实际委派交付工具提交准确回执。撤回全部 Knowledge 工具执行权后，当前与历史回执仍能阅读，原抽取值为 `123.45`；原始执行详情继续拒绝。分别撤回下载、资料库和目录阅读权，或将远端内容改为 `999.99`，交付正文和原回执均隐藏。恢复及重启后继续读取原回执，全过程只发生一次资料上传写入。
- 真实 Chrome 验证四类结果、抽取值及证据、历史版本、撤权／恢复、刷新、关闭清理和 390px 页面。网络记录只请求已交付回执，没有原始执行结果请求。已检查桌面与窄屏截图。
- Agent／SDK／Knowledge 全包通过；应用、Knowledge owner／provider 和真实 HTTP 场景竞态检查通过。已有 SaaS 转发和全部契约测试随全包通过；本阶段的真实 Knowledge 数据场景在 Module／HTTP 装配中执行。
