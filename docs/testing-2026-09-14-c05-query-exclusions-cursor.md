# C05：查询排除范围与原游标交付

接续[业务共享阅读](testing-2026-09-14-c05-business-shared-readers.md)和[其他 Knowledge 来源](testing-2026-09-14-c05-knowledge-other-sources.md)。本阶段扩展当前阅读范围的证明和真实查询分页交付；整表仍为 **4／25**，完整 C05 尚未验收。

原范围证明支持相同 SDK SQL、常见 AND／OR 和原子等值集合，但无法证明 `NOT(IN(a))` 覆盖 `NOT(IN(a,b))`，也无法证明同一字段的多个等值 OR 覆盖 IN 列表。反例先复现这些误拒绝。现在完整谓词仍先由 Identity SDK 校验、翻译和绑定实际主体／组织／业务事实，再证明有限正集合及排除关系。否定包含关系反向比较：排除较少值的范围更宽。SDK 的 `neq`、`not_in` 与显式 NOT 按相同 SQL 空值语义处理；跨主体引用继续分别绑定，未知、关系路径和不能证明的组合拒绝。没有通过 JSON 类型交集推断范围为空，避免 SQL 类型转换产生错误的空范围证明。

查询总数和游标位置仍描述原提供者的完整查询范围；保存的第一页可读并不足以放行总数。当前读者的拒绝范围必须包含在原提供者的拒绝范围内。四组真实 SQLite／ORM 场景覆盖显式否定、原生排除和双方不同表达形式：原提供者可读两条记录，读者初始范围更宽，能读准确原第一页／第二页；不能执行原提供者游标。读者随后收窄到第一页的一条记录，即使这条记录仍可读取，也拒绝原总数和第二页。

这些自定义行谓词由公开 SDK 策略夹具提供，读取确实经过真实 ORM／Record 服务；它们不计作真实 Identity 自定义行策略发布。当前生产 Identity 角色接口只发布已有 DataScope 类型，自定义表达式用于字段策略。实际账号链路另使用当前公开角色契约。

新增实际 Runtime 根场景使用两个独立 Identity 账号、真实角色、SQLite 和 Agent 工具委派。接收 Agent 从实际目录选择业务记录字段，依次执行姓名 IN、姓名 NOT IN、余额下限和上限四项 AND 筛选，核对原第一页的 Alpha／10、总数 3 及游标，再用该游标读取 Beta／20 的第二页。模型继续从实际第一页和目录选择详情及关联查询，五份准确原回执自动交付、程序核对和账号验收；任务预算保持 12 步／12 次调用／8192 字节／90 秒。

实际 RPC 检查直接使用交付页里的原证据和原 proof，不重新查询或签名来替代它。只读角色可授权原第一页／第二页，但公开查询入口按缺少执行权拒绝。给同一读者真实查询角色后，其自身的新查询通过，而另一账号的原游标按游标主体绑定拒绝；随后恢复只读角色。首次 RPC 反例把入口的执行拒绝误认为游标拒绝，失败记录保留，检查已按两个边界拆开。

实际账号场景还保持原执行角色、撤回其中的工具执行权，并同步持久配置及真实角色目录，确保重启不会恢复授权。原页／共享过程在首次发布、执行权撤回、重启和资料权限恢复后逐页核对 SHA；读者字段和原提供者资料角色撤回期间拒绝。另一账号仍不能访问原私有会话。

最终验证：完整授权宿主／transport 回归及针对性 race 已通过，包括四组 ORM 表达式混用。最终范围源码的复杂筛选／原游标实际 Agent 根和原七类业务回执 RPC 根均完整通过，分别为 155.88 秒和 9.53 秒；复杂场景四轮共 20 次原 SHA 核对。三根中间回归也完整通过，但编译早于原生排除范围补充，不能替代最终源码命令。命令、启动源码摘要、完整日志及历史失败见[本阶段证据](evidence/2026-09-14-c05-query-exclusions-cursor/acceptance.json)。

上阶段托管 Knowledge 完整实际 race 已通过，根场景 673.32 秒，原页 SHA 共 16 次。原 10 分钟超时记录不改写；后续只调整 Go 测试整体观察时限到 20 分钟，实际任务预算不变。未托管／默认来源的旧 race 命令最终发生整体 10 分钟超时，其中未托管根通过、默认根未完成，整条命令记失败；确认原进程结束后启动的 20 分钟观察命令已完整通过，两根分别为 421.41 秒和 232.53 秒，共 28 次原 SHA 核对。这些 Knowledge race 的编译早于本阶段业务范围改动，验证原阶段的 Knowledge 链路，不能替代本阶段最终授权宿主 race。
