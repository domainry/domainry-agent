# C05：业务动作与流程的实际 Agent 委派

接续[业务原提供者与当前读者分离](testing-2026-09-14-c05-business-shared-readers.md)，补实际业务动作／流程工具委派、两次确认、自动交付与跨账号共享。整表仍为 **4／25**；C05 继续保留 Knowledge 用户绑定及其余明确待办。

Runtime 目录阅读新增来源持有的动作／流程契约阅读端口。实际读者按独立回执权限检查原提供者的 owner 范围；动作还要求对象可读。Host 复用现有目录投影，核对完整原 JSON 与当前公开契约，支持准确详情和目录分页；未知证明、已变契约或不可读的后续条目拒绝。普通执行权限仍保留原有目录查看能力，新增端口不授予动作／流程执行权，不读取调用账本。实际启动回执和流程状态继续核对原账本、准确参数以及当前参与人／关联记录范围。SDK 与 Agent 继续使用上一阶段的共享阅读端口，本阶段没有新增 RPC 或持久结构。

新真实 Runtime 根场景使用两个实际 Identity 用户、SQLite、Action／Workflow owner 和确定性模型决策：

- 发起账号仅有业务阅读与协作权限；模型实际调用 `agent_delegate`，用户批准准确委派。接收 Agent 按配置 owner 的真实账号和冻结角色执行。
- 接收方从实际动作／流程目录取得当前 execution version，分别请求准确客户创建和流程启动确认。发起方访问私有确认入口返回 404；委派明确授予接收用户 view／manage 后，由真实执行用户批准。两次原批准请求重试不重复效果。
- 确认前没有客户创建或流程启动效果；确认后实际新增客户和流程各一。流程启动仅为 accepted，程序约定明确要求 accepted；实际流程仍 waiting，审批任务为 open。
- 接收模型实际调用 `delegation_update` 自动交付五份原回执。发起账号检查程序验证和原回执后明确验收，八步共享过程没有 interaction／write scope 控制信息。
- 五份原执行结果分别为 3–4 页；按 256 字节分页拼接，完整 SHA-256 匹配准确原引用。初次共享、撤回执行权限后和重启后共三次核对。
- 使用嵌入式 Runtime 同一可信 ProjectRoleCatalogPublisher 端口撤回原执行角色的动作／流程／Agent 工具执行权限，保留该角色身份、资料与回执授权；保存相同项目配置，重启不能恢复撤回的执行权。实际动作／启动授权拒绝，原交付和共享页仍可读。
- 发起读者仅有自身 owner 回执范围、资料阅读撤回、原执行用户角色撤回时，旧交付页和共享过程拒绝；恢复后原效果仍各一，审批任务保持 open，私有会话仍返回 404。

任务预算为 12 步／12 次调用／8192 字节／90 秒，与上一阶段实际业务读取夹具相同。完整执行为五次业务调用、约定读取、交付提交和最终答复，共八步。没有调整既有专业写入的 60 秒预算，没有新增前端或外部模型验收。
