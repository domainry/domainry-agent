# C05：历史与执行记录的独立来源读取

日期：2026-09-13。接续[任务回执读取](testing-2026-09-13-c05-task-result-reading.md)，本阶段覆盖 `history_search`、`history_read`、`execution_read` 和 `tool_result_read`。整体仍为 **4／25**；C05 尚有计划工具的独立回执读取和跨用户／角色主体协作。

## 读取策略

四种包装结果复用 Agent 原执行账本核对：当前交付权限、工具启用、实际用户拥有的原会话，以及完整调用、定义、幂等键和结果。只对明确提交的交付启用独立来源读取，普通工具调用和普通原结果入口保留原授权。

历史消息及执行索引本身是执行资料。即使指向同一委派，也必须通过当前 `execution_read`，不能使用较窄的交付来源核对例外。读取原消息时使用实际用户的 History owner 接口，核对会话／消息／运行、角色、序号、时间和原文片段；assistant 消息继续检查其原运行的资料来源。检索结果逐项核对保存的命中记录，不因后来增加消息而替换旧页或再次搜索。明确指定私有会话的空页也检查来源存在性和读取权限。

`history_read` 核对原 UTF-8 字节位置、边界和结束标记。`tool_result_read` 对照原结果摘要与完整序列化字节，保留原分页边界；当前模型上下文预算变化不会重切旧页。嵌套结果仍递归核对实际来源；读取同一运行更早的完成调用允许，当前／未来调用引用拒绝。

执行索引的每项投影与实际原执行记录相符，包含状态、调用位置、资源 ID 和原结果引用。投影逻辑与实际 `execution_read` 共用，原记录变化则拒绝旧项。未完成或错误结果没有独立完成回执，继续使用既有执行与来源授权，不通过忽略失败输出的普通来源分支放行。索引为空时仍核对实际运行归属和来源权限。

原始协作结果不能通过包装为结果片段或索引获得交付来源例外。历史摘要和任务详情还可能间接包含协作消息，因此增加内部读取上下文：保留独立业务／个人资料读取，但其来源中的原始通信和执行内容必须按当前协作权限核对。该上下文使用独立的本次读取缓存，与已有来源遍历共享循环检测，避免先核对交付来源后复用较宽的已缓存判断。

全部路径只读，保留私有附件隔离、工具停用及超时／取消处理，没有新 SDK／RPC 契约、数据库迁移、生产前端或执行行为变更。

## 验证

- 四类结果的原调用、当前用户、来源存在性、原文／片段／执行条目、UTF-8 分页、工具停用、执行读取撤权、私有附件及取消检查。
- 原始协作结果分别经过四类包装，先缓存同委派的合法交付来源核对，再读取原始内容，仍因缺少通信权限拒绝；恢复当前通信读取权限后允许。任务详情覆盖同样的间接通信来源边界。
- 私有来源空页依然受权；同一运行更早的结果可读，当前和未来结果拒绝。
- 真实 Agent、Identity、SQLite、HTTP 和 worker 生成原日期与长文本说明，再实际执行四类读取和二层结果读取。五份回执明确提交为交付；撤回所有个人工具执行权限后，只保留当前协作资料读取权限，当前／历史交付的原结果和原片段均可读。停用原工具或撤回私有执行读取权限则隐藏；普通原结果入口继续拒绝。恢复并重启宿主后原值不变，原日期工具仍只执行一次。
- 原有任务交付／取消／恢复场景和大型结果压缩分页 HTTP 场景回归通过。命令、最终检查和源码摘要见[证据](evidence/2026-09-13-c05-history-result-reading/commands.md)。

## 目录复核与剩余项

`internal/assembly/web/schedule_tools.go` 在启用计划工具时装配 Tools 的 `scheduletools.Adapter`。当前该适配器的 `Register` 仅设置 `AuthorizeResult`，没有 `AuthorizeResultRead`，因此 `schedule_create/list/get/update/pause/resume/delete` 仍回退到原执行授权。它们是受支持的产品工具，应补 Scheduler owner 的独立回执策略；不将其含混归入自定义扩展例外。

跨用户／角色执行主体仍未实现，不通过替换读取者 UserID 取得来源权限。自定义来源未声明独立读取端口时继续采用既有严格授权。先前记录的 Runtime 发布模块锁与工作区契约差异仍待联合发布核对。
