# C05 组合业务阅读范围

Runtime 现有业务原页阅读按提供者的完整原查询范围授权，总数和游标不能仅靠可见首行放行。原实现分别比较 allow／deny，无法合并多个读者规则，也没有利用提供者 deny 对完整产生范围的收窄。

保留原快速证明，失败后对 SDK 已编译过滤器做有界组合证明。提供者范围为 allow 的 OR、所有 NOT(deny) 和原查询的 AND；读者范围独立保留自己的 allow／deny。每个原子分别保留提供者、读者或查询字面值绑定上下文，不修改 Identity 主体，也不调用新的执行或阅读端口。

将 NOT 按 SQL 三值布尔语义移至原子，支持双重否定及 De Morgan；IN 分解为相应等值分支，NOT IN 分解为否定等值的 AND。NULL 等值及其否定均不匹配 WHERE；缺失业务 claim 先按 SDK 原生 FALSE 处理，再处理外层 NOT，避免把原生 neq／not_in 的缺失 claim 错转为 TRUE。列表中看似 $subject／$context 的字面值通过无身份、无 grants 的本地上下文绑定，不能重新解释为当前读者 claim。

只删除准确绑定的 P AND NOT(P)，不按不同 JSON 类型或字面值推断范围为空。SQLite 类型转换和 NOCASE 排序规则的实际反例仍拒绝。每次证明最多 64 分支、每分支 64 原子、4096 节点、24 层深度及 4096 次非缓存原子比较；比较缓存只存在于当前证明。超限、关系路径或 SDK 不可翻译的完整树不获得新阅读权限。

最终完整授权宿主正常／race 各 62 个根、151 个子场景通过；新增 3 根／29 子场景。其中五类实际 ORM 原总数／游标场景覆盖多条 allow、原查询在不同 conjunction 间分项覆盖、提供者 deny 收窄、多个 deny 合并、双重否定及 De Morgan。每类都验证原页阅读、撤权后可见首行与完整原范围分离、恢复及原证据字节不变。校正后的原生产 overlay 五类全部失败，这是能力缺口，不记作资料泄漏。

另外十八类直接执行 SDK 生成的实际 SQLite SQL，验证 NULL、缺失 claim、主体隔离、查询与提供者绑定、claim 字面值、类型转换、NOCASE、准确矛盾及否定前缀。检查使用 reader IS NOT TRUE，UNKNOWN 也计为读者排除，避免 NOT(reader) 丢失 NULL 反例。六类完整树／资源界限检查保持拒绝。

真实独立业务 RPC 正常根 3.61 秒通过，覆盖六份原业务回执、执行授权分离、伪造／撤权／重启。真实跨账号复杂筛选 Agent 根 133.50 秒通过，含五份专业原回执、八步共享执行、原查询游标与实际查询执行分离、自动交付、账户验收、资料／字段撤权、专业执行权限撤回、重启及 20 次原 SHA 核对。原委派任务 90 秒预算保持；这是既有实际场景的最终生产版本回归，不能称为新增任意谓词的实际 Identity 配置验收。当前 RolePermission 只有预设 DataScope 字段，不能直接通过该入口配置本阶段测试中的任意 allow 谓词。

6084／9893 份最终保守依赖输入清单及前后源码、完整补丁、反例、最终宿主日志和实际正常日志按阶段归档。实际正常启动后的保守上集中有一份未编译的依赖包测试源码补充了比较预算场景；实际编译的生产与根测试输入保持，启动／最终清单及差异分类分别保存，不能声称原保守上集零变化。

同一最终生产版本的实际 race 初次在外层 90 秒观察结束时任务仍运行，不记作任务失败；[延长外层观察后的真实终态](testing-2026-09-14-c05-business-union-race-terminal.md)证明委派运行 90059 毫秒后因原 90 秒任务预算失败，六次读取完成，第七次交付调用失败，新版交付和账户验收未完成。阶段证据见[归档清单](evidence/2026-09-14-c05-business-union-scope/index.json)。更完整关系／查询范围、其他专业来源、完整旧生命周期的实际预算失败、账号写入包观察失败、其余依赖／退出联动及发布锁同步继续按原 C05 范围处理，C05 和整表仍为 4／25。
