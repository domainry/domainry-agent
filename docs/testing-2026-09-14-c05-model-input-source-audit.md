# C05：模型请求前的协作回执来源审计

日期：2026-09-14。完整 C05 继续待办，整表保持 **4／25**。

当前模型请求前会先遍历整份运行来源，随后逐份授权前序工具回执。原生协作结果检查器本身再次完整遍历该回执的来源，形成重复审计。现在先核对前序模型步骤与准确工具回执，再将本运行、原身份相同、定义及完成状态一致的协作回执交给后续完整检查；其余来源继续正常遍历。

原生协作检查器执行完整来源审计及当前会话／委派归属检查。自定义宿主未调用原生检查器时，Agent 在普通工具／结果授权后补做完整来源审计。每份待复核记录只属于本次模型输入检查，不跨模型请求或公开读取保存授权决定。

待复核记录绑定实际服务、运行、身份、完整回执摘要和调用方来源范围。原遍历建立的来源、父身份及 Agent 配置值在复核时保留，取消和期限使用当前请求。发布／原始执行等读取范围变化、不同 Agent 配置、旧或未知角色、继承运行、有限前缀、变化或未被前序调用采用的回执继续完整检查。扩展提出更严格的原生检查时保留该检查；原生检查失败会记录到当前输入检查中，扩展丢弃错误也不能借之前的完成标记放行。

增加前序模型步骤编号和工具回执步骤编号一致性检查。模型步骤缺失、结果缺失、调用缺失、结果未完成或原参数不匹配仍拒绝进入模型。
