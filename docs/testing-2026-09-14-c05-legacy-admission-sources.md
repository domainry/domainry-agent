# C05：旧接单要求根与历史来源分页身份

日期：2026-09-14。接续[旧发布角色恢复](testing-2026-09-14-c05-legacy-source-publishers.md)。本阶段继续 C05，整表仍为 4／25。

## 当前实现

- 旧约定历史不重复保存 `requirements.sources`。初始约定的可信 `ChangeSource` 定位原接单步骤；只有该步骤中已完成的 `agent_delegate`、返回的准确委派 ID 和原参数中逐份明确声明的来源根，能恢复对应发布者。当前要求根或当前 Agent 配置不能补造历史声明。
- 仍按原运行不可变身份恢复发布角色，原专业提供者独立保留。读取投影不修改旧发布 JSON、ID 或约定／工具账本；不恢复人工历史没有记录的角色。
- 交付回执分页入口在解析账本前限定准确委派 ID、`delivery` 用途和已提交原回执前缀。仅有约定、消息、其他委派或未知发布者记录时拒绝，不能用另一类授权代替交付发布。
- 保存的委派来源分页核对原运行的不可变身份与原 Agent 角色。历史任务属于该委派的原接单记录时，后来的执行角色不替换原证明；当前读者资料策略继续独立检查。实时调用仍要求当前接收会话和当前准确执行主体，历史读取不授予调用权。

## 验证范围

存储用例覆盖原接单声明恢复、当前要求根改变不替代原声明、未声明根、其他委派、未完成调用、其他步骤／操作及人工历史不恢复角色。交付入口用例覆盖其他用途／委派和未知发布者在访问结果存储前拒绝，准确交付发布保留独立资料阅读。

历史分页应用用例使用服务端接单记录和不可变运行头：切换到另一接单角色后原页仍按原身份与当前读者读取；没有接单关联、原 Agent 角色与运行头矛盾、在原历史会话实时调用均拒绝。此处是应用用例，不声明跨主体实际转交已验收。

真实 Runtime 场景先产生原报表与分析结果，再经 Agent 工具明确委派、分页阅读、自动交付及账号明确验收。关闭 Runtime 后同时将真实约定要求根和交付来源发布转换为旧格式；原接单调用、原专业结果和不可变历史保持。重新打开后的两个原值、另一资料阅读角色、保存的来源页、发布者／原提供者／字段撤权继续核对，覆盖旧要求根的原接单恢复。数据库为 SQLite，模型为确定性 wire。

最终验证通过：8 个核心／SDK／传输包、2 个 race 包、2 项真实 HTTP 协作场景和 4 项 Runtime 场景；69 份源码摘要与验证版本一致。准确命令、完整日志、工作区和当前源码摘要见[本阶段证据](evidence/2026-09-14-c05-legacy-admission-sources/commands.md)。完整 C05 尚未验收。
