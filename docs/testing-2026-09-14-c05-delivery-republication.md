# C05：原交付预览与明确重新共享

日期：2026-09-14。接续[旧接单来源身份](testing-2026-09-14-c05-legacy-admission-sources.md)。本阶段补交付重新共享，整表仍为 4／25。

## 当前实现

- 新增原交付版本索引和预览接口，SDK／HTTP／Module／SaaS 贯通。索引只返回记录版本、类型及约定版本，不返回旧正文、依据或证据；正文在预览时按当前身份与逐根来源授权核对。
- 当前记录及准确历史提交／核对／验收记录均可选取。预览核对实际执行用户、当前查看／接收／阅读／共享权限、不可变提供者和当前资料范围；缺少原运行身份或来源核对端口时阻止预览。不能用当前配置补造旧发布身份。
- `republish_delivery` 只接收准确原记录版本、摘要和预览时的委派版本。提交重新核对权限与原结果，事务内重新选取原记录、比较摘要和版本，保存本次实际发布用户／角色及明确来源授权。
- 已验收、旧要求和已关闭任务的历史发布不执行任务、不改变原交付／核对／验收结论、任务状态、原决定或约定版本。新增不可变发布审计记录，原提交和验收历史保持；提交返回窄范围发布回执。
- 页面可选择当前或历史记录、预览原文和接收用户、填写说明并明确共享。关闭或撤权清掉预览。响应丢失时保留原请求版本、摘要与请求 ID；页面刷新后仍可按原请求重试，避免把已提交操作当成新发布。
- 交付历史显示本次实际发布用户／角色、原记录版本和发布时间，保留原验收者的核对记录，能分别追溯本次共享和原验收。

## 验证范围

应用用例覆盖版本索引不泄露正文、缺少来源端口、预览不发布、预览后来源／原专业角色撤权、伪造原摘要、错误发布用户及窄回执。存储用例覆盖已验收状态、原任务／决定／交付／核对／历史不变、原提供者与实际发布角色分别保存、错误版本／摘要／正文／主体回滚、准确重试单条审计及未知旧发布记录不被改写。

真实 Runtime 用例先通过实际工具产生不同旧角色的完整报表与分析原结果，两个原值均为 70，再由账号提交和验收。停止夹具后只把实际交付发布转换为缺少 `Publisher` 的旧格式，不改原工具账本与交付历史。重新打开后旧回执拒绝；版本索引可选、预览保留原值且不产生授权；当前字段／原角色撤权阻止提交；明确重新共享后恢复原回执阅读，原验收历史保持，重复提交只有一条审计，撤回发布角色与再次重启继续验证。

真实 Identity／Agent HTTP 浏览器用例覆盖已验收原时钟交付选择、预览、明确共享、服务端提交成功但响应丢失、刷新后保留准确版本／摘要／请求 ID 重试、单条审计、实际发布身份展示、撤权隐藏、恢复及桌面／窄屏。另以客户端 DTO 回放验证旧未核对记录的空数组兼容；未使用旧格式浏览器数据库。

最终通过 8 个核心／SDK／传输包、2 个 race 包、1 项真实 Runtime 场景、1 项真实 HTTP 浏览器流程、73 项前端测试和前端构建。98 份源码及构建文件摘要与最终验证版本一致。

数据库覆盖 SQLite，模型为确定性 wire；其他数据库及在线模型不在本阶段验收范围。多所有者来源、旧约定完整接单流程、参与者更多范围、完整执行详情、跨主体转交及主体退出继续归 C05，未将本阶段视为完整 C05 验收。
