## 代码边界和实际行为

- 公共契约为 Agent SDK 的 `KnowledgeDocumentTransferService`。`internal/application/knowledge_document_transfer.go` 只通过 SDK 端口做授权、原件读取与目标登记；远端调用由既有 Provider / Connector 完成，应用层不直接依赖 Connector 或数据库实现。
- 源下载、目标复制／移动动作和目标上传分别授权。移动额外检查源删除权限；存储事务再次检查两侧当前成员、归档状态、来源版本、文件摘要与字节数。
- 目标是独立文档，有独立原件、远端文档 ID、请求 ID 和目标库权限摘要。复制保留源文件；移动在目标原件持久保存后，将目标发布与源状态变为 `deleting` 放在同一事务中。失败回滚不能只删除源文件。
- 原位置一旦进入 `deleting` 就不再下载或作为检索来源，即使知识服务还返回旧索引片段。目标入库和源远端删除通过既有持久任务继续；私有删除仍要求确认回执，不能仅凭 fetch 不可见判定删除完成。
- 完成的移动回执可按原请求编号恢复，不需要重新读取已删除或已撤权的源文件。回执仍要求当前目标库写权限和对应 Identity 动作；改变来源或模式会幂等冲突。来源关系只存在服务端持久记录中，不出现在目标库普通文档列表里。
- 没有新增原文件解析、正文缓存或索引实现；复制的是已经授权的原件字节，知识索引沿用 Connector。

## 本批修复

`KnowledgeDocumentTransferDialog.tsx` 原先始终要求目标库 `documents_configured`，导致已成功移动但响应丢失后，知识源临时失效就无法点击“核对上次操作”。现在 `document-transfer-state.ts` 允许固定目标的已有回执继续核对；新操作仍要求配置可用，阅读者、归档库和同库目标仍拒绝。最终状态由同一个后端复制／移动操作返回，不新增绕过权限的恢复接口。

## 本批验证

1. `TestKnowledgeDocumentTransferAtomicRetirementAndRecovery` 五项事务场景通过：目标版本冲突时源删除回滚，源先删除、源成员撤销、目标成员撤销、两次竞争移动。另验证成功移动的两侧原子切换、目标独立 ACL / 远端 ID、重建 Repository 后回执恢复、变更请求冲突和私有来源不外泄。
2. `TestKnowledgeDocumentTransferSaaSScopesRecoveryAndStaleSearch` 通过实际 SaaS 服务 / 客户端、SQLite、原件存储和官方 Connector 的 HTTP 协议完成个人 → 共享复制、共享 → 个人移动。协议夹具核对两套不同私有 ACL 请求头和持久请求 ID；共享读者不能读取个人原件，旧索引片段在移动后不进入模型输入。
3. 远端实际受理目标上传后返回 503，Agent 保存 `needs_reconcile`。关闭并重开应用服务与 SaaS 绑定，沿用持久化的 30 秒重试时间，目标随后变为 ready；原请求回执可恢复，未重复 PUT。三份合成远端文档各一次 PUT / DELETE，源原件实际清理。专项 30.39 秒通过；相关 race 通过（持久层包 2.661 秒，integration 包 34.237 秒）。
4. 网页使用实际 Identity 登录、Module / HTTP / SQLite、产品构建和文件存储。通过个人库明确复制到共享库、复制动作撤权 / 恢复、下载字节一致、原件与副本独立删除，以及共享库移动到个人库的可见范围确认。
5. 浏览器故意丢弃已经成功的移动响应，完整重启 Web 宿主并移除知识源配置。刷新后从资料库窗口找到待确认操作，以完全相同的请求恢复同一个目标 ID；此时源已不能下载，目标原件仍可下载且字节一致。恢复知识源配置后，真实后台重试完成索引，再由网页删除目标；宿主核对所有合成远端文档均各写 / 删一次并已清理。
6. 首轮四项界面基线（复制桌面 / 手机、移动桌面、回执恢复手机）均无质量错误或页面横向溢出，浏览器无异常和外部请求。人工检查手机恢复弹窗。最终剩余项网页报告 `complete: true`，宿主测试 69.54 秒（包 70.032 秒）通过。
7. 前端 36 项测试、生产构建、架构边界测试、相关 Go vet、脚本语法和差异空白检查通过。没有重复跑此前已通过的全量 Agent / SDK 测试。

## 失败记录和复验范围

- 首次 SaaS 测试编译错误是新脚本误将 `ConversationRun` 当作包装回执；修正为实际 SDK 返回值。第二次最后的多文档检索运行失败；协议夹具原先遍历 map 返回不稳定顺序，改为稳定排序后专项及 race 均通过。两次失败日志保留。
- 首轮完整网页验收在知识源恢复后的索引等待超时：测试只等 20 秒，后端不可用重试保存的是 30 秒。四项界面基线和此前业务断言已通过，末尾清理未完成，首轮浏览器和宿主均保留为失败。
- 第一次定向复验遇到测试脚本局部变量遮蔽，尚未执行剩余恢复段；修正变量名。第二次定向复验只重新准备移动所需数据并验证恢复、索引和清理，等待上限 45 秒覆盖后台重试及网页轮询，没有改写后台调度。先前通过的界面检查没有重复执行。
- 未调用真实 Verdent；外部知识服务使用本地合成协议夹具。此证据不能替代实际私有 KB 的迁移验收。
