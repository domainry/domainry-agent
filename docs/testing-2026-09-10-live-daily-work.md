## 复现

```sh
python3 scripts/test-agent-live.py
# 自动流程完成后，继续开放当前前端供浏览器验收：
python3 scripts/test-agent-live.py --browser
# 选择已验证支持 Responses 的 Verdent 模型进行对照：
AGENT_CONVERSATION_MODEL=gpt-5.6-sol AGENT_CONVERSATION_PROTOCOL=responses python3 scripts/test-agent-live.py --browser
```

启动器读取仓库外的 `web-services.json` 中非敏感模型配置，或使用现有进程环境；未提供密钥时通过终端隐藏输入读取，不写入文件。真实模型请求仅在显式运行该脚本或设置 `AGENT_DAILY_WORK_LIVE=1` 时发生，普通 Go 测试默认跳过。

启动器打印本次私有执行证据目录，保存合成验收数据对应的公开 Run 投影（实际工具参数、结果、状态和模型最终回复），用于失败后核对。该目录不保存 API Key、原始网络响应或完整模型输入。可以通过 `AGENT_LIVE_EVIDENCE_DIR` 指定目录。

数据库、Identity 用户和生成的待办 / 记忆 / 成果均在临时测试宿主中创建，不修改现有部署的数据或权限。`--browser` 使用 8092 端口和当前 `frontend/dist`；页面标明实际模型名称，验收后关闭临时服务。

## 场景与判断依据

1. 在原始会话讨论三项“青禾发布事项”，仅讨论，不保存待办。
2. 新建工作会话，通过真实模型检索并读取原始讨论，按原顺序创建一批待办；检查数据库返回的三个标题、批次、原始位置、时区和状态。
3. 让模型把第二项改到本周五；必须查询可信时间，检查实际第二项的截止日期和修订号。
4. 明确要求保存周报三节格式；检查启用的个人记忆确实写入。
5. 根据事项和偏好创建 Markdown 周报；检查保存的成果 ID、版本和三节标题。
6. 完全关闭并重新打开 Identity / Agent 宿主，复用同一 SQLite；重新登录，在新会话完成原第二项，并找回周报偏好。
7. 修改原周报第二节；检查同一成果版本更新、其他节保留、原始版本不变。
8. 通过模型导出版本 1，经受权下载接口读取文件，与原始保存内容逐字节比较。

断言以真实存储结果为主，不固定每一步的工具顺序。模型可在已失败的调用后读取实际状态并纠正参数；失败调用不会被当成已完成效果。真实模型端到端与真实知识文档验收分别记录，本测试不接知识服务。
