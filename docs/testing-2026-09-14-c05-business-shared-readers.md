# C05：业务原提供者与当前读者分离

本阶段接续[跨账号专业写入](testing-2026-09-14-c05-professional-writes.md)中七项业务回执的用户绑定失败，继续完整 C05。整表验收仍为 **4／25**。

Agent 在明确发布的来源内，从准确原运行恢复证据提供者，按原提供者核对业务来源和 scope 指纹；当前读者仍是请求身份。新增可选 `ConversationBusinessSharedResultReadSource` 和 `business_shared_result_read` RPC，传入原证据、实际读者与独立的提供者。参数和原 JSON 保持不变，模型不能选择执行用户或角色。相同身份沿用旧端口；同用户不同角色优先走共享端口，旧用户绑定来源保留现有当前角色检查。明确拒绝不回退；未支持跨用户的来源保留原执行授权路径。

Runtime 为目录、查询、记录详情、关联查询、流程状态、动作与流程启动回执分别实施当前阅读检查。记录读取验证完整原签名或准确原值，再检查双方当前资料权限、每个保存的记录及读者字段隐藏／遮罩。原游标按提供者核对，读者只验证相同字段／筛选／排序，不获得使用原游标执行查询的权利。查询总数和分页要求读者的当前范围覆盖提供者范围；使用 Identity SDK 编译并绑定的主体／组织／业务事实比较相同谓词、AND／OR 包含和等值／集合范围，保留读者拒绝项。未能证明覆盖的表达式拒绝，不仅凭可读的第一页放行。

动作 owner 新增只读 `ReadSharedInvocationReceipt`，流程 owner 新增只读 `ReadSharedAgentWorkflowReceipt`。原提供者定位 actor 绑定的准确账本和请求指纹，实际读者的回执范围针对原 actor 求值，并核对所有记录引用或当前流程参与范围。Host 同时检查原提供者的当前资料／回执权限；不授予 RunAs，不执行、恢复、索取执行租约或消费批准。流程有相关记录时继续检查记录权；没有相关记录的流程保持自身的参与范围。

新记录和流程快照的 opaque proof 分别为 `2`、`workflow2`：签名绑定有效读取策略、主体／业务上下文和可读对象字段，去掉执行／写入／导出策略与解析到期／版本噪声。工具执行权撤回后，普通值或状态更新不替换原回执。旧 `1`／`workflow1` 签名仍校验原 MAC，并保留原有效策略／准确当前投影回退。证据 JSON 版本仍为 1，无新持久结构。SDK RPC 方法描述符 SHA 已协调更新；严格部署须同步使用新的客户端／服务端 pin。

已验证：

- Agent 应用和完整 SDK；Runtime Action、Workflow、AgentHost 三个完整包通过。
- Agent 两个业务交付 HTTP 根场景通过，覆盖既有独立业务回执读取与原写入回执阅读。
- Agent／SDK 和 Runtime 针对性 race 通过，覆盖七项原身份、同用户不同角色、原值与游标、源／读者撤权、可读第一页但不可读总数、101 项动作引用、实际流程参与人和无执行效果。
- 四个真实 Runtime 根场景通过。其中新 RPC 场景使用独立真实账号、Identity／SQLite／Action／Workflow owner，读取七类原回执（查询含原游标第二页），核对自有回执范围拒绝外国 actor、读者字段／资料撤权、原角色撤回／恢复及重启。RPC 写入使用既有显式确认夹具，此场景不计作 Agent 工具批准或自动交付验收。
- 新真实 Agent 场景由模型调用 `agent_delegate`，用户批准准确委派；接收方按配置 owner 的当前 `headquarters_admin` 执行四项业务读取，再实际 `delegation_update` 自动交付。账号核对原页及程序验证后验收。明确执行发布、七步共享过程、四份结果分别为 3–5 页，完整字节 SHA-256 匹配原引用；重启后再次通过；读者字段和原执行角色撤回使旧页及共享过程不可读，双方私有会话仍隔离。

新增模型是确定性夹具，没有外部模型服务。Agent 实际业务读取任务预算为 12 步／12 次工具／8192 字节／90 秒，与本批接续的专业委派夹具一致；未调整已有写入任务的 60 秒预算。没有新增前端验收。

保留了首次 RPC 描述符 pin 失败、旧执行绑定预期、夹具非法 all 谓词、关联记录来源范围和无关联流程预期错误等失败记录；失败不计通过。上一阶段业务七项 before proof 和专业写入并发执行超时的原记录保持。

证据：[接受记录](evidence/2026-09-14-c05-business-shared-readers/acceptance.json)。完整 C05 仍需业务动作／流程来源的实际 Agent 工具委派共享和自动交付、更完整的查询表达式范围、Knowledge 用户绑定来源、其他明确来源／旧角色及历史／依赖／退出范围。上一阶段专业写入 race 的执行超时仍未验收，不能凭本批只读 race 计为通过。
