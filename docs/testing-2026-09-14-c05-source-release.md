# C05：跨主体来源发布与 Agent 自动交付

日期：2026-09-14。接续[接收方执行身份绑定](testing-2026-09-14-c05-delegation-execution-binding.md)。当前验证覆盖本部署内、已明确绑定接收角色的两用户协作，以及内置时钟来源的工具委派、Agent 消息和自动交付。**C05 仍未完整验收，整表仍为 4／25。**

## 当前实现

- 来源核对分别保存实际读者与原执行主体。原执行主体只用于定位已发布文字的不可变原运行／工具账本；当前资料与工具结果阅读策略继续使用实际读者。普通会话、任务、运行和结果入口仍按原归属检查。
- 内部来源发布契约记录具体委派、用途、原执行身份与角色，以及准确会话／运行／步骤前缀。浏览器和模型不能提交来源授权主体。用途覆盖约定、消息和交付。
- 发布与对应约定／消息／交付使用同一数据库事务，重新打开仓库后仍可核对。迁移 28 的 `_agent_source_releases` 通过宿主迁移记录和 ORM 建立；索引按实际读者及准确运行／前缀查询。来源发布不会修改原会话的归属。
- 接收方检查 Agent 生成的约定／输入，消息消费检查其来源，交付投影、历史、原回执阅读和验收接入明确来源范围。读取时复核工作空间、当前成员、原发布角色的共享权限和读者对该项委派的实际权限。
- 前缀发布不能扩展为整个运行或后续步骤。成果正文入口另检查原回执是否明确出现在该版本交付中，随后核对原调用、状态与摘要；仅持有运行级证据引用不允许读取其中任意调用的正文。
- 主体数据清理对新增来源表同时覆盖读者与发布者索引。发布者退出时，存放在其他读者下的来源记录也移除；该处理不代表其他跨主体生命周期范围已经完成。

## 验证结果

真实 Identity、HTTP、SQLite 与模型工具夹具中，发起账号没有接收权限和时钟工具权限，接收账号明确绑定自己的角色并共享配置。发起 Agent 通过 `agent_delegate` 发起工作，测试账号完成该调用所要求的操作确认。接收 Agent 实际调用 `time_now`、查询约定、发送带原来源的消息，再通过工具自动提交真实时钟回执。

发起账号能读取该项自动交付、准确原回执并通过 HTTP 验收；验收操作是发起账号提交，不声明发起 Agent 已自主决定验收。重启后回执仍能读取。双方普通私有会话入口返回 404，未提交的调用引用返回 403。撤回读者的 `delivery_read` 或发布者的 `share` 后，已有成果回执返回 403。

应用边界用例验证：原计算回执可独立核对，已核实的私有 Todo 回执仍按实际读者检查，来源上下文不能换读者，撤回发布角色权限后拒绝，同一用户也不能绕过工作空间边界，以及前缀不能扩展。存储用例验证准确身份／用途、前缀、幂等、重新打开仓库、普通原运行隔离、发布者清理及事务失败没有残留部分授权。

应用与存储完整回归、原双主体执行绑定 HTTP 场景、新增来源 HTTP 场景，以及新增边界的 race 检查通过。命令、原始结果、源文件摘要和范围记录见[本轮证据](evidence/2026-09-14-c05-source-release/commands.md)。

## 剩余范围

本轮跨主体自动交付验证使用内置时钟。其他专业来源仍需独立处理原提供者凭证与实际读者的数据权限；私有记忆、Todo、附件、历史与执行正文不会因为来源发布自动获得共享授权。未知自定义来源继续保留原授权检查。

多所有者依赖、跨主体转交、参与者管理与执行／交付范围、完整执行详情共享、跨主体角色与配置授权的全部退出处理，以及全目标预算仍待完成。新增迁移覆盖三种方言的结构渲染，实际数据库验收仅覆盖 SQLite。
