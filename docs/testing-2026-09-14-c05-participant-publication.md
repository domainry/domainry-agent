# C05：参与人授权身份与准确约定来源

日期：2026-09-14。接续[资料失权时的委派管理入口](testing-2026-09-14-c05-recovery-controls.md)。本阶段补强已有参与人查看／沟通范围的授权与来源边界；完整 C05 仍待完成，整表仍为 **4／25**。

参与人名单现在保存实际授权人的 Runtime、Workspace、用户和角色。客户端只提交接收用户和范围，不能选择授权身份。读取和消息进入模型时，先检查实际授权人仍是当前成员且该角色仍有共享权，再用实际读者／发送者的当前 Identity 角色与这条委派的授予范围取交集。原任务仍使用已绑定的接收执行身份。没有授权身份的旧名单不猜测今天的角色；所有者明确重新共享后记录新的授权身份及授权版本。

新增共享先读取准确的不可变约定来源，逐项检查当前原提供者与实际发布者权限，然后在名单保存事务中记录对应约定的来源发布；读取时另检查实际读者的当前权限。引用只覆盖原运行的准确前缀，不开放原私有会话或之后的执行步骤。来源审查使用冻结的要求根、输入／要求来源和依赖来源，避免今天记录缺少要求根时漏检。原来源撤权时隐藏派生约定；参与人的隐藏响应也移除私有发起／执行会话 ID。

明确重新共享使用本次操作人的角色审查原资料，不要求借用已撤权的旧发布角色。缩小范围或移出名单不依赖读取旧约定，保留剩余范围原有的授权身份；它不会把撤权操作变成另一个角色的重新发布。改变实际授权角色会产生新的授权版本，旧版本尚未消费的参与人消息失效，原内容和原回执保留。新增共享缺少准确原约定时整笔回滚。

准确修复前的生产文件保存在 `source-before-prospective-fix/testdata`，避免证据文件被普通 Go 包扫描。当前完整测试夹具配合 [Go overlay](evidence/2026-09-14-c05-participant-publication/before-overlay.json) 重现两项问题：首次新共享误用已失权发布者，以及缩小范围误改授权角色。旧测试中的约定版本不匹配、夹具缺少参与人 Repository 方法和最初未留完整源码检查点的诊断失败分别保留，不作为准确修复前状态的验收依据。

当前 Agent／SDK 八个包通过，两个包的相关 race 场景通过。真实 SQLite、Identity、HTTP 和 Chrome 双账号场景通过，用时 **18.09 秒**，浏览器错误为零。HTTP 验证当前授权角色共享权撤回后详情拒绝、目录隐藏，以及恢复权限后授权身份和授权版本保持；浏览器验证单项邀请、查看升级为沟通、实际发送身份、原任务消费、私有执行与管理隔离、390px 布局和移出名单后关闭详情／刷新仍不可访问。截图已检查。实现与夹具的 142 份源码、既有前端构建的 571 份资源及证据文件校验值已核对，准确结果见[证据](evidence/2026-09-14-c05-participant-publication/acceptance.json)。

本阶段前端与 Runtime 实现未修改，使用此前已验收的页面构建；没有重新运行 Runtime 集成场景。原资料来源边界的新增场景由应用／存储测试覆盖，真实 HTTP／浏览器场景使用确定性模型夹具。参与人操作仍仅开放 `view`、`communicate`；管理、执行／交付阅读范围、完整执行详情共享、多所有者旧来源／依赖、跨主体转交与退出等继续待办，不把本阶段基础加固记作 C05 完成。
