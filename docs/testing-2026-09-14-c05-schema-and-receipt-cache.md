# C05 授权投影与回执复核缓存

真实跨账号专业业务 Agent 场景在普通构建中能够自动交付，但在 `-race` 下会耗尽原任务的 90 秒预算。此前的终态证据表明，第七次 `delegation_update` 已成功，下一次模型步骤才被中断；因此这不是放宽任务预算或延长执行时间能验收的授权功能缺口，而是同一份授权事实被重复投影和复核造成的执行放大。

Runtime 的 `RecordSchemaSnapshotProvider` 现在按 schema generation 保存一份不可变基础快照，并按完整 Identity 策略包、系统范围和系统能力保存受权投影。元数据、Agent 元数据、Workflow 新增及删除都会推进 generation，并同时废弃基础快照和全部主体投影。权限包的到期时间作为缓存条目的上限，不再参与策略键；同策略的新权限包只能在旧条目的较早到期点之前复用。过期、撤权、字段／数据规则变化以及 schema 发布都不能命中旧投影。

基础 schema 和同一权限键的首次投影都在 provider 内合并冷建。并发请求不再重复做对象／字段／Action／Agent 可见性裁剪和完整 JSON 哈希。投影最多保存 256 项；达到上限后整体换代，避免无界主体缓存。缓存返回值视为不可变，Workflow 适配和多语言投影在改写切片前复制自己的派生结构，消除共享底层数组的数据竞争。

Agent 的完成回执复核按 `conversation_id + run_id` 合并来源前缀，只对该运行最大的 `BeforeStep` 做一次完整来源授权检查。每一份回执仍逐项读取准确 `step + call_id`，并核对完成状态和原结果 SHA-256。交付条件、验证条件、历史交付、转交历史和发布预览的调用点先汇总回执再进入复核，避免上层按条件逐次绕开合并。

定向测试验证 32 个并发主体请求只发布同一投影、权限刷新复用、到期拒绝、所有 schema 变更失效和 256 项边界；普通与 `-race` 均通过。Runtime 两个受影响包普通与 `-race` 各 85 个顶层测试通过，Agent application 包普通与 `-race` 各 141 个顶层测试通过。

最终真实普通场景中，独立所有者 RPC 为 1.93 秒，复杂 Agent 根由前一版 61.48 秒降到 17.81 秒。最终真实 `-race` 场景两个根均通过：Agent 在原 90 秒任务预算内完成五次专业读取和自动交付，随后完成账号验收、当前权限撤回、重启及二十次准确原页／SHA-256 复核。整个测试根的 262.37 秒包含任务完成后的多轮复核，不是任务预算。

前后 1,167 个依赖、9,895 个保守输入路径完全一致，最终仅 provider 和新缓存测试两个输入的哈希变化。两个仓库的准确阶段前后源码、可重建补丁、连续红例、最终普通／竞态日志、CPU profile 和输入清单见[证据归档](evidence/2026-09-14-c05-schema-and-receipt-cache/acceptance.json)。本阶段解决的是已验收跨账号业务共享链路的重复计算，并未补齐 C05 尚缺的全部授权与资料类型，整表仍为 4／25。
