# C05：Identity 停用与跨主体生命周期删除

日期：2026-09-14。接续[多所有者专业依赖来源](testing-2026-09-14-c05-multiple-owner-dependencies.md)。本阶段补真实账号停用／恢复、执行中身份失效以及 Runtime Lifecycle 删除链路。C05 的其余范围继续待办，整表仍为 **4／25**。

## 行为与修复

执行身份沿用现有 Identity 当前 principal 解析：读取原来源、接单及实际执行边界不使用过期会话权限。两个专业来源所有者分别保留原专业角色及实际发布角色，第三个账号 Agent 读取原回执、计算总额并提交经过程序核对的交付，由账号明确验收。

- 停用原分析提供者／发布者，相关保存页拒绝阅读；其余独立来源仍可核对。恢复账号并重新登录后原页恢复。停用接收账号后会话拒绝，匹配不能允许接单，直接发起委派也拒绝。
- 已进入模型请求的后台委派，在接收账号停用后返回合法的 `delegation_get` 调用，实际调用前重新核对身份并停止。恢复身份不自动重启已失败的任务；原运行没有成功工具回执。
- 永久删除通过实际 Runtime `/lifecycle/subjects` HTTP 请求，使用真实 Identity token、理由、确认和当前角色范围；提供夹具验证引用，预览实际 owner，由另一真实账号批准，再执行删除。请求者不能批准自己的请求。没有直接调用 Agent 删除接口替代 Lifecycle 装配。
- Lifecycle 实际调用 Identity、Agent、Knowledge、Todo、Data Exchange、Integration 等已装配 owner。删除账号不能登录，所属共享 Agent 不再出现在目录，接收方在途委派停止并保留对方可查看的退出元数据。Runtime 夹具为此场景选装真实 Data Exchange Factory，其他场景保留原装配。
- 删除上游约定后，整个已采用依赖图不能复核，两份下游包装页都拒绝阅读；所属账号自己的原报表运行继续逐字相同。当前下游交付标为待更新，不能继续当作有效依据；原交付与验收证明保留。

本阶段发现并修复两处存储问题：

1. 依赖失效原先会把已完成或失败的任务改成取消，并覆盖结束时间。现在只改变当前约定的有效性；终态任务保留准确原状态、结束时间、完成事件和运行引用，显式恢复仍走既有检查。
2. 主体清理按 map 顺序逐条传播依赖变更并清理消息，后续传播可能重新产生已清理委派的通知。删除后剩余账号的队列会反复遇到不存在的委派。现在在同一事务中先完成全部失效传播，再统一清理发布及未消费消息。剩余账号可以接单并启动独立工作。

使用真实 Lifecycle 导出／独立批准／下载核对持久数据：删除及重启前后，下游原任务和运行逐字一致；当前委派只增加来源明确的待更新记录，原约定版本、交付和验收证明保持。普通协作响应仍隐藏失效来源正文，治理导出不能被当作协作读取授权。

修复前，真实 Runtime 导出已经证明原任务被改写；存储夹具分别复现完成／失败终态改写。队列问题的修复前夹具在 16 次运行中出现 13 次失败和 3 次通过，证明结果受遍历顺序影响。首次夹具错误包括未注册的时钟工具、缺少会话 client_id、错误的 Task／Admission 类型、缺少上游受众、旧 Data Exchange 夹具没有生命周期、登录状态及依赖页预期错误；失败日志单独保留，不计通过。
