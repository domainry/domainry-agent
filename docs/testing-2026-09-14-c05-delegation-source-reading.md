# C05：明确来源接单、委派内原回执阅读与混合旧角色自动交付

日期：2026-09-14。接续[旧角色来源首次共享](testing-2026-09-14-c05-old-role-source-release.md)。本阶段补齐混合旧角色的明确来源匹配／接单、阅读工具与自动交付。C05 仍未完整验收，整表仍为 4／25。

后续[旧发布角色恢复](testing-2026-09-14-c05-legacy-source-publishers.md)已替换本记录中的旧 `Publisher` 缺失兼容策略：当前实现只接受从真实历史恢复的发布身份或明确新提交，未知发布者拒绝。以下保留本阶段原验收范围及证据。

## 当前实现

- `requirements.sources` 继续使用准确会话／运行／步骤前缀，不接收授权主体。匹配逐根解析原身份，以发起方及实际接收方分别检查；接单前再次核对。匹配只提供观察，不发布来源。
- 接单事务同时保存约定来源发布，纳入明确要求的根；每根分别保留原运行角色。来源未知时，委派／任务／来源发布一起回滚。来源变更才重新发布，普通元数据更新保持不变的历史根。
- SDK 新增内置协作工具 `delegation_source_read`。只有当前接收执行能调用；指定委派 ID、原工具回执及分页。服务端核对原后台任务、当前约定、实际执行身份与前缀；每页按当前阅读权限及原提供者证明读取已经完成的原结果，不重新执行业务工具。
- 此工具只返回原结果分页及来源委派 ID，独立于普通 `tool_result_read` 和原执行入口。Go JSON 展平请求字段，工具 Schema 复用现有准确结果分页契约，增加委派 ID，保留引用、偏移、大小等边界。
- 后台工具目录和原来源遍历复核上述明确根。保存的来源阅读分页作为后续历史或成果来源时，重新核对所属原任务、准确前缀及当前资料权限，并将分页字节与完整原结果比较；不能用分页包装绕过来源撤权。不同阅读范围的遍历使用独立审计，循环检查沿整个引用链保留。
- 同身份／旧委派没有独立主体映射时，原执行身份从原任务恢复，工具发起身份从原发起运行恢复；新的阅读角色不能替换原身份。仍保持当前读者身份用于资料授权。
- 新发布记录分别保存 `Producer` 与 `Publisher`：原运行角色用于证明，发布角色用于当前共享授权。重新打开仓库后分别复核，当前实际读者继续单独核对。这是私有持久化元数据，不是公开 authority DTO；沿用原表、ORM、事务及宿主迁移记录，不新增迁移。

## 验证边界

应用用例覆盖：只有原阅读策略、没有原执行授权也能读取明确原结果；实际读者与原证明角色分开；未列出的运行、超出前缀的步骤、其他委派／执行及错误接单角色拒绝；分页篡改、当前字段拒绝及原角色撤权拒绝；发布角色与原提供者角色的持久化撤权分别检查。

存储用例覆盖：两个旧角色的明确要求根在真实接单事务中按各自原角色发布，未知根导致回滚；相同主体没有映射行时，换阅读角色后原任务身份保持不变，其他用户不能查询。SDK／应用／存储完整检查、相关 race、传输／能力装配、原跨用户工具委派及接单撤权 HTTP 场景已通过。

`TestMixedOldRoleSourceToolDispatchReadAndAutomaticDelivery` 使用真实 Identity、Runtime、Report／Analysis、Tools、Agent 后台执行及 SQLite，模型仅为确定性 wire 夹具。两个旧角色先各产生一份专业原结果，再切换到绑定的成果阅读角色；发起 Agent 通过工具明确委派两个来源根，账号处理工具委派所需的确认。接收 Agent 分页读取原回执、逐行求和并核对独立分析值，均为 70；没有调用专业执行工具，自动提交两个原引用，账号明确验收。

最终四项 Runtime 回归已通过：本阶段的混合旧角色自动流程、原账号首次提交、既有跨用户专业自动流程、既有同用户不同角色专业自动流程。随后单独重跑新增阅读角色／发布角色边界：切换到另一同资料范围的成果阅读角色并保留原角色后，两份原值及保存的来源阅读分页仍可核对；只移除原发布角色、保留两份原提供者角色后，两份回执拒绝。字段撤权、恢复、单独移除原报表角色及重启也通过。该重跑的夹具时间预算为 180 秒，运行完成与原值／撤权断言保持；生产超时规则未变。

原始日志、准确命令、工作区及 65 个当前源文件摘要见[本阶段证据](evidence/2026-09-14-c05-delegation-source-reading/commands.md)。四场景日志编译于最后阅读角色断言和夹具预算调整之前；最终单场景日志覆盖这些新增断言。检查期间 Lifecycle SDK 包名变化使 Runtime 的导入与引用不一致，最终只统一当前导入别名；没有改动该模块的生命周期行为。本阶段不声明完整前端、在线模型或部署验收。
